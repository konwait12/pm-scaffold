## 1. 项目目标

本项目是 PRD-only 产品经理 AI 脚手架。输入可以是邮件、会议记录、PPT、图片或已有文档；唯一最终产品交付是经授权人工确认的中文 `prd.md`。

当前不覆盖研发任务拆分、技术实现、Testcase Review、用户手册或发布实施。调研、图表、原型和分析报告只为形成 PRD 服务。

## 2. 五层结构

| 层级 | 职责 | 不负责 |
|---|---|---|
| L1 项目治理 | 边界、状态、事实纪律、确认权、追溯和变更规则 | 具体需求内容 |
| L2 业务阶段 | 阶段目标、上下文、进入和退出条件 | 直接生成产物 |
| L3 工作事项 / Skill | 完成可独立启动、审查和确认的产品经理工作 | 把每个产出拆成 Skill |
| L4 Skill 内部流程 | 提取、思考、澄清、生成、审查、回流 | 新增业务阶段 |
| L5 产物与记录 | 正式基线和过程证据 | 反向决定流程结构 |

共享机制和条件支线横向服务 L2-L4，不进入纵向主干。

## 3. 概念词典

- **Stage**：业务工作的粗粒度上下文包，不可单独执行。
- **Work Item**：阶段内可被产品经理识别的工作事项。
- **Skill**：执行一个 Work Item 的 Agent 能力包。
- **Artifact**：Skill 的正式输出载体；一个 Skill 可以有多个 Artifact。
- **Record**：来源、问题、决定、审查和变更等过程证据。
- **Shared Mechanism**：所有 Skill 复用的控制能力，不是独立业务事项。
- **Support Skill**：存在独立触发意图、输入输出和人工责任人的条件能力。

“Wave”只作为旧 CLI 的兼容别名，不再表示业务阶段、Skill 或产出物。

## 4. 治理原则

1. AI 不替人工确认业务事实、范围、方案取舍和最终 PRD。
2. `confirmed` 只能由明确的人工评审操作产生，自动模式不得设置。
3. 事实、决定、假设、AI 推演、未知和冲突必须区分。
4. 正式基线发生变化时，从最早受影响的 Work Item 选择性回流。
5. 下游内容必须能追溯到上游目标、角色、场景或人工决定。
6. 先跑通最小主干，再依据真实问题增加条件能力。

## 5. 禁止项

- 不按产出物数量机械拆 Skill。
- 不把提问、头脑风暴、自审、画图或修改循环包装成业务阶段。
- 不把竞品调研、可行性分析固定到每个需求。
- 不强制每个阶段生成空问题清单或无用途报告。
- 不在 PRD 汇总阶段新增未经上游确认的需求。
- 不用模拟 reviewer 或 `--yes` 生成正式确认状态。
