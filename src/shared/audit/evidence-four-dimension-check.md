# 证据四维核验清单（Evidence Four-Dimension Check）

> 来源吸收：work-buddy `pm-chief-naysayer` skill Stage 2「Truth（证据盘问）」的四维核验——来源/规模/匹配/方向；顺带吸收其三阶段质疑（基础/证据/收敛）的 killer-question 精神。**附属于本项目六态知识状态 `FACT` 校验**与 Human Gate / 对抗审查提示。
> 定位：`src/framework/contracts.md` 定义 `FACT`=有出处的已确认事实。本文档给出判定某条证据与业务声明相称、从而可标 `FACT` 的四维门槛；供六态标注、对抗性审查（见 `adversarial-agent-prompt.md`）与 Human Gate 复核证据时使用。
> 触发：把一条信息标为 `FACT` 时、对抗审查核对证据时、评审人对"用户需要 X / 明显会发生 Y"类主张要求证据时。**按需加载，不设全局闸门**。

## 1. 四维核验清单

| 维 | killer question | 通过 = 可判 `FACT`；不通过 → 降级 |
|---|---|---|
| 来源 Source | 是第一手数据 / 本人访谈原话 / 自有产品埋点，还是转述 / 行业报告 / "我看到有人说"？ | 仅首手与直接观察可支撑 `FACT`；二手续述降级为 `AI_INFERENCE` / `UNKNOWN` |
| 规模 Scale | 是孤例还是规律？样本 N 是多少？覆盖什么时间段？ | 百分比必须带分母（"62%——of 多少人、多久"）；单例不足以支撑 |
| 匹配 Match | 这条证据直接证明本声明，还是只证明相邻命题？ | "问题存在" ≠ "此方案能解决"；相邻证据 ≠ 支撑证据 |
| 方向 Direction | 证据显示行为 A，产品要求行为 B；A 与 B 同向吗？ | 证据反指即证伪而非支撑（用户回避额外操作 vs 产品需额外操作） |

## 2. 应用到六态标注

- 要标 `FACT` 的主张必须**四维全过**（有直接首手来源、有规模、精确匹配、方向一致），并已登记 SRC-ID。
- 四维任一不过 → 标 `AI_INFERENCE` 或 `UNKNOWN`，不硬凑 `FACT`；这不破坏 `confirmed` 红线（只能人工 review approve 写入）。
- 对抗审查 / 评审时：先按四维对"用户需要 X / 显然……"类主张提问，再进入结论，避免把"看起来合理"当证据。

## 3. 三阶段质疑（killer-question 精神，Human Gate 提示词可选）

1. **基础 First Principles**：剥离竞品与惯例，问"最核心假设是什么；若它明早被证伪，整条逻辑是否坍塌？"
2. **证据 Evidence**：即上表四维核验，逐维一轮，不跳步；"我认为 / 这很明显"不算证据。
3. **收敛 Pruning**："若只给一小时交付，最小可证逻辑是什么；砍掉 X 是否制造更糟的新问题？"

每轮 ≤2 个 killer question；命题漂移（换了毫不相干的说法）时立即点破。完整铁律见 work-buddy 三阶段原文。
