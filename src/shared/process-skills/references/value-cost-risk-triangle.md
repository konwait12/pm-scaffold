# 价值-成本-风险三角（Value-Cost-Risk Triangle）

> 本文将相关实践转化为本项目的可选方法，不引入外部运行时依赖。
>
> **定位**：每条 stakeholder 诉求必须能用"价值 / 成本 / 风险"三角度评估——AI 经常只看"价值大不大"，忽略"成本高不高"、"风险是不是扛得住"，结果 PRD 里塞满了"高价值低成本零风险"的功能（实际上不存在）。本技法把三角显式化，逼出 stakeholder 真实优先级。
>
> **触发**：RR Intake 时遇到以下信号——
> - 业务方只说"价值"不说成本
> - 多个 RR 冲突 / 资源不够
> - 优先级定级时 stakeholder 全标 P0
>
> **按需加载，不设全局闸门。**

## 2. 三角评估 3 维

对每条 stakeholder 诉求（RR-XXX），从 3 维打分：

### 价值（Value）

- **可衡量的可观察结果**：不是"提升体验"，而是"提升 30% 转化率"
- **量级**：影响多少用户 / 多大营收 / 多少效率
- **时间窗**：价值多久实现？持续多久？
- **可验证**：成功判据是什么？谁来验证？

| 等级 | 判定 | 标注 |
|---|---|---|
| V1 高价值 | 影响核心业务目标，可量化 ≥30% 改善 | P0 候选 |
| V2 中价值 | 影响次要目标，可量化 5-30% 改善 | P1 候选 |
| V3 低价值 | 仅优化体验，无量化数据 | P2 候选 |
| V0 伪价值 | "显然有用"但无证据 | 标 ASSUMPTION 验证 |

### 成本（Cost）

- **研发成本**：人月（PM / 设计 / 研发 / 测试）
- **时间成本**：开发周期 + 联调时间 + 灰度时间
- **运维成本**：服务器 / 数据库 / 第三方服务年费
- **机会成本**：做这个，放弃做那个

| 等级 | 判定 | 标注 |
|---|---|---|
| C1 低成本 | < 1 人月，无运维成本 | 优先 |
| C2 中成本 | 1-3 人月，有持续运维 | 评估 |
| C3 高成本 | > 3 人月或高运维 | 谨慎 |
| C0 不可承受 | 远超预算 / 资源 | 砍 / 延期 / 替换方案 |

### 风险（Risk）

- **技术风险**：依赖不可控 / 性能瓶颈 / 数据迁移
- **业务风险**：合规红线 / 资金安全 / PII / 误读代价
- **运营风险**：用户不接受 / 培训成本 / 客服压力
- **战略风险**：做了之后难以回退 / 锁定供应商

| 等级 | 判定 | 标注 |
|---|---|---|
| R0 低风险 | 可逆 / 无合规 / 无 PII | 默认 |
| R1 中风险 | 部分不可逆 / 部分合规 | 验证 |
| R2 高风险 | 不可逆 / 合规红线 / 误读代价高 | 强制 RR 复述 |
| R3 硬性降级 | 9 条硬性降级项之一（合规红线 / 依赖不可控 / 成本倒挂 / AI 为了 AI 等） | 砍掉 |

---

## 3. 9 条硬性降级项（任一命中 → 砍掉或重做）

来自 `shared/audit/review-taxonomy.md` 的 `[HarddownRule]`：

1. **合规红线**：跨境数据无合规授权 / 未成年人数据违规
2. **依赖不可控**：依赖供应商无替代且关键路径
3. **成本倒挂**：单功能成本 > 预期收益 5 倍
4. **AI 为了 AI**：用 AI 但效果不如规则 / 没有用户价值
5. **数据不可得**：核心数据无法采集 / 无法清洗 / 无法访问
6. **合规待决**：法务 / 监管尚未签字但已承诺上线
7. **责任不清**：事故时无人负责 / 多方推诿
8. **不可逆 + 高代价**：删库 / 退订 / 法律告知一旦失误无法挽回
9. **体验口号**：写"提升体验"但无量化指标

## 4. 应对 12 类典型追问

### 追问 1："业务方说 X 价值很大，但成本呢？"
**答**：追问"X 需要多少人月开发？" / "需要多少服务器？" / "运维年费多少？"——把模糊"价值"补齐三角。

### 追问 2："成本高但价值也高，怎么办？"
**答**：RICE 评分 + MoSCoW——若价值 > 成本 + 风险，P0；若价值 ≤ 成本，P1；若成本倒挂（P2 > P0 收益），砍或延期。

### 追问 3："风险都说'可控'，但没具体说明，怎么办？"
**答**：追问 "可控" 的具体判据——有 mitigation 吗？降级方案？回退成本？

### 追问 4："业务方把 X 标 P0，运营标 P1，研发说做不到，怎么办？"
**答**：三角评估——若 X 价值高 + 成本高 + 风险中，业务方与运营都想要但研发做不到 → 触发可行性分析（feasibility-analysis）。AI 不替业务方决策。

### 追问 5："多个 X 都是 P0，但资源只够做 1 个，怎么办？"
**答**：用 RICE 量化排序——参考 `feature-priority-quant.md`。但量化只是工具，决策权在人。

### 追问 6："AI 标的价值评估是 AI_INFERENCE，业务方没确认，怎么办？"
**答**：追问业务方"X 价值大在哪？能给我一个具体数字吗？"——逼出 stakeholder 自己的量化。

### 追问 7："成本评估怎么算？研发说 3 周，业务方说 1 周，怎么办？"
**答**：研发评估是 FACT（F 事实），业务方评估是 W（诉求）或 AI_INFERENCE。三角评估时以研发评估为准（FACT），业务方评估标 ASSUMPTION 验证。

### 追问 8："风险评估标 R2 高风险，但 stakeholder 说'做了再说'，怎么办？"
**答**：R2 高风险必须 RR 复述确认（`requirement-restate`）。stakeholder 口头"做了再说" ≠ 接受风险——AI 不得擅自 accepted。

### 追问 9："成本倒挂（C3 + V2）怎么办？"
**答**：硬性降级项。砍掉或替换方案——不可"勉强做"。

### 追问 10："AI 为了 AI——产品经理想用 AI 显得先进，怎么办？"
**答**：硬性降级项。追问"AI 的不可替代性在哪？规则做不到什么必须 AI 做？"——把不可替代性写进 RR-XXX。

### 追问 11："体验口号（'提升体验'）怎么量化？"
**答**：追问"提升哪类用户的哪个动作的哪个指标？"——例：新手用户注册流程时长从 5 分钟降至 2 分钟（V1 高价值 + C2 中成本 + R0 低风险）。

### 追问 12："三角评估后 stakeholder 还是坚持做，怎么办？"
**答**：标 DEC 类，让 stakeholder 书面签字接受风险（accepted 状态只能由决策 owner 设）。

## 6. 错误示例

❌ **只看价值不看成本**："这个功能价值很大！做了！"——成本没说
✅ 三角评估：V1 高价值 + C3 高成本 + R1 中风险 → 业务方决策是否值得

❌ **"显然"当证据**："这个成本显然可控"——显然不是证据
✅ "成本可控 [SRC-001 §3.2 研发评估 3 人月，2026-08-15 邮件]"

❌ **AI 替 stakeholder 接受风险**：R2 风险 stakeholder 说"做了再说"，AI 标 accepted
✅ R2 必须 RR 复述；accepted 状态只能由决策 owner 设

❌ **成本倒挂砍不掉**：C3 + V2 硬性降级，业务方坚持做
✅ 标 BLK，issue-record 触发；业务方书面签字才能继续

❌ **AI 为了 AI 包装成"用户体验提升"**：AI 功能但用户实际不需要
✅ 追问 AI 不可替代性；若规则能实现同等效果，砍 AI 改规则

❌ **"提升体验"当 V1 高价值**：无量化指标的口号
✅ 追问具体数字 + 时间窗 + 验证判据
