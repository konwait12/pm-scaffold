# 三档门槛评估技法（Threshold Tier）

> 来源吸收：`daedalus-skill` 的 SKILL.md 门槛评估模块 + `templates/round3_triggers.md` §1 项目门槛评估，作为 feasibility-analysis 的可选落地能力。
> 定位：在可行性评估早期就把"成本/时间/形态"三档预期摆上桌，让 stakeholder 选择轻量/中等/完整路径，避免可行性分析对着一个远超预算的"完整方案"空谈。
> 触发：Preflight/Intake 阶段方案成本范围不清、或 stakeholder 尚未选择投入档次时；v1-boundary 需要门槛路径输入时。**按需加载，不设全局闸门**。

## 1. 输入映射（pm-scaffold 语境）

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| 方案功能描述 | feasibility-report §投入产出 | 成本/时间估算对象 |
| 档位选择（1/2/3） | feasibility-report §结论（有条件做） | 决定可行域与放行条件 |
| 成本预期 | v1-boundary 的收敛后输入包附注 | 边界与门槛联动 |
| 档位推荐 | scoring-7d 的可交付性维度 | 影响评分 |

> 三档是**起点选择**，不是终点承诺——轻量验证通过后可升级到中等/完整档。

## 2. 三档门槛模型（搬入自 daedalus SKILL.md 门槛评估）

| 档位 | 成本 | 时间 | 形态 | 目标 |
|------|------|------|------|------|
| 1 轻量级验证 | < 500 元 | 几天 | 无后台或纯前端（本地存储、静态地图） | 验证核心假设 |
| 2 中等完整度 | 几千元 | 几周 | 简单后端（微信小程序云开发、Supabase 免费额度） | 小型工具/小团队可用 |
| 3 全功能产品 | 万元以上 | 月固定费用 | 需开发团队或深入学习后端 | 正式商业化 |

## 3. 门槛评估输出模板（搬入自 daedalus round3_triggers §1）

```markdown
**💰 项目门槛评估**

根据你之前的描述，这个产品可能涉及以下技术组件和成本：

- **后端/数据库**：如需用户账号、存储轨迹数据，需要服务器和数据库。
- **地图 API**：调用地图服务可能产生费用（高德/百度地图免费额度通常足够初期）。
- **云存储**：如果允许用户上传图片，会产生存储和流量费用。
- **运维学习**：即使使用低代码方案，也需要花时间学习部署、备份等。

**建议你选择一条路径**（回复数字 1、2 或 3）：

1. **轻量级验证**：成本 < 500 元，几天时间，无后台或纯前端（如本地存储、静态地图）。
2. **中等完整度**：成本几千元，几周时间，简单后端（如微信小程序云开发、Supabase 免费额度）。
3. **全功能产品**：成本万元以上，月固定费用，需开发团队或深入学习后端。

请回复 1、2 或 3。
```

## 4. 各档适用场景与产物深度

### 1 轻量级验证（< 500 元 / 几天）

- **适用**：L0 想法初筛、核心假设尚不明确、需要先验证"有没有人要"。
- **产物深度**：
  - 可点原型 / 静态 Demo / 表单收集意愿
  - 只覆盖 1-2 个关键场景
  - 不建账号体系（本地存储）
- **可行性分析侧重**：用户价值与验证质量为主，投入产出从简。

### 2 中等完整度（几千元 / 几周）

- **适用**：核心假设初步成立、需要真实用户小规模使用、内部工具或小团队工具。
- **产物深度**：
  - 简单后端 + 基础数据模型
  - 覆盖主流程 + 关键异常
  - 可配账号、权限雏形
- **可行性分析侧重**：技术可行性（简单后端选型）+ 投入产出（几千元 vs 预期收益）。

### 3 全功能产品（万元以上 / 月固定费用）

- **适用**：商业化产品、多角色权限、合规要求高、需要长期运营。
- **产物深度**：
  - 完整后端 + 数据库 + 运维
  - 覆盖状态机、权限矩阵、审计、异常降级
  - 需合规审查（支付/隐私/数据）
- **可行性分析侧重**：市场空间 + ROI + 风险评估，须过 review-threshold-7d 研发评审门槛。

## 5. 与可行性分析各维度的联动

| 档位 | 市场空间 | 技术可行性 | 投入产出 | 风险评估 |
|------|---------|-----------|---------|---------|
| 轻量 | 定性判断为主 | 纯前端/低代码已验证 | <500 元，几乎无沉没成本 | 聚焦需求风险 |
| 中等 | 定性 + 粗算 | 简单后端选型待验证 | 几千元，可算回本周期 | 聚焦集成/依赖 |
| 完整 | TAM/SAM/SOM 量化 | 全栈复杂度待验证 | 万元级，需 ROI 测算 | 全维：合规/交付/组织 |

## 6. 工作流程

1. **列组件成本**：根据方案功能列出可能涉及的技术组件（后端/API/存储/运维）及成本点。
2. **出三档选项**：按模板输出轻量/中等/完整三档，请 stakeholder 回复 1/2/3。
3. **按档位分析**：以所选档位为可行域，裁剪四维度分析的深度与口径。
4. **联动边界与评分**：档位选择附注收敛后输入包（v1-boundary）；可交付性评分与档位匹配。
5. **留升级路径**：结论中注明"轻量验证通过后可升级"，不锁死在单一档位。

## 7. 核心硬规则

1. **档位先于深度**：不先确认档位就做万元级完整分析 = 对着假设空谈。
2. **成本如实列**：地图 API 超额度收费、云存储费用、运维学习成本必须列出，不隐藏。
3. **档位与产物匹配**：轻量档不配完整状态机/审计，完整档不省合规/降级。
4. **选择权在人**：AI 只列档位与成本，stakeholder 拍板。
5. **分析深度随档位**：轻量档可行性从简，完整档须过研发评审 7 维门槛。
6. **升级路径显式**：每档结论注明可升级条件，防"一次性做完所有档"的资源浪费。

## 8. 边界（Do Not）

- 不替 stakeholder 选档——只给三档选项与成本差异。
- 不跳过档位直接评估完整方案——成本范围不清时先定档。
- 不把三档说成终局——轻量验证通过后可升级。
- 不给"越贵越完整越值得"的暗示——档位由需求与预算决定。
- 不在轻量档塞完整档的可行性要求——按档位裁剪分析深度。

## 9. 质量自检清单

- [ ] 技术组件（后端/API/存储/运维）与成本点已列出
- [ ] 轻量/中等/完整三档选项已输出并请 stakeholder 选择
- [ ] 分析深度与所选档位匹配（轻量从简、完整全维）
- [ ] 档位选择已附注输入包并与 v1-boundary 联动
- [ ] 升级路径已注明
- [ ] 无替 stakeholder 选档、无隐藏成本
