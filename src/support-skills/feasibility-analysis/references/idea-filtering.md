# Idea Filtering 市场重复性检查（Idea Filtering）

> 来源吸收：`product-solution-evaluator` skill 的 `references/idea-filtering-market-scan.md`（6 类替代方案 + Build/Buy/Partner/Integrate/Abandon），作为 feasibility-analysis 的可选落地能力。
> 定位：在可行性评估前先判断"市场上是否已有成熟替代方案"，避免重复开发、过度自研或把采购/集成问题误判为研发问题——这是"要不要做"的第一道闸。
> 触发：评估对象是 0 到 1 新产品/新功能/新 AI Agent/内部平台，或用户担心"重复造轮子"、需判断自研/采购/集成/合作/放弃时。**按需加载，不设全局闸门**。

## 1. 输入映射（pm-scaffold 语境）

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| 新产品/自研方案 | feasibility-report §市场空间 | 过滤对象 |
| 6 类替代方案扫描 | feasibility-report §多方案取舍 候选 | 替代方案进对比矩阵 |
| 五路径决策 | feasibility-report §结论 | Build/Buy/Partner/Integrate/Abandon |
| 自研必要性判断 | scoring-7d 的市场重复性维度（15%） | 影响用户价值/ROI 评分 |

> 若只对已有 PRD/上线功能做质量评审，可不展开完整市场扫描，但仍应在"方案闭环与差异化"中检查替代方案。

## 2. 触发条件（搬入自 idea-filtering-market-scan §1）

当输入属于以下任一情况时，先执行 Idea Filtering：

- 评估 0 到 1 新产品、新功能、新工具或新 AI Agent；
- 用户明确担心"市场上是否已有类似产品""是否重复造轮子""有没有现成方案"；
- 方案需要投入研发、采购预算、团队资源或进入路线图排期；
- 用户要求判断是否应该自研、采购、集成、合作或放弃；
- 方案看起来像通用能力（表单、知识库、CRM、自动化、报表、客服、内容生成、Agent 编排、数据分析、协同办公等）。

## 3. 六类替代方案（搬入自 idea-filtering-market-scan §2）

Idea Filtering **不能只看直接竞品**，应覆盖以下六类替代方案：

| # | 替代方案类型 | 说明 |
|---|---|---|
| 1 | 直接竞品 | 已面向同一目标用户、解决同一核心问题的商业产品 |
| 2 | 间接替代方案 | 用户当前通过现有软件、人工服务、外包、Excel、流程规范、咨询服务等方式解决问题 |
| 3 | 平台内置能力 | 飞书、企微、钉钉、Notion、Office、WPS、Zapier、Make、各类 CRM/CDP/客服/营销自动化平台、云厂商和 AI 平台的内置能力 |
| 4 | 开源或可复用方案 | GitHub、Hugging Face、模型、插件、模板、自动化脚本、低代码组件 |
| 5 | 垂直行业方案 | 行业 SaaS、系统集成商、咨询服务、代运营方案、垂直插件 |
| 6 | 大厂或生态能力 | 云厂商、办公平台、AI 平台、浏览器/操作系统、主流模型服务商、应用市场已有能力 |

## 4. 检索与事实核验要求（搬入自 idea-filtering-market-scan §3）

结论依赖"市场上是否已有类似产品、价格、发布状态、功能覆盖、开源活跃度或平台能力"时，必须用一手或权威来源核验：

- 产品官网、定价页、文档、帮助中心、开发者文档；
- 官方应用市场、插件市场、集成市场；
- GitHub 仓库、Release、README、Issue 活跃度；
- 云厂商、办公平台、AI 平台官方文档；
- 权威评测、行业报告或用户社区作为辅助证据。

> 不要只凭模型记忆判断"市场上没有类似产品"。无法联网/无法读取原文时，标注"未完成充分市场核验"，结论降为低或中低置信度。

## 5. 输出结构（搬入自 idea-filtering-market-scan §4）

正式评分前增加以下小节：

```markdown
## 0. Idea Filtering：市场重复性与自研必要性

- 市场重复性：高 / 中 / 低 / 暂无法判断
- 已有成熟方案：有 / 部分有 / 暂未发现 / 未完成充分核验
- 主要替代方案：
  1. 产品或方案 A：覆盖了……；成熟度……；证据来源……
  2. 产品或方案 B：覆盖了……；成熟度……；证据来源……
  3. 开源/平台能力 C：适合……；限制……；证据来源……
- 当前方案差异化：
- 用户为什么不用已有方案：
- 自研必要性：强 / 中 / 弱
- 推荐路径：Build / Buy / Partner / Integrate / Abandon
- 是否进入正式产品方案评估：是 / 否 / 需补充验证后再评估
```

用户要求简短输出时可合并为 5 行结论，但仍应覆盖"已有方案、差异化、自研必要性、推荐路径、置信度"。

## 6. Build / Buy / Partner / Integrate / Abandon 判断（搬入自 idea-filtering-market-scan §5）

| 路径 | 适用条件 | 典型建议 |
|---|---|---|
| Build 自研 | 现有方案无法覆盖核心场景；存在独有数据、流程、体验、合规或战略壁垒 | 进入 MVP 或立项评估，但先验证最关键差异化 |
| Buy 采购 | 市场已有成熟低成本产品，需求标准化，自研无法形成壁垒 | 优先做供应商评估、试用和采购测算 |
| Partner 合作 | 外部方案成熟但需要行业资源、数据、渠道或联合交付 | 设计联合试点和商业分工 |
| Integrate 集成 | 平台已有能力可覆盖 60% 以上需求，差异点在流程编排或数据打通 | 优先做插件、API 集成、低代码或自动化工作流 |
| Abandon 放弃 | 需求弱、替代充分、差异化不足、投入产出倒挂 | 不进入研发排期，保留为观察项或需求池 |

## 7. 硬性降级规则（搬入自 idea-filtering-market-scan §6）

若市场上已有成熟、低成本、易采购或易集成的同类方案，而当前方案没有明确差异化、数据壁垒、流程壁垒、体验优势、合规必要性或商业必要性，则**必须显著降级**。此类方案默认不建议直接投入完整研发，应优先考虑：

- 采购现成产品；
- 集成平台能力；
- 使用开源方案二次封装；
- 做轻量插件、脚本、低代码或工作流自动化；
- 先用人工服务或半自动流程验证需求；
- 暂缓或放弃研发。

## 8. 常见误判（搬入自 idea-filtering-market-scan §7）

- 把"市面上没有完全一样的产品"误判为"值得自研"——真正要看用户问题、替代方案和差异化价值；
- 把"已有产品不好用"直接等同于"我们应该做一个"——必须说明为什么我们能做得显著更好；
- 把"内部流程特殊"直接等同于"必须自研"——很多流程可以通过配置、集成、低代码或运营调整解决；
- 只比较功能清单，不比较迁移成本、采购成本、维护成本、组织成本和失败成本；
- 只看直接竞品，忽略用户已经用 Excel、人工服务、平台插件或外包方式解决问题。

## 9. 工作流程

1. **判触发**：新想法/自研工具/AI Agent/内部平台 → 执行 Idea Filtering；存量 PRD 评审 → 只在差异化处查替代。
2. **六类扫描**：按直接竞品/间接替代/平台内置/开源/垂直/大厂生态六类逐类检索。
3. **事实核验**：关键结论用一手来源核验，核验不了标"未完成充分市场核验"。
4. **填输出结构**：市场重复性/已有成熟方案/差异化/自研必要性/推荐路径。
5. **映射处置**：无成熟替代 → 进入正式评估；成熟替代但无差异化 → 显著降级，推荐 Buy/Integrate/Abandon。
6. **进多方案取舍**：存在 ≥2 个实质方案（自研 vs 采购等）时，接入 feasibility-report §多方案取舍 矩阵。

## 10. 核心硬规则

1. **六类替代全查**：只查直接竞品 = 不完整；间接替代（Excel/人工/外包）必须纳入。
2. **事实必须核验**：市场结论用一手来源；无法核验即降置信度，不得凭模型记忆断言。
3. **有成熟替代即降级**：无差异化 + 有低成本替代 → 显著降级，不直接进入完整研发。
4. **"没有完全一样"≠值得自研**：看用户问题、替代方案与差异化价值。
5. **推荐路径明确给出**：Build/Buy/Partner/Integrate/Abandon 五选一，不模糊。
6. **过滤结论先行**：Idea Filtering 结论在正式评分前输出，影响市场重复性维度评分。

## 11. 边界（Do Not）

- 不把"已有产品不好用"直接等于"我们该做"——必须论证差异化。
- 不把"内部流程特殊"直接等于"必须自研"——先评估配置/集成/低代码。
- 不比较完功能清单就下结论——还要比迁移/采购/维护/组织/失败成本。
- 不因过滤否定就停止沟通——Abandon 保留为观察项或需求池，不浪费前期认知。
- 不编造竞品存在或不存在的结论——证据不足标"未完成充分核验"。

## 12. 质量自检清单

- [ ] 六类替代方案（直接/间接/平台内置/开源/垂直/大厂生态）已逐类扫描
- [ ] 关键市场结论有一手来源核验，无法核验已标"未完成充分市场核验"
- [ ] 输出结构覆盖：市场重复性/已有成熟方案/差异化/自研必要性/推荐路径/是否进入评估
- [ ] Build/Buy/Partner/Integrate/Abandon 五选一已明确
- [ ] 无差异化且有低成本替代时已显著降级
- [ ] 无"没有完全一样=值得自研"式误判
