# 交付评审

这是一个面向产品交付的内部能力，吸收 Superpowers 的“先定义完成、先验证再交付、完成前复核”原则，但不替代任何主干 Work Item，也不替业务负责人做决定。

## 适用边界

- 主干产物或支持能力已经形成草稿，需要在 `Human Gate` 前做一次可执行性检查。
- 需求仍含有方案化表述、范围漂移、不可观察的验收或没有证据的事实声明。
- 多人协作后需要把交付结论、测试证据和未决问题收敛成一份评审包。

不要用本能力代替需求重述、头脑风暴、可行性分析或 PRD 汇总；它只检查并组织已有内容。

## 固定流程

1. **拆解**：把目标拆成可观察结果、范围边界、依赖、风险和未决问题。每一项只表达一个可判断命题。
2. **验收先行**：为每个可交付命题写出 Given/When/Then 或等价的可复现判据；无法验证的命题标记为 `UNKNOWN`，进入问题清单，不得用“基本完成”“体验良好”代替。
3. **证据核对**：为判断绑定 `SRC-*`、上游产物 ID、命令输出或文件路径。推断必须标 `AI_INFERENCE`，不得升级为 `FACT`。
4. **对抗复核**：至少构造一个失败路径、边界输入和回退条件；检查是否误把实现方案当成业务事实，是否引入未确认范围。
5. **评审包**：按 `references/output-contract.md` 生成过程记录，列出结论、证据、验收判据、风险、未决项和建议动作。过程记录不进入 PRD 正文。
6. **人工闸门**：停在 `ready_for_human_review`，由声明的业务负责人或产品负责人确认。没有人工确认，不得写入下游正式产物或标记 `confirmed`。

## 证据优先级

`confirmed` 的上游产物/人工 ReviewRecord > 可复现命令输出 > 明确来源材料 > `AI_INFERENCE`。证据不足时少写一个结论，不要用模板字段填空制造确定性。

## 完成标准

- 每个结论都有来源、知识状态和可观察验收判据。
- 范围内与范围外均有明确描述，至少一个失败或回退场景已检查。
- 未决项有 owner、下一步和阻断性；没有未决项时显式写“无未决项（已核对）”。
- 评审包已通过自检并等待人工闸门；本能力不设置自动通过。

详细字段见 `references/output-contract.md`，人工逐项检查见 `references/reviewer-checklist.md`，通用思考透镜见 `references/thinking-framework.md`。
