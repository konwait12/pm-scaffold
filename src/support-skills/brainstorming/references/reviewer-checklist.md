# 人类审查清单 · 头脑风暴发散收敛（Brainstorming）

> 本清单给 **PM/业务方** 在审查 AI 产出的 `brainstorming-output.md` 并做候选处置时使用。
> 不是给 AI 看的（AI 看 `audit-checklist.md`）。
> 每条 = "是 / 否 / 不适用"，有"否"则进入 Revision 修改确认。

## 发散完整性
- [ ] 12 个维度（生命周期 / 角色 / 正常·备选·异常·失败·超时 / 权限 / 数据条件 / 交接 / 依赖 / 取消 / 重试 / 回滚 / 变更恢复 / 约束）是否都被扫过或明确说明跳过？
- [ ] 候选是否覆盖了你业务上"明显应该想到但没写到"的要点？（想到一个就补一个 SCN）
- [ ] 是否有大量重复候选没有被聚类去重？

## 候选质量
- [ ] 每条候选的 Evidence 是否说明"AI 为什么这么想"？有没有把 AI 的推测当成事实？
- [ ] 每条候选的 Impact 是否说得清"纳入后会怎样"？
- [ ] 原始想法（你的一句话）是否被原样保留在 §1 原始输入里，没有被 AI 悄悄改写？

## 处置决定（这是你的活，别让 AI 替你做）
- [ ] 逐条处置：`include`（纳入）/ `exclude`（排除，给原因）/ `defer`（暂缓，给触发条件）/ `research`（待调研，登记问题跟进）。
- [ ] 每条 `include` 是否都有明确的 Write-back Target（写回 `project-background-goal` 输入包的哪个段）？
- [ ] `exclude` 是否写了原因？`defer` 是否写了触发条件？`research` 是否登记了 issue-record / 问题清单？
- [ ] 有没有你本来想排除但 AI 擅自标记 include 的候选？（AI 无权替你处置）

## 可传递性
- [ ] §收敛后输入包是否只综合了 include 项？是否达到"拿给 project-background-goal 直接开跑"的充分程度（≥ 50 字）？
- [ ] 如果我是接手背景与目标的同事，读完输入包是否知道：做什么活动、给谁做、大致分几个阶段、有哪些约束候选？

## 最终判断
1. **你认同这份候选清单和处置结果吗？** 如果认同，基于哪些候选和证据？如果不认同，缺什么？
2. **你可以拿这个输入包去和 project-background-goal 的产出方开会吗？** 如果可以，哪些部分还需要补充？如果不可以，缺什么？
