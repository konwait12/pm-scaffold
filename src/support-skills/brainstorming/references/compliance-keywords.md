# 合规风险关键词库（Compliance Keywords）

> 来源吸收：`daedalus-skill` 的 `rules.md` §3 风险识别规则 + `templates/risk_checklist.md`（合规风险与安全风险关键词库），作为 brainstorming 的可选落地能力。
> 定位：在发散候选阶段就给"会踩合规红线"的候选打上 ⚠️ 标记，避免把位置追踪/UGC/金融等功能当成普通功能发散；把风险提示前移，降低后期返工与合规事故。
> 触发：SCN 发散候选涉及位置、内容、支付、健康、未成年人、地图等关键词时；或候选交人工处置前需给 business_owner 附风险提示时。**按需加载，不设全局闸门**。

## 1. 输入映射（pm-scaffold 语境）

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| 用户功能描述 | brainstorming 的 SCN-XXX 候选 | 扫描对象 |
| 命中风险类别 | SCN 候选的 ⚠️ 标记 + 处置建议 | 风险候选进 `defer`/`research` 倾向 |
| 风险提示 | issue-record 的 Q-XXX（INF） | 需业务方确认的合规问题 |
| 免责声明 | 人工处置表附注 | 不替 stakeholder 决策 |

> 本清单只做**提示与知情**，不禁止功能——decision 权在 business_owner。已提醒过的风险类别记录在 `risk_reminded`，避免重复输出。

## 2. 合规风险关键词库（搬入自 daedalus risk_checklist 第一部分）

| 类别 | 触发词示例 | 风险等级 | 检查项/提示模板（摘要） |
|------|-----------|---------|------------------------|
| 位置追踪 | 定位、轨迹、打卡、签到、附近的人、实时位置 | 高 | 需遵守《个人信息保护法》：明示告知、征得同意、提供关闭与数据删除功能 |
| 用户上传内容（UGC） | 图片、评论、帖子、分享、发布、上传 | 中 | 需建立内容审核机制（关键词过滤+举报+第三方审核 API），否则可能因违规内容下架 |
| 匿名社交 | 匿名、悄悄话、私密、无登录 | 高 | 易被滥用进行骚扰或违法信息传播，建议增加身份验证（手机号绑定）或举报功能 |
| 健康数据 | 心率、步数、减肥、体重、医疗、病症 | 高 | 敏感个人信息，需更高加密与合规声明，部分功能可能需要医疗器械认证 |
| 金融相关 | 支付、红包、理财、借贷、转账、钱包 | 极高 | 需支付牌照或合规资质，个人开发者无法上线；建议使用微信支付/支付宝合规接口 |
| 未成年人 | 儿童、学生、青少年、18 岁以下 | 高 | 需符合《未成年人保护法》：年龄验证、家长同意机制，不得收集不必要信息 |
| 境外地图 | Google Maps、MapKit（境外）、境外地图 | 中 | 国内应用必须使用合规地图服务（高德、百度、腾讯），否则违法 |
| 社交关系 | 好友、关注、粉丝、私信 | 中 | 需提供隐私设置、拉黑举报功能，遵守《网络安全法》 |

## 3. 安全风险关键词库（搬入自 daedalus risk_checklist 第二部分）

| 功能点 | 关键词 | 风险描述 | 提示模板 |
| :----- | :----- | :------- | :------- |
| 图片上传 | 上传图片、拍照、相册 | 云存储被滥用作图床，产生高额费用或传播非法内容 | 限制文件类型（jpg/png）、大小（≤5MB）、防盗链 + 图片审核 API |
| 短信验证码 | 短信登录、验证码、注册 | 恶意刷量导致费用飙升，用户被骚扰 | 频率限制（同一手机号 1 次/分钟）、图形验证码、IP 黑名单 |
| 用户数据存储 | 个人信息、密码、轨迹 | 数据泄露、未加密存储 | 敏感信息加密存储（如 bcrypt）、传输使用 HTTPS、定期备份 |
| 位置记录 | 定位、轨迹、打卡 | 轨迹数据滥用 | 明确告知用途，提供删除功能，定期清理（如保留 90 天） |
| 第三方 API | API 密钥、地图服务 | API 密钥泄露导致盗刷 | 密钥不硬编码在前端，后端代理请求，设置调用频率限制 |
| 用户身份伪造 | 冒充他人、盗用账号 | 冒充他人发布内容或查看隐私 | 基本身份校验（手机号绑定、邮箱验证），敏感操作二次验证 |
| 未授权接口 | 数据遍历、越权 | 接口无鉴权，可遍历其他用户数据 | 所有写操作和敏感读操作验证用户身份（token），使用随机 ID 而非自增 ID |

## 4. 输出模板（搬入自 daedalus risk_checklist）

### 合规风险提示卡（命中关键词时）

```markdown
**⚖️ 法律与伦理风险提示**

根据你描述的[功能名称]，系统识别到以下风险领域：

- **[风险类别]**：[具体风险说明]
- **[风险类别]**：[具体风险说明]

> 免责声明：我们已经尽力帮你识别常见的法律、伦理风险，但不同地区的规定可能更新较快，建议你针对自己的项目具体咨询专业人士或自行查询最新法规。
```

### 安全风险提醒（提出明确功能后，产品经理角度）

```markdown
**🔒 安全风险提醒（产品经理角度）**
你提到的 [功能] 需要注意：
- [具体风险1]：[建议]
- [具体风险2]：[建议]
```

### 合并输出示例（"用户可上传店铺照片"）

```markdown
**⚖️ 法律与伦理风险提示**
- **位置追踪**：记录用户签到地点需遵守《个人信息保护法》，必须弹窗告知、征得同意，并提供"关闭轨迹记录"功能。
- **用户上传内容**：上传的图片需进行内容审核（涉黄、涉政、广告），否则可能被应用商店下架。建议接入第三方审核 API。

**🔒 安全风险提醒（产品经理角度）**
- **图床滥用**：建议限制文件类型（jpg/png）、大小（≤5MB），并添加防盗链和图片审核。
- **存储费用**：建议设置每日上传次数限制（如每人每天最多 5 张）。
```

## 5. 快速匹配逻辑（搬入自 daedalus risk_checklist 第三部分伪代码）

```text
扫描用户输入中的所有功能描述 → 与关键词库匹配
合规风险：keyword ∈ user_input 且 category ∉ risk_reminded → 加入输出
安全风险：keyword ∈ user_input 且含明确功能描述 → 加入输出
去重：已提醒过的类别不再重复输出
```

## 6. 工作流程

1. **扫描候选**：对每个 SCN 候选描述与关键词库匹配，命中即标风险类别。
2. **去重提醒**：比对 `risk_reminded`，只输出未提醒过的风险类别。
3. **出提示卡**：合规风险按模板输出提示卡（含免责声明）；安全风险按模板附建议。
4. **标记处置**：命中高风险类别的候选在处置表倾向 `research`/`defer`，交 business_owner 裁决。
5. **记录已提醒**：更新 `risk_reminded`，避免后续轮次重复刷屏。

## 7. 核心硬规则

1. **只提示不禁止**：风险提示给知情权，最终 include/exclude 由 business_owner 决定。
2. **命中必出卡**：触发词命中即输出风险提示卡，不因"候选还不是需求"而省略。
3. **去重防刷屏**：已提醒类别不重复输出；只有新功能触及新风险才补充提示。
4. **免责声明必带**：所有合规提示附"建议咨询专业人士/自行查询最新法规"。
5. **提示语用业务语言**：写"需明示告知用户、提供关闭选项"，不写法律条文堆砌。
6. **不替法务下结论**：是否违法、是否可上线由专业合规审查判定，本清单只做产品视角提示。

## 8. 边界（Do Not）

- 不提供正式法律意见或监管结论——只做产品评估视角的提示。
- 不因风险直接 `exclude` 候选——处置权在 business_owner。
- 不重复提醒已确认的风险类别——避免打扰。
- 不把"境外地图"等中风险项夸大/缩小——按风险等级如实提示。
- 不在发散阶段无限追问合规细节——先标记，集中到 issue-record 澄清。
