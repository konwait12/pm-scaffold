# 来源处理 · Brainstorming（发散收敛）

本 skill 通常**纯 L0 无源**（只有一行想法，没有书面材料）——此时不发散内容仅有 AI_INFERENCE 推断。若有材料（消息 / 邮件 / 纪要）才按本文件登记 `SRC-*`，并作为候选 Evidence 的依据。

## 来源登记（Source Register）

为每个来源分配一个稳定 ID 并记录：

```text
source_id
title_or_description
format
author_or_speaker
provided_by
created_at
retrieved_at
authority_scope
location_or_link
notes
```

使用 `SRC-001`、`SRC-002` 等。对于会议，区分会议纪要原文与 AI 生成的摘要。对于聊天/工单，保留线程上下文与时间戳。

## 提取规则（Extraction Rules）

1. 在规范化之前**逐字**（verbatim）提取候选相关的原始措辞——原始措辞是候选 Evidence 的原材料。
2. 对每个候选保留来源说话人或作者与位置，后续必须能回溯到具体段落 / 时间戳。
3. 区分显式陈述与隐含含义；隐含含义成为 `AI_INFERENCE`，绝不成为 `FACT`。
4. 显式跨源合并重复项：注明"同一候选、不同措辞（SRC-001 vs SRC-002）"，而不是静默丢弃其中一个。
5. 绝不把"没有提及"当作候选不存在的证据——发散阶段恰恰是从间隙中生成候选的方向。

## 术语记录（Term Recording）

不同来源可能对同一对象或动作使用不同术语。不要静默统一：

- 记录两个术语及映射（`客户` = `会员`、`核销` = `销核`）；
- 如果术语差异可能隐藏对象/范围差异（如 `客户` 含匿名访客而 `会员` 不含），在候选 Evidence 中标注术语差异，留待后续阶段确认；
- 发散候选可暂时采用最清晰的主流术语，但保留同义词映射备注。

## 权威性（Authority）

**不做通用来源优先级**。用以下方式评估某个来源对候选的支持强度：

1. 针对本项目是否有显式的人工确认；
2. 对特定候选/对象的决策权；
3. 来源的直接程度；
4. 时效性，以及后续陈述是否显式取代先前陈述；
5. 独立来源的相互佐证。

权威性只影响候选 Evidence 的可信度，**不影响**发散是否进行：没有权威来源时仍按 12 维度发散，只是全标 `AI_INFERENCE`。

> 冲突处置：若材料之间出现"同一想法两种说法"的冲突，本 skill **不裁决、不路由**——冲突是 `requirement-restate`（复述）阶段的职责。本 skill 记录材料中的显式措辞即可，冲突交由复述阶段处理。

## 调研边界（Research Boundary）

仅当外部事实能消解发散的歧义（术语的行业定义、某种做法是否合规/可行）且可发现时，才做调研。记录来源、日期、事实/推断状态、置信度、适用性与决策影响。

调研不能确认业务方想引入哪些候选、或核准哪些候选被 `include`；那是人工决策，提交给 business_owner。

凡"现在无法判定的候选"，标 `research` 处置并登记 issue-record / QuestionRecord 跟进，而不是静默搁置。

## 混合媒体（Mixed Media）

- 对于幻灯片与文档，保留幻灯片/页面/章节位置。
- 对于音频/视频转写，保留每个内容的时间戳；注明转写是否由 AI 生成。
- 对于聊天/工单，保留发件人、线程上下文、日期，以及后续消息是否取代先前消息。
- 对于图片，转录可见的承载需求文本并注明不确定性。
