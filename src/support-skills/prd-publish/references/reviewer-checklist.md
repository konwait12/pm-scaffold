# 人类审查清单 · PRD 发布

> 本清单给 **授权发布人/PM** 在审查 AI 产出的 `publish-record.md` 时使用。
> 不是给 AI 看的（AI 看 `audit-checklist.md`）。
> 每条 = "是 / 否 / 不适用"，有"否"则进入 Revision 修改确认。

## 正确性
- [ ] 发布前检查是否全部通过？（PRD confirmed、hash 一致、5 个 Work Item 全 confirmed、无 REVISION 级问题）
- [ ] 发布记录中的源 PRD artifact ID 与 SHA-256 是否与确认版本一致？
- [ ] 各渠道链接/路径是否真实可达，还是只是 AI 声称？

## 完整性
- [ ] 是否覆盖了所有要求的发布渠道？（飞书 Docx / PDF / HTML / Markdown 有没有漏）
- [ ] 每个渠道的渲染限制是否记录？（如飞书 Markdown 里 Mermaid 不渲染）
- [ ] 通知是否发出？接收人是否覆盖产品、业务、研发、测试？

## 一致性
- [ ] 目的地副本是否与源 PRD 逐字节一致？（标题、章节顺序、表格、图、§7 追溯矩阵、元数据）
- [ ] 有没有"顺手改个错别字"之类的内容漂移？任何内容差异都是缺陷
- [ ] 源 hash 与确认 hash 是否一致（确认后被篡改的检测）？

## 可测性
- [ ] 发布记录里的验证结果是基于实际目的地检查的，还是信任导出工具的成功提示？
- [ ] 如果我是拿到这份副本的研发/测试，能否看到完整的追溯矩阵和验收依据？

## 可维护性
- [ ] 发布记录是否可作为后续比对的基线？（含源 hash、目标路径、验证时间戳）
- [ ] 若有已知渲染限制，是否明确标注，不会误导下游以为该内容缺失？

## 可追溯性
- [ ] 每次发布的记录是否可追溯到确认版本？（version + SHA-256 + 日期）
- [ ] 发布后若有内容变更，是否走 change-management / Reflow，而非静默改发布副本？

## 最终判断
看完这份产物后，回答这两个问题：
1. **你确认这份 PRD 可以对外发布了吗？** 如果确认，基于哪些验证项？如果不确认，缺什么？
2. **发布副本与你确认的版本完全一致吗？** 如果一致，你可以签收；如果不一致，哪部分需要重新导出验证？
