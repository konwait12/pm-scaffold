# 链接验证三层降级机制（Link Validation & Graceful Degradation）

> 来源吸收：`prd-competitor-check` 的 `--check-links` 链接验证机制——主链接→alt_urls→search_keywords 三层降级 + 链接状态实时显示，作为 competitive-research 的可选落地能力。
> 定位：竞品调研最怕来源失效——本文档提供一套三层降级机制，让每条竞品来源在主链接失效时自动顺延到备选链接、再到搜索关键词，保证调研始终有可访问的入口，且状态全程可见。
> 触发：当竞品参考库条目需要验证可用性、或调研过程中发现链接失效时使用。**按需加载，不设全局闸门**。

## 1. 输入映射

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| 竞品条目的 url | competitive-research 的 SRC-ID 来源 | 主链接 |
| 竞品条目的 alt_urls | 同一 SRC-ID 的备选入口 | 降级第 2 层 |
| 竞品条目的 search_keywords | 检索记录（搜索引擎回源） | 降级第 3 层 |
| `--check-links` | Preflight 来源核验 | 默认模式不自动执行，按需开启 |
| 链接状态图标 | 产物中的来源状态标注 | ✅/❌/⚠️ 实时可见 |

> **失效不静默**：任一竞品来源降级到第 3 层仍失败时，该条目标 `UNKNOWN`，交给 Clarify 让用户提供替代来源，不编造链接。

## 2. 三层降级机制

对每个竞品来源，按以下顺序尝试，找到第一个可用即停止：

```
第 1 层：主链接（url）           → 可访问则使用
   ↓ 失败
第 2 层：备选链接（alt_urls）    → 按顺序尝试 2-3 个，找到可用即停
   ↓ 全部失败
第 3 层：搜索关键词（search_keywords） → 用关键词在搜索引擎定位竞品
   ↓ 仍失败
UNKNOWN → 交人工（Clarify），不编造来源
```

### 2.1 各层要点

| 层级 | 来源字段 | 规则 |
|---|---|---|
| 第 1 层 | url（主链接） | 官网首页/文档中心首页，发起 HTTP 请求验证 |
| 第 2 层 | alt_urls（备选链接） | 2-3 个，按数组顺序尝试，找到第一个可用链接即停止 |
| 第 3 层 | search_keywords | 链接全失效时用于搜索引擎查找，替代"死链接" |

### 2.2 链接状态图标

| 状态图标 | 说明 |
|---|---|
| ✅ | 链接可访问（HTTP 200/30x） |
| ❌ | 链接失效（HTTP 404/500 等） |
| ⚠️ | 使用备选链接（主链接失效后降级成功） |
| （无图标） | 未检查（默认模式） |

## 3. 验证参数与限制（吸收自 prd-competitor-check）

1. **验证超时**：单链接超时 5 秒，超时视为不可访问。
2. **SSL 校验**：忽略 SSL 证书验证（避免证书过期导致误判）。
3. **自动化屏蔽**：部分网站可能屏蔽自动化访问——此类网站降级到人工验证或搜索关键词。
4. **只验证可用性**：验证环节不做内容判断，内容提取走 Intake。

## 4. 报告中的状态展示示例

```
✅ 可访问 (HTTP 200)
❌ HTTP 错误：404 Not Found
⚠️  备选链接可用：https://...
```

| 竞品名称 | 官方文档链接 | 链接状态 | 界面截图说明 |
|----------|--------------|----------|--------------|
| GitHub Marketplace | [查看文档](https://github.com/marketplace) | ✅ 可访问 | 列表页：左侧分类筛选... |
| 阿里云百炼平台 | [查看文档](https://help.aliyun.com/zh/model-studio) | ✅ 可访问 | 模型广场：网格布局... |
| 某已失效竞品 | [查看文档](https://old-domain.com) | ⚠️ 备选可用 | 降级到 docs 子域 |

> 💡 所有链接均为竞品官网首页或文档中心，确保长期有效；状态列让读者一眼看到来源健康度。

## 5. 工作流程

1. **登记条目**：从竞品参考库取条目，确认主链接/alt_urls/search_keywords 齐全。
2. **验证主链接**：HTTP 请求，200/30x → ✅；否则进入降级。
3. **顺延备选**：按 alt_urls 顺序逐个尝试，命中即标 ⚠️ 并记录实际使用的 URL。
4. **搜索兜底**：全失败则用 search_keywords 检索，记录检索到的替代页面。
5. **标记状态**：每个条目在产物中标 ✅/❌/⚠️/无图标。
6. **交人工**：三层全失败标 `UNKNOWN`，进 Clarify 由用户提供替代来源。

## 6. 核心硬规则

1. **三层顺序不可跳**：主链接没验证失败，不得直接跳到 alt_urls；备选未全失败不得启用搜索关键词。
2. **找到即停**：降级过程中命中第一个可用链接即停止，不再继续尝试后续备选。
3. **降级必留痕**：实际使用的 URL 与降级层级必须记录，产物中读者可见（⚠️ 标注）。
4. **失效不静默**：三层全失败必须标 `UNKNOWN` 并进 Clarify，绝不编造一个链接凑数。
5. **入口不替换结论**：链接验证只保证"入口可达"，竞品内容仍须按 source-handling 逐字提取。
6. **每次复用前重验**：竞品事实复用前重新核验来源（过时来源不作现状）。

## 7. 边界（Do Not）

- 不把"链接可访问"当作"内容正确"——可达性≠事实性，内容仍走 Intake 提取。
- 不因主链接失效就放弃条目——三层降级全走完才算失败。
- 不突破 5 秒超时反复重试——超时即降级，避免拖慢调研。
- 不替自动化屏蔽的网站硬闯——尊重 robots 限制，降级到人工或搜索。
- 不把降级信息藏起来——链接状态是调研质量的一部分，必须可见。

- [ ] 命中第一个可用链接即停止，无多余请求
- [ ] 实际使用 URL 与降级层级已记录并在产物中可见
- [ ] 三层全失败的条目已标 `UNKNOWN` 且进入 Clarify
- [ ] 链接状态图标（✅/❌/⚠️/无图标）标注完整
- [ ] 复用竞品事实前已重新核验来源时效
- [ ] 无编造链接/无把可达性当事实的情况
