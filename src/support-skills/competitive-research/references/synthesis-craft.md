# 竞品综合分析五段式技法（Synthesis Craft）

> 来源吸收：`product-researching`（产品深度分析）的阶段二「综合分析」——5 段式结构（六维速读/设计逻辑/增长壁垒/演进推演/犀利洞察）+ 独立成文硬约束 + 犀利洞察"被点醒"标准 + 阶段一六维研究框架，作为 competitive-research 的可选落地能力。
> 定位：竞品调研的产出（competitive-analysis.md）若只是竞品事实罗列，决策者读不下去；本技法提供一篇"独立成文、有洞察、可交付"的综合分析写法，让调研结论真正可被产品决策消费。
> 触发：当竞品调研需输出综合结论（§4"So What"），或需要比逐品罗列更深一层的洞察时使用。**按需加载，不设全局闸门**。

## 1. 输入映射

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| 6 份维度报告 | competitive-research 的逐品分析（§2） | 综合分析的素材来源 |
| 维度六素材汇总 | §3 横向对比 | 跨竞品的关键事实归口 |
| 综合分析（阶段二） | §4 结论（"So What"） | 独立成文的交付物 |
| 犀利洞察 | "So What"中的差异化建议 | 每段映射回已确认目标 |

> **素材在前，成文在后**：综合分析必须等逐品分析/横向对比完成后才动笔——禁止凭空生成竞品事实，所有量化结论须能追溯 SRC-ID。

## 2. 六维研究框架（素材层，吸收自 product-researching 阶段一）

前五个维度是单维度素材，维度六是跨维度事实归口（不下最终判断）：

| 序号 | 维度 | 性质 | 核心问题 |
|---|---|---|---|
| 1 | 产品设计与用户体验 | 单维度素材 | 竞品解决什么问题、怎么解决的、设计逻辑是什么 |
| 2 | 商业模式与变现逻辑 | 单维度素材 | 怎么赚钱、模式为什么可行、定价逻辑背后的策略 |
| 3 | 市场格局与竞争定位 | 单维度素材 | 品类格局如何、差异化定位是什么、竞争策略怎么打 |
| 4 | 用户增长与留存机制 | 单维度素材 | 用户怎么来的、怎么留住的、增长飞轮是什么 |
| 5 | 团队、生态与演进趋势 | 单维度素材 | 团队基因是什么、生态壁垒有多深、产品会往哪走 |
| 6 | 分析素材汇总 | 跨维度归口 | 核心逻辑/关键成功因素/风险信号/演进推演素材——为综合分析备料，**不下最终判断** |

> **维度六不做综合性最终判断**：把"判断需要的事实摆好"，综合判断留给综合分析阶段独立做出。

## 3. 综合分析 5 段式结构（吸收自 product-researching 阶段二）

综合分析的定位：**不是前几份素材的总结，而是一篇独立的、面向产品决策者的深度洞察**。

| 段落 | 字数 | 必须回答 |
|---|---|---|
| **【一】全景速读** | 300-500 | 用融合语言把竞品的全貌勾勒出来（**不是分竞品逐个总结**） |
| **【二】设计逻辑解读** | 400-600 | 竞品的核心设计决策 / 用户价值主张 / 为什么这样设计而不是那样 |
| **【三】增长与壁垒** | 400-600 | 增长引擎是什么 / 壁垒在哪里 / 竞争优势在强化还是衰减 |
| **【四】演进推演** | 500-700 | 竞品当前的核心矛盾 / 下一步最可能的演进方向 / 面临的关键抉择 |
| **【五】犀利洞察** | 150-250 | 抛开框架的产品老炮直言——这个竞品最被忽视的真相 |

### 3.1 全景速读写法（吸收自"六维全景速读"）

用 1 段或 3-5 个短段落融合勾勒全貌，**不是写"竞品 A 讲了什么、竞品 B 讲了什么"**——那是文件目录。挑最关键的 5-8 个数据点，让读者读完能用 30 秒向别人讲清楚"这是一个什么样的竞品，它处在什么状态"。

### 3.2 个性化原则（吸收自"设计逻辑解读"）

| 竞品类型 | 这一段的重点 |
|---|---|
| **平台/市场产品** | 拆供需匹配机制、信任体系、平台治理——"如何解决双边市场冷启动" |
| **效率/工具产品** | 拆工作流设计、功能架构逻辑、复杂性管理——"如何取舍丰富与简单" |
| **内容/社区产品** | 拆分发机制、创作者激励、社区氛围——"为什么用户在这里而不是别处" |
| **AI 产品** | 拆 AI 能力产品化、交互设计、人机协作——"技术如何转化为用户价值" |

### 3.3 增长飞轮与竞争壁垒写法

- **飞轮**：画因果链——"因为 X → 所以 Y → 导致 Z → 又反过来加强 X"，不写"增长策略 A、B、C"式清单。
- **壁垒**：围绕"为什么竞品追不上"写——壁垒类型（网络效应/数据/技术/品牌/生态/规模/转换成本）、壁垒强度（竞品全力追赶需要多久）、壁垒趋势（增强还是被侵蚀）、最脆弱环节。

### 3.4 犀利洞察的"被点醒"标准（吸收自"犀利洞察"段）

**核心标准：让读者读完有"被点醒"的感觉——"原来可以这样理解这个竞品"。**

禁忌句式（写出这些就是失败）：
- ❌ "因人而异，适合自己的就是最好的"
- ❌ "各有优缺点，看个人需求"
- ❌ 所有"一方面……另一方面……"
- ❌ 把前面已经讲过的话再说一遍

好的犀利洞察示例（吸收自 product-researching）：

> 例（社交平台）：「小红书最牛的不是内容质量——是它重新定义了'搜索'。百度的搜索是'我有问题要答案'，小红书的搜索是'我有欲望要灵感'。所有人以为它是社区、是内容平台，但它正在变成生活决策领域的搜索引擎——而且是那种用户心甘情愿贡献 UGC 来喂养的搜索引擎。」

> 例（效率工具）：「Notion 的真正问题不是产品做得不好——是它创造了一种新型拖延症。工具太好用了，以至于使用工具本身成了目的。这是一个设计上的'有益的 bug'——用户花在搭系统上的时间恰恰是留存的来源。」

## 4. 独立成文硬约束

1. **不写"如维度 X 所述""承接前文"**——读者预设是产品从业者但不了解这份调研，每个判断的依据当场说清楚。
2. **正文不写溯源标记（如【源：竞品 A】）**——素材层负责溯源，综合分析只写流畅独立的判断；每个数字心里清楚出处即可。
3. **换个竞品名也成立 = 失败**——必须针对这个竞品的特点做个性化写法。
4. **重点是"理解"而非"建议"**——分析回答"为什么"和"怎么做到的"，不写"值不值得抄"。
5. **宁可尖锐犯错，不要平庸正确**——给明确判断，错了可修正，骑墙的分析没价值。

## 5. 工作流程

1. **读素材**：完整读完逐品分析（§2）与横向对比（§3），心里想清楚 8 件事（竞品最本质是什么 / 解决什么问题 / 核心设计决策 / 增长引擎 / 壁垒在哪 / 核心矛盾 / 演进方向 / 最深刻的一句话）。
2. **全景速读**：融合语言勾勒全貌，只挑关键 5-8 个数据点。
3. **拆设计逻辑**：抓住 2-3 个最值得拆的设计决策讲透，不面面俱到。
4. **画飞轮与壁垒**：因果链 + 壁垒诊断（类型/强度/趋势/最脆弱环节）。
5. **演进推演**：核心矛盾 → 2-3 条演进路径（标最可能）→ 1-2 个关键抉择。
6. **写犀利洞察**：一句让人"被点醒"的话，映射回已确认目标（goal ID）。
7. **映射收口**：每条结论标 `AI_INFERENCE`，映射回已确认目标，送 Human Gate。

## 6. 核心硬规则

1. **素材未齐不动笔**：综合分析必须等逐品分析/横向对比完成后才写，禁止凭空生成竞品事实。
2. **独立成文**：正文不写"如维度 X 所述"类依赖语言，不写溯源标记——每个判断当场说清依据。
3. **个性化**：换竞品名也成立的分析 = 失败，必须抓住该竞品独特的设计/增长/壁垒逻辑。
4. **5 段齐全且比例正确**：速读 15-20% / 设计逻辑 20-25% / 增长壁垒 20-25% / 演进推演 25-30% / 犀利洞察 8-12%。
5. **犀利洞察要有灵魂**：写不出"被点醒"的洞察就重写，套话即失败。
6. **洞察不脱离目标**：每条"犀利"结论必须映射回已确认目标，标 `AI_INFERENCE`，否则是空转。

## 7. 边界（Do Not）

- 不分竞品逐个总结——那是素材目录，不是综合分析。
- 不写"一方面……另一方面"——选一边，下判断。
- 不写"值得/不值得"消费建议——重点是洞察，不是购买指南。
- 不面面俱到拆每个功能——只拆 2-3 个最值得拆的决策。
- 不给"该不该抄竞品 X"的建议——映射到已确认目标，结论由业务负责人裁决。

## 8. 质量自检清单

- [ ] 综合分析独立成文，无"如维度 X 所述/承接前文"依赖语言
- [ ] 正文无【源：竞品 X】溯源标记
- [ ] 5 段结构齐全（速读/设计逻辑/增长壁垒/演进推演/犀利洞察），比例符合参考
- [ ] 速读段是融合性勾勒，非分竞品总结
- [ ] 每段有具体数据/具体判断，无纯形容词堆砌
- [ ] 犀利洞察让人有"被点醒"的感觉，无套话/禁忌句式
- [ ] 换竞品名会失效（个性化写法）
- [ ] 每条结论映射回已确认目标，标注 `AI_INFERENCE`
- [ ] 素材层（逐品分析/横向对比）先行完成，无凭空生成事实
