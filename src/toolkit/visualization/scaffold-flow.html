3. 六态知识标注 证据与不确定性必须可见

每条声明必须标注知识状态；AI 的推断永远冒充不了事实，冲突不会被折叠成虚假一致。ready_for_human_review 强制六态全覆盖且 ASSUMPTION ≤ 30%。
FACT来源明确的事实（追 SRC-）
DECISION人类明确决定（含决策人）
ASSUMPTION暂定假设（≤30% 硬顶）
AI_INFERENCEAI 推断，未经确认
UNKNOWN缺失信息（链问题 ID）
CONFLICT来源矛盾（需裁决）

4. Loop 引擎：命令链与闭环机制 v0.2.0

一条命令链驱动整个需求生命周期；四道机器闸门 + 一道人工闸门 + 两条回流通道构成闭环。
# 1 建骨架（从注册表生成目录 + 授权清单骨架）
python3 src/scripts/pipeline.py init REQ-001-my-feature
# 2 查状态（active / next / 越级检测 / 单活跃项约束）
python3 src/scripts/pipeline.py requirements/REQ-001-my-feature status
# 3 成熟度判定（L0-L4 + 推荐入口 + 分支信号）
python3 src/scripts/pipeline.py requirements/REQ-001-my-feature entry
# 4 机器闸门（DoR 上游确认 + DoD 校验器/六态/自审 + property + 双向追溯）
python3 src/scripts/pipeline.py requirements/REQ-001-my-feature gate --work-item project-background-goal
# 5 人工确认（真实人名 + 授权清单匹配 + 角色匹配 + SHA-256 ReviewRecord）
python3 src/scripts/pipeline.py requirements/REQ-001-my-feature review --work-item project-background-goal \
  --decision approve --reviewer "评审人姓名" --reviewer-id "飞书ID" --reviewer-role "business_owner"
# 6 变更回流（dry-run 预览 → --apply 级联失效下游 + 写 ChangeRecord）
python3 src/scripts/pipeline.py requirements/REQ-001-my-feature reflow --work-item project-background-goal [--apply]
# 7 全量自检
bash run_tests.sh && python3 src/scripts/consistency_check.py
闭环 A · 级联失效（变更）
上游 confirmed 被改
→ reflow --apply 把下游翻为 superseded
→ ChangeRecord 留痕
→ next_work_item 回归最早受影响项
→ 重新走 8 步循环
‖
闭环 B · 双向追溯（防断链）
正向：G→ST→FEA→FUN→AC/BR 每行共现
反向：上游 ID 必须被下游消费
（无下游引用的孤儿目标报警）
‖
闭环 C · 防篡改
review 时写 SHA-256
→ branch_validator 比对当前哈希与 ReviewRecord
→ prd-publish 发布前 SHA-256 复核

6. 分支 Skill 触发矩阵 7 个 · 触发才跑

分支 skill 不占主干；进入前按 Inquiry Contract 询问。prd-publish 的触发（PRD confirmed）可由 entry 命令机器检测并提示。
competitive-research · 竞品调研
触发：方案方向不清或功能设计缺乏参考
产出：竞品分析（3-5 家）→ 99-review/support/
solution-assessment · 方案评估
触发：方案取舍影响范围/成本/风险
产出：可行性报告 + 多方案对比（DEC-XXX 决策记录）
prd-publish · PRD 发布
触发：prd-assembly confirmed（机器可检测 ✓）
产出：发布记录（SHA-256 复核后才可发布）
project-scope · 范围基线
触发：项目边界不清或范围蔓延风险
产出：In/Out/Deferred/Conditional 四类（S-NNN）
requirement-restate · 需求复述
触发：干系人语言歧义或多来源术语不一致
产出：复述清单（RR-NNN，原文 verbatim）
tracking-plan · 埋点计划
触发：功能需要数据埋点或追踪计划
产出：事件表（EV-NNN，链 FUN- + G-）+ PII 登记
issue-record · 问题清单
触发：任何阶段需求不明确/冲突/风险
产出：六类问题清单（BLK/RSK/DEC/INF/CLS/OUT）
