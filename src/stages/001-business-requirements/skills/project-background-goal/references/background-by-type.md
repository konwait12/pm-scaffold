# 三类项目背景目标指引

本指引服务于 project-background-goal 的 PM 对话，不是主文档的一部分。

## 重构

适用于已有系统、稳定人工流程或既有工具需要替换、整合或显著改进的场景。

必须说明：

- 之前如何完成，涉及哪些系统/角色；
- 什么问题有证据支持，以及造成什么影响；
- 要从什么状态变成什么状态；
- 如何判断改造带来的结果。

不要把“重构成小程序/新平台”本身当作问题；先说明体验、效率、转化、合规或协同哪里失效。

## 从 0 到 1

适用于尚未有可用的目标业务能力，但线下/人工业务已经存在，或需要首次建立一项业务服务的场景。已有小程序、账号体系、渠道或通用平台不等于这项能力已经存在。

必须说明：

- 若已有人工做法，它现在是否通过电话、微信、表格、纸质或人工协同完成；
- 若是全新的业务服务，它首次从触发到结果的完整业务流程至少有哪些关键步骤；
- 谁参与、每一步产生什么结果；
- 新能力要建立什么业务结果。

不要因为“没有系统”就写成没有现状。已有线下业务过程是现状；没有既有过程时，明确写出“当前没有该能力”及首个要建立的业务流程。

## 迭代

适用于既有目标业务能力中的局部新增或调整。不能只因项目复用既有小程序、账号体系或系统，就把首次建立的核心业务能力判为迭代。

主文档可以很短，但至少回答：

- 为什么现在要加/改；
- 加/改后要解决什么业务问题或获得什么结果；
- 是否影响既有角色、约束或边界。

不要把单点迭代扩成整个项目背景；如发现它实际改变了核心业务过程，应重新判断为重构或从 0 到 1。
