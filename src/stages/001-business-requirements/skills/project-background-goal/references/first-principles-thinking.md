# 第一性原理思考（First-Principles Thinking）

> **重要**：本目录是**思考引导层**（thinking reference），**不是产物模板**——不体现在 `user-journey.md` 或 `background-goal.md` 的结构里。
>
> AI 在 Generate 阶段做内部思考时按本目录追问，**追问结果用于填充主文档已存在的「项目背景」/「一句话旅程叙事」/「核心问题与证据」/「目标与成功判断」等节**——把"为什么要做"和"做成什么样"写得有根，不写空话。

---

## 0. 为什么要做这个 reference

模板填空式思考会回避根本问题：

- "项目背景"段写完只说"业务由来 / 为什么现在"——**没问"不做的代价"**
- "目标与成功判断"段写完只说"基线 → 目标 + 衡量"——**没问"目标被解决的定性标志"**
- "一句话旅程叙事"写完只说"触发到结果"——**没问"旅程要补的根本体验断层"**

本目录把"第一性原理"作为思考方式之一，强制 AI 在 Generate 阶段追问五问，五问结果**回填主文档已有节**（不是新建段），避免污染产物结构。

---

## 1. 五问（BG 视角）

| 追问 | 落点 | 反问示例 |
|---|---|---|
| **真正要解决的根本问题是什么？** | 主文档「项目背景」/「核心问题与证据」 | "用户说的需求 vs 业务真正卡在哪里，去掉'想做的功能'之后还剩什么？" |
| **不解决会怎样？** | 「项目背景」段中段 | "项目不存在的话，业务会怎样？写出来——让 PM 能拒绝'为做而做'的项目。" |
| **为什么是现在？** | 「项目背景」尾部 | "触发事件 / 外部约束 / 内部条件。不是'最近有人提了'。" |
| **核心假设是什么？** | 「核心问题与证据」+ governance 主张来源 | "项目成功依赖的 3-5 个关键假设；每条标 待验证 / 已验证 / 已证伪。" |
| **问题被解决的标志是什么？** | 「目标与成功判断」 | "定性的行为 / 结构 / 关系变化，证明问题已解——不是'项目已交付'。" |

## 2. 五问（UJ 视角）

| 追问 | 落点 | 反问示例 |
|---|---|---|
| **旅程要解决的根本体验断层是什么？** | 主文档「一句话旅程叙事」前置思考 | "去掉所有具体触点后，客户当前的体验链哪里断裂、为什么要补这段旅程？" |
| **不补会怎样？** | 「核心问题与证据」段 | "客户 / 业务 / 品牌的代价。旅程存在的根本理由。" |
| **为什么是现在补？** | 「业务生命周期分解」的「触发事件」列 | "政策 / 技术 / 竞品 / 用户行为变化 / 内部组织能力。" |
| **旅程推断的核心假设是什么？** | governance 主张来源 | "行为假设：客户真的会按这个路径走？触点假设：当前触点是否支持？技术假设：跨渠道一致性能实现？" |
| **体验连贯的标志是什么？** | 「路径与情绪」+「旅程覆盖与边界」 | "不同角色 × 不同入口 × 不同状态下，旅程是否一致、无缝、可中断可恢复。" |

## 3. BG 与 UJ 的映射

BG 问的是抽象层（项目层）"项目要解决的根本问题"；UJ 问的是具象层（旅程层）"旅程要补的根本体验断层"。两者是**同一根因的抽象层与具象层映射**——

- UJ 草稿前应先核对 BG 第一性原理段，保证旅程是在补背景目标的具体路径，而不是新发明一个体验问题
- 如果发现 UJ 追问的"根本体验断层"与 BG 追问的"根本问题"对不上，回到 BG 重新确认

## 4. 类型分支（按项目类型裁剪追问深度）

| 类型 | 五问裁剪 | 备注 |
|---|---|---|
| **重构** | 五问必答 | 机理解释 > 现状痛点；避免"换皮不换骨" |
| **从 0 到 1** | 五问必答 | 区分"真问题"与"想象中的问题"；避免 solution in search of a problem |
| **迭代** | 仅答两条（根本问题 + 不做的代价） | 小迭代过度论证反而拖慢；其他三问可标"不适用" |

## 5. AI 内部使用流程

1. 读本目录（每次 Generate 阶段开始时）
2. 按项目类型确定追问深度（重构 / 从 0 到 1 五问；迭代两问）
3. 对每个追问做内部思考，结果**回填到主文档已存在的节**：
   - BG：项目背景 / 核心问题与证据 / 目标与成功判断
   - UJ：一句话旅程叙事 / 业务生命周期分解 / 核心问题 / 路径与情绪 / 旅程覆盖与边界
4. **不在主文档加新段**——五问结果融入已有节，不破坏产物结构
5. 治理伴随文件的「主张来源与知识状态」表登记五问结果的来源（FACT / DECISION / AI_INFERENCE / UNKNOWN）

## 6. 与 anti-bloat / lite 的关系

- **anti-bloat**：五问结果如果用"待确认"敷衍，会被 `bg.bloat_warning` 标记（占位符密度高）；五问是反占位符的工具
- **P0-3 lite 注释**：五问不增加产物字段，但增加"必留节"内的提问深度；迭代类型 lite 模式下五问压缩为两问，与 P0-3 兼容
- **W6 五步决策树**：五问结果若与材料冲突，按五步决策树归因（已正确登记 TBC = 非缺陷）

## 7. 维护

- 本目录是**思考方式之一**，与护栏 ①-⑬ 平行存在；护栏管"产物形态"，本目录管"思考深度"
- 半年无争议可考虑下沉到 thinking-core.md（项目 framework 层）
- 争议大时保留在本目录作为 skill 内部的思考引导
