# 背景四要素（Background Four Elements）

> 来源吸收：work-buddy `prd-reviewer` skill 模块 2「项目/需求背景」评分标准——用户+场景+问题+量化数据四要素（格式规范 / 量化数据 / 描述清晰三档扣分）；对齐项目 background-goal 产物。
> 定位：background-goal.md 负责把"为什么做"落到可评审的结构；本文档凝练四要素写作指引与达标示例，供 Generate 背景/目标章节或 Audit/评审核对背景完整性时使用。
> 触发：Generate 背景/目标章节、或 Audit/Reviewer 核对背景完整性时。**按需加载，不设全局闸门**。

## 1. 四要素定义

| 要素 | 回答的问题 | 反例（不达标） |
|---|---|---|
| 用户 | 谁受影响、谁是直接使用者 | "用户普遍体验差" |
| 场景 | 在哪一步、什么情境发生 | "申请贷款提额时" → 缺具体场景则不给分 |
| 问题 | 已经发生的具体困难是什么 | "审批常被拒"（未点出为什么） |
| 量化数据 | 规模 / 发生率 / 影响范围的具体数值 | "很多用户受影响" |

## 2. 达标示例

> 针对借款用户（用户）在申请贷款提额时（场景），因无法提供可信征信材料导致审批被拒（问题），月均受影响用户约 5 万人，转化率下降 15%（量化数据）。

## 3. 核心硬规则

1. **四要素缺一不可**；缺「量化数据」视为背景不完整（上游评审模块 2 直接扣分项）。
2. **量化数据必须有具体数值**（用户量级 / 发生率 / 影响范围），拒绝"很多 / 一些 / 显著"这类无分母表述；数值缺失标 `待确认`。
3. **问题要落到"发生了什么"**，而不是停留在"体验不好"；**问题与目标成对出现**："做 X 以缓解 Y"。
4. **主张沿用 background-goal 的来源登记（SRC-ID）与六态知识标签**：可量化证据经核验才可标 `FACT`（核验清单见 `src/shared/audit/evidence-four-dimension-check.md`），未确证数值标 `AI_INFERENCE`/`UNKNOWN`，不凭空发明。
