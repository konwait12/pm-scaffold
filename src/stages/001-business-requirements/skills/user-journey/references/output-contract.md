# 用户旅程输出契约

本文件定义格式与边界，不提供任何项目事实或业务示例。缺少证据时使用 `待确认` 和知识状态，不要用模板占位内容冒充事实。

## 产物组成

### 主文档 `user-journey.md`

- 面向人和 AI 阅读，能够脱离治理文件理解当前旅程候选；
- 使用模板中的全部二级标题：预检与摘要、 一句话旅程叙事、业务生命周期分解、角色旅程矩阵、路径与情绪、触点/痛点/机会、旅程覆盖与边界、待确认与风险、参考资料；
- 只描述角色、阶段、行为、触点、交接、业务结果、可观察信号和明确的未知；
- 不包含治理表、哈希、审计记录、澄清 Session 或机器状态历史。

### 治理伴随文件 `user-journey.governance.md`

记录主张来源、知识状态、澄清问答、AI Audit、HTML 审阅板记录、PM 确认和主文档 SHA-256。它与主文档保持同一 `artifact_id` 和版本。

### 可选 `user-journey.board.html`

只从主文档和治理文件渲染角色、阶段、路径、情绪证据和未知项。单文件、零外部依赖、只读；不把 HTML 意见自动写回事实。

## 状态

AI 只能写：`draft`、`needs_user_input`、`conditional_review`、`ready_for_human_review`。`confirmed` 只能由授权人类在宿主流程中写入；`superseded` 只用于被新基线替代的历史版本。

## 知识状态

| 标签 | 含义 |
|---|---|
| `FACT` | 原始材料明确陈述，能定位到来源位置 |
| `DECISION` | 授权人类明确做出的决定 |
| `ASSUMPTION` | 为继续分析而暂时采用，尚未确认 |
| `AI_INFERENCE` | AI 基于材料推导的解读，不是事实 |
| `UNKNOWN` | 当前材料无法判断 |
| `CONFLICT` | 两个来源的陈述不兼容，等待裁决 |

## 澄清记录字段

治理文件每条澄清至少记录：`question_id`、问题、AI 初步判断及证据、A/B/C 三个互斥选项、PM 答复、负责人、影响、是否阻断、回写位置和回写后的 Audit 结果。未获 PM 答复的问题不得标为已确认。

## 下游交接

旅程确认后提供紧凑交接摘要：确认版本、旅程叙事、角色、生命周期阶段、路径覆盖、非阻断未知和来源 ID。下游 `user-stories` 可据此继续工作，但不得反向修改旅程事实。
