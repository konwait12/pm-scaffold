# 用户旅程澄清问题模式

本文件只定义提问结构，不提供项目事实。所有方括号内容必须由当前任务的原始材料替换；不能把示例当作答案。

## 提问结构

每个问题都按以下顺序组织：

```text
AI 初步判断：基于 [来源/位置]，当前更接近 [判断]，但 [不确定性]。
问题：[一个会改变角色/阶段/路径/情绪/边界的问题]？
选项：A) [解释一]  B) [解释二]  C) [解释三]  其他：自由回答
影响：[选择后会改变哪些旅程节点或下游交接]
负责人：[事实负责人或目标决策负责人]
阻断：[yes/no]
```

每轮最多 5 个问题，按“影响 × 不确定性”排序。选项必须互斥，不能把“待确认”伪装成选项。

## 1. 角色与责任

**触发**：材料出现多个参与者，但责任、目标或交接归属不清。

```text
AI 初步判断：材料中的 [角色 A] 负责 [行为/结果]，[角色 B] 可能参与 [交接]，但归属未明确。
问题：该节点的主要责任角色是哪一类？
选项：A) [角色 A]  B) [角色 B]  C) [两者共同负责]  其他：自由回答
```

## 2. 阶段边界

**触发**：两个阶段的进入/离开标志重叠，或主线顺序无法从材料确定。

```text
AI 初步判断：来源明确了 [事件一] 和 [事件二]，但未说明它们是否属于同一阶段。
问题：[事件一] 与 [事件二] 应如何划分？
选项：A) [同一阶段]  B) [拆成前后两个阶段]  C) [仅保留材料明确的阶段]  其他：自由回答
```

## 3. 主路径与变体

**触发**：来源描述了不同入口、条件或结果，但无法判断哪条是主路径。

```text
AI 初步判断： [来源 A] 描述 [路径一]，[来源 B] 描述 [路径二]；当前无法判断主次。
问题：本次旅程的主路径是哪一条？
选项：A) [路径一]  B) [路径二]  C) [两条并列，按条件区分]  其他：自由回答
```

## 4. 痛点与情绪证据

**触发**：材料只描述方案、抱怨或结果，没有可观察行为支撑痛点/情绪。

```text
AI 初步判断：材料支持 [可观察行为]，但不能证明 [情绪或痛点结论]。
问题：该节点应如何记录？
选项：A) [仅记录可观察行为]  B) [标为 AI_INFERENCE，等待确认]  C) [标为 UNKNOWN 并暂不推导]  其他：自由回答
```

## 5. 交接与恢复

**触发**：异常退出后由谁接手、如何回到主路径未被材料说明。

```text
AI 初步判断：异常在 [节点] 发生；来源没有明确恢复责任或回流位置。
问题：该异常的恢复路径采用哪种记录？
选项：A) [原角色在原节点恢复]  B) [交给指定角色后恢复]  C) [材料不足，保留 UNKNOWN 并阻断]  其他：自由回答
```

## 使用约束

- 不询问可以从当前材料直接读取的事实；先回查原始文件和位置。
- 不用联网搜索、行业惯例或模型记忆替 PM 选择答案。
- 不把技术实现、页面名称或按钮动作作为旅程决策选项；先改写为角色行为和业务结果。
- PM 选择后，把原问题、AI 判断、选项、回答、负责人和回写位置写入治理伴随文件。
