# 用户旅程人工审查清单

本清单供 PM/业务负责人审查 `user-journey.md`。清单不提供业务示例；所有判断必须回到本次原始材料和治理伴随文件。

## 正确性

- [ ] 每个角色、阶段、触点和结果都能定位到原始材料位置或明确标为 `AI_INFERENCE` / `UNKNOWN`。
- [ ] 材料中的说话人、时间、条件和交接关系没有被改写成其他含义。
- [ ] 冲突来源同时保留，并已标出需要哪位负责人裁决。

## 完整性

- [ ] 每个材料明确出现的角色都有独立旅程记录。
- [ ] 每个材料明确出现的生命周期阶段都有触发、行为、触点和结果。
- [ ] 正常、备选、异常、失败、交接和恢复路径的缺口已显式写出，而不是静默留白。
- [ ] 情绪和痛点只在存在可观察证据时成立；否则标为未知。

## 边界与可用性

- [ ] 叙事停留在角色行为和业务结果层，没有页面、按钮、字段、接口或实现方案。
- [ ] 每个机会都能追溯到一个来源支持的痛点或阻碍，并描述为可观察的改进结果。
- [ ] 主文档没有治理表、哈希、审计历史或机器确认记录。
- [ ] 治理伴随文件记录了来源、知识状态、澄清、Audit、HTML 一致性和 PM 决定。

## HTML 审阅板

- [ ] HTML 只呈现 Markdown 已有的节点，没有新增页面、功能、文案、状态或业务结论。
- [ ] 角色、阶段、路径、情绪证据、未知项与 Markdown 一致。
- [ ] 筛选、展开、锚点和窄屏阅读可用，且没有外部网络依赖。

## 最终判断

1. 这份旅程是否准确表达材料中的角色如何走完业务生命周期？
2. 哪些节点仍需事实负责人或目标决策负责人选择 A/B/C？
3. 是否可以把当前版本交给授权评审人，而不把 AI 推断误认为已确认事实？
