# 旅程提取护栏（Journey Extraction Guardrails：品类分列 / 形态枚举 / 空态与身份骨架 / 版式文字化 / 占位符登记）

> 来源吸收：盲测对比修复（CHANEL Digital Passport 第二轮 A-1～A-7 归因；方法论经 2026-09-02 零引导复测验证——品类分列类缺陷在无规则时不可复现，必须显式规则化）。
> 定位：旅程产物最常见的失真不在"结构"而在"提取粒度"——原材料明明给了、产物却丢了或合并了：①多品类并列展示被合并成一句笼统表述；②notification/reminder/alert 类提示被并入已知形态而漏枚举；③空态与身份分支只登记 TBC 不画骨架、影响面丢失；④图片/版式型线索（模板缩略图、并列方案图、流程图节点）未文字化；⑤文案占位符未登记导致下游返工。本文件是拦截这五类缺陷的**强制提取护栏**。
> 触发：**每次 Generate 前必读**（与 output-contract 并列的强制加载项）；材料含多品类/多变体并列页、通知提醒类词汇、界面状态矩阵/弹窗清单、占位符文案、图片缩略图与并列方案图时，尤其要逐条过。方法不构成项目事实。

## 2. 五条护栏

### 护栏 1：品类/变体强制分列（禁止跨品类合并表述）

- **触发**：原材料出现多品类/多变体**并列展示**（HBG PDP 与 RTW PDP 分页/分列/分 Tab），或同一行为在不同品类下存在差异。
- **动作**：
  1. 提取信息字段、功能入口、信息入口时必须**按品类分列成对照表**（列 = 品类；行 = 维度，如信息字段 / 功能入口 / 信息入口 / 删除入口 / 内容法务待办 / 适用范围），**颗粒度对齐目标态材料自身的品类枚举**——材料给了几档就分几列，不自行归并为「其他 / 特殊」；
  2. 矩阵节点可以合并行为，但必须保留"**品类适用范围**"标注（如"ORT 入口现仅见于 HBG 详情；RTW 详情仅 OAB"），差异不允许在节点层被吞掉；
  3. 对照表写入主文档（business+product 粒度）或路由到下游（page-design / business-rules 显式继承），并在待确认/路由说明中注明"下游禁止再次合并表述"。
- 反例 → 正例：
  - 反例（A-1 复现）：C-11「查看单件 DP 详情（产品、购买、保修信息；护理指引…）」——RTW 无 Warranty 的结构差异被合并掉；
  - 正例：C-11「查看单件 DP 详情——HBG/RTW 的信息字段与入口**按品类分列**（RTW 无 Warranty、有 Size；信息入口命名不同；ORT 仅 HBG 出现，详见品类对照表）」。

### 护栏 2：通知/提醒/提示形态枚举清单（独立节点不并入已知形态）

- **触发**：材料出现 notification / reminder / alert / 提示 / 提醒 / 通知 / 标签 / 红点 / 弹窗 等词汇，或流程图中存在**独立提示节点**（如 Receive a reminder）。
- **动作**：
  1. 输出该旅程的**提醒形态清单**：外部渠道消息（短信/邮件/服务号消息…）与站内提醒（红点/标签/弹窗…）逐条枚举，每条含材料定位、已知规则、旅程落点与证据；
  2. **子态强制拆分**：每种形态按角色 × 渠道 × 成功/失败等子态各自成条，不并入「成功态」/「失败态」统称；例：「注册成功推送」「注册失败推送」必须独立成条，不写一条「注册推送」；
  3. 流程图中**独立出现但未定义规则**的节点（Receive a reminder），禁止并入已知形态——登记为独立形态，并生成澄清问题（触发频率/出现条件/文案/与红点标签的关系）；
  4. 清单与路径转述对读，避免"路径转述里出现过、清单里却没有"。

### 护栏 3：空态与身份分支骨架必检（TBC 也先画骨架）

> **骨架≠裁决**：本护栏要求"先画骨架 + 影响面清单"，是为防止遗漏与下游返工；它**不是**替上游裁决空态与身份分支去向。骨架格中材料无证据者标 TBC/UNKNOWN，**不画成已决路径**；裁决被推翻时按本护栏更新 E 表与空态去向，不沿用旧假设。

- **触发**：旅程含"资产类"对象（作品列表/收藏/证件/票券）或入口受"是否拥有/是否某身份"控制；**或旅程含「经链接/卡片/二维码唤起」的触点（通知、分享、邀请函、电子凭证）——「点开的人 ≠ 接收人」是普遍分支维度**。
- **动作**（对应盲测 A-6/B-12 教训）：
  1. **资产空态必检**：资产状态至少三行——从未拥有 / 曾拥有已删光或解绑 / 正常拥有——对到列表、各入口的去向；材料无证据的格子标 TBC/UNKNOWN，**不替上游裁决**（绝不采信未被证实的假设）；
  2. **身份 × 登录态 × 资产状态分支骨架**：列出各维度取值 → 影响的旅程节点 → 材料给出的去向；即使材料标 TBC 也要输出骨架，并给出"该决策将分叉哪些节点"的**影响面清单**；
  3. **访问权限分支骨架（接收人/非接收人）**：凡旅程含链接/卡片/二维码触点，登记「接收人 / 非接收人」两个角色的去向——非接收人点开后的行为（无权限访问提示页 / 提示联系 FA / 静默失效等）必须显式登记；材料无证据时标 TBC，AI 不裁决；详见 `question-patterns.md` 对应探针问题；
  4. **handoff 触点对方侧骨架**：凡「把内容交给另一个人」的触点（分享、转赠、转发、协同邀请），登记对方侧节点骨架（进入点 → 可见内容版本 → 失效/异常去向）；材料未覆盖处标 TBC，AI 不裁决；
  5. 骨架去向随澄清/上游裁决更新；若裁决推翻了材料假设（如入口在删光后仍保留），更新 E 表与空态去向，不沿用旧假设。

### 护栏 4：版式型线索文字化（图片/并列图逐图枚举）

- **触发**：材料以图片/版式承载信息——模板缩略图、多方案并列图、流程图节点、分栏列表、图注/alt、页脚 TBC 标注；**或任何内容主体位于图片中的页**（含整页 PPT 截图、流程图、扫描件、多方案并列图等）。
- **动作**：
  1. **先做材料元数据核对**：登记总页数 / 页码口径（PDF 页序 vs 材料自编号）/ 载体类型分布；下游所有页码引用统一按该口径，防止错位引用；
  2. **逐页台账**（详见 `source-handling.md` 同步新增的「逐页台账」段）：每页登记「页码 × 载体 × 解析状态 × 一句话摘要 × 证据状态 × 澄清问题 ID」；不可解析页必须附已尝试的证明（OCR / 视觉解析后仍无可读内容），并**逐页**生成一条澄清问题；
  3. **无文字描述的图片页必须先尝试视觉解析**——内容进入产物，或升级为单条澄清问题，两者都必须在治理文件留记录；
  4. 逐图/逐列把可见选项**枚举为条目**（如"EDM 模板有三种图示：Leather goods / RTW / RTW & Leather goods"），不许"XX 通知""若干模板"一笔带过；
  5. 枚举后若选择/触发规则未给，登记待确认（如模板按什么选）；
  6. 图注/页脚的 TBC、pending、assumption 一并进入待确认清单（与 SKILL.md「待确认的两个来源」扫描要求对齐）。

### 护栏 5：占位符与动态变量登记（供下游直接认领）

- **触发**：文案含占位符（XX、女士/先生、链接示例、变量符）或动态取值字段。
- **动作**：登记"**动态变量清单 + 取值口径待确认 + 来源位置**"，写入待确认或产品层附注（如短信：【XX 称谓】【女士/先生】取值口径（客户姓氏/性别）待确认；落地链接为示例 URL）；不替下游决定取值口径，但让下游 BRD/模板开发可直接认领。

### 护栏 6：系统级 UI 提示机制（护栏 ⑥）

- **触发**：材料定义跨页面存在的提示机制（角标/未读/提示点类）—— 跨页面复用、状态独立、可能有后台配置项。
- **动作**：独立登记「触发场景 × 是否可配置 × 默认态 × 影响范围」四元组，不并入普通触点或字段表。
- **适用形态无关表述**（不绑具体平台）：「跨页面提示」「未读提示」「配置型提示机制」等可触发本护栏。

### 护栏 7：按用户态切换的 UI 元素（护栏 ⑦）

- **触发**：材料出现「满足条件 A 才展示元素 B」类规则——按用户态（登录/未登录/已关注/未关注）、按数据态（有/无）、按时间态（D-1/D/D+1）切换的 UI 元素。
- **动作**：登记「触发条件 × UI 元素」矩阵——每个条件组合对应一个 UI 元素（卡片/弹窗/按钮/标签），不并入普通字段表。

### 护栏 8：CTA 动态配置（护栏 ⑧）

- **触发**：材料的 CTA（按钮）显隐/数量/文案可配置，或不同活动类型 / 不同状态显示不同 CTA。
- **动作**：登记「文案 × 是否可配 × 配置维度 × 默认态」四元组；配置维度需列明（如「按活动类型 / 按活动状态 / 按用户角色」），不写为单一维度的开关。

### 护栏 9：系统生成物（护栏 ⑨）

- **触发**：材料定义系统生成的码/链接/凭证类对象（邀请码 / 二维码 / 一次性链接 / 电子凭证 / 校验码）—— 客人在旅程中接收、消费或转发。
- **动作**：登记「生成维度 × 有效期 × 生成方 × 消费方」四元组；生成维度需列明（按活动 / 按店铺 / 按场次 / 按时间窗等），不写为单一维度的对象。

### 护栏 10：骨架底座原则（护栏 ⑩）

- **触发**：目标态材料（BRD / PRD）与现状材料（AS-IS / 运营沉淀）同时在场。
- **动作**：分支骨架以**目标态状态机为底**（即将实现的目标结构），现状证据单独成段做映射，禁止混用——否则会拿 AS-IS 的弹窗去压平 BRD 的状态机层级。例：BRD 「即刻预约」定义三重判断（活动结束 × 场次过期 × 客人预约/签到状态）的状态机，不能用 AS-IS 的六类异常弹窗压平。

### 护栏 11：入口生命周期四列（护栏 ⑪）

- **触发**：材料出现入口列表（菜单项 / 跳转路径 / Tab / 服务号菜单项），尤其是 BRD 包含删除/改版的入口。
- **动作**：登记四列「现有 / 新增 / 已删除 / 待定」——目标态材料的删除线与变更日志中的入口删除必须有落点（不能合并到「现有」里悄悄丢）；无删除时该列空即可，不删除列。

### 护栏 12：阶段 ↔ User Story 映射表（护栏 ⑫）

- **触发**：旅程用生命周期阶段；需求方用 User Story 编号。
- **动作**：两套坐标系必须建一对多映射表（一个旅程阶段可对应多个 User Story，一个 User Story 通常只对应一个阶段）。下游 user-stories skill 凭映射认领；缺映射表 = 下游无法认领 → 等于旅程与 User Story 断链。

### 护栏 13：不编造检查（护栏 ⑬）

- **触发**：产物中拟登记任何形态/选项/方案。
- **动作**：产物中任何在目标态材料里找不到出处的形态/选项/方案，必须在治理文件标 `AI_INFERENCE` / `ASSUMPTION`，禁止与 `FACT` 在主文档同等呈现（并列「待确认方案」也不行——并列也会被读为等同）。


## 3. 工作流程

1. **扫并列页/并列图**（护栏 1/4）：通读材料，标记所有多品类并列展示与图片承载信息；
2. **扫形态词**（护栏 2）：全文检索 notification/reminder/提醒/标签/红点/弹窗/提示类词，对照流程图独立节点——按子态拆分（成功/失败等）；
3. **扫空态与身份 + 链接接收人 + handoff 对方侧**（护栏 3）：找出受"拥有状态/身份/登录态"控制的入口与列表，含链接/卡片触点的接收人/非接收人分支、handoff 触点的对方侧骨架；
4. **扫占位符**（护栏 5）：标记文案变量与示例链接；
5. **扫系统级 UI 机制**（护栏 6-9）：跨页面提示机制、条件渲染元素、CTA 动态配置、系统生成物——四类独立登记；
6. **扫入口生命周期**（护栏 11）：标记现有/新增/已删除/待定入口——已删除入口必须有落点；
7. **扫阶段 ↔ User Story 映射**（护栏 12）：建立映射表，避免下游断链；
8. **扫底座选择**（护栏 10）：目标态材料 vs 现状材料同时在场时，骨架以目标态为底；
9. **落产物**：品类对照表与形态清单进产品层展开（business+product）或路由说明；空态/身份/链接接收人/handoff 对方侧骨架进覆盖与边界或 E 表；占位符进待确认；UI 机制四段进触点表后子段；映射表独立段；入口生命周期独立段；
10. **不编造复检**（护栏 13）：每条形态/选项/方案有材料出处；无出处标 AI_INFERENCE/ASSUMPTION；
11. **Generate 后自检**：按 §6 清单逐条过，未过项修复后再 Audit。

## 4. 核心硬规则

1. 多品类并列 → 必须分列对照（颗粒度对齐目标态品类枚举），禁止跨品类合并表述；
2. 独立提示节点 → 独立登记 + 澄清问题，禁止并入已知形态；通知枚举强制子态拆分；
3. 空态与身份分支 → 即使 TBC 也画骨架 + 影响面清单，禁止只登记不推导、禁止替上游裁决；含链接接收人 / handoff 对方侧骨架；
4. 图片/版式线索 → 逐图枚举文字化（先做元数据核对 + 逐页台账 + 视觉解析），禁止一笔带过；
5. 占位符 → 必登记变量 + 口径待确认，禁止沉默；
6. 系统级 UI 提示机制 → 独立登记四元组，不并入普通触点；
7. 按用户态切换的 UI 元素 → 登记「触发条件 × UI 元素」矩阵；
8. CTA 动态配置 → 登记「文案 × 是否可配 × 配置维度 × 默认态」；
9. 系统生成物 → 登记「生成维度 × 有效期 × 生成方 × 消费方」；
10. 骨架底座 → 目标态材料与现状材料同时在场时，以目标态状态机为底；
11. 入口生命周期 → 四列登记，已删除入口必须有落点；
12. 阶段 ↔ User Story → 必须建映射表；
13. 不编造 → 产物中任何无出处的形态/选项/方案必须标 AI_INFERENCE/ASSUMPTION。

## 5. 边界（Do Not）

- 不分列成"页面级字段全量清单"——只提取**材料明确的品类间差异**，页面字段细节路由 page-design；
- 不为凑形态枚举引入材料未出现的渠道/提醒；
- 空态与身份去向若材料无证据，标 TBC/UNKNOWN，**不画成已决路径**（骨架 ≠ 裁决）；
- 不把占位符取值口径猜死（不写"XX=姓"除非材料如此）；
- 本护栏只管提取完整性，不新增业务阶段、不改模板 frontmatter、不改状态机语义。
