# 旅程矩阵与关键时刻技法（Journey Matrix & Moments of Truth）

> 来源吸收：进化驱动力、JTBD、SDT、生命周期切分和机会评分等方法，作为 user-journey 的可选落地能力；方法不构成项目事实。
> 定位：把"每角色一张旅程图"升级为"角色×阶段矩阵 + 情绪曲线 MOT + 触点矩阵"的结构化旅程技法——先切矩阵再填充，让旅程阶段、触点、情绪、机会都有据可依、无死角。
> 触发：旅程涉及多角色多阶段、需定位关键时刻（MOT）或把痛点转成可量化机会时加载。**按需加载，不设全局闸门**。

## 1. 输入映射（pm-scaffold 语境）

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| 生命周期阶段 | user-journey 的阶段定义参考 | 只采用当前原始材料明确的阶段和进入/离开标志 |
| 进化驱动力（停用→不适信号） | user-journey 情绪曲线的低落点来源 | 判"用户在哪个阶段最想弃用" |
| JTBD 三层 | 阶段的行为与情绪标注 | 仅作为分析提问，不能替代材料中的事实 |
| SDT 三维（自主/胜任/关联） | MOT 的定位依据 | 关键时刻 = 自主/胜任/关联感被放大或受挫的触点 |
| 情景分析五要素（任务/时间/地点/起因/经过/条件/道具） | 阶段内容填充（行为与触点） | 每个阶段补"什么情景下发生" |
| 机会评分（重要性×满意度） | 痛点→机会的量化排序 | 机会不止"对应上"，还要按机会分排序 |

> **先切矩阵，再填充内容**（呼应 `src/framework/thinking-core.md` 的 MECE 思路）：禁止直接列旅程清单；先按角色 × 生命周期阶段切出矩阵，再逐格填充。

## 2. 角色×生命周期阶段矩阵（MECE 切分）

### 2.1 阶段参考轴（以原始材料为准）

| 来源情况 | 阶段轴 | 说明 |
|---|---|---|
| 材料明确阶段 | `[阶段 A] → [阶段 B] → …` | 只使用材料中的名称，不用行业惯例补齐 |
| 阶段不完整 | `[已知阶段]` + `UNKNOWN` | 缺少进入/离开标志时进入 Clarify |

**阶段切分自检**：阶段之间互斥、并集覆盖全程，每阶段有材料支持的进入/离开标志。切不出明确边界时进入 Clarify，不用行业惯例补齐。

> **空态与分支骨架的下游**：矩阵中关于"资产状态×登录×身份"的空态格与分支处理（如"未创建 DP 时入口去向""All User vs InCHANEL Client 身份×登录态组合去向"），按 `journey-extraction-guardrails.md` 护栏 3 处理——**骨架≠裁决**：TBC 也先画骨架并给出影响面清单，不替上游裁决，不沿用未被证实的假设。

### 2.2 矩阵模板

行 = 角色（来自已确认的上游产物），列 = 当前原始材料明确的阶段，格内填 `行为 / 触点 / 情绪`。

| 角色 \\ 阶段 | [阶段 A] | [阶段 B] | [阶段 C] |
|---|---|---|---|
| [角色 1] | | | |
| [角色 2] | | | |
| [角色 3] | | | |

- **先建空矩阵，确认角色×阶段网格完整，再填充**——网格数 = 角色数 × 阶段数，每一格都必须有内容（无内容 = 信息缺口 → 进 Clarify，不许空白跳过）。
- 每格行为/触点/情绪必须逐字来自来源（挂 SRC-*），AI 补全标 `AI_INFERENCE`。

## 3. 情绪曲线与关键时刻 MOT

### 3.1 情绪来源判据（producrequirementanalyzer 三框架）

情绪不是凭空写的"高兴/沮丧"，必须挂判据：

| 判据框架 | 问法 | 情绪落点 |
|---|---|---|
| 进化驱动力 | "如果停止当前旅程，这个角色最强烈的不适是什么？" | 不适最强的阶段 = 情绪低谷候选 |
| JTBD 三层 | 功能工作（任务完成度）/ 情感工作（感受）/ 社会工作（别人怎么看） | 三层任一未满足 → 情绪低；超预期满足 → 情绪高 |
| SDT 三维 | 自主（有选择/控制感）、胜任（做得到）、关联（被看见/有联结） | 三维受挫触点 = MOT 负向候选 |

### 3.2 关键时刻（MOT）识别

MOT = **情绪剧烈波动或行为方向转折的触点**，满足以下任一即是：

1. **情绪断崖**：该触点前后情绪分差明显，或出现材料记录的放弃行为。
2. **决策翻转**：该触点改变角色对当前旅程的判断。
3. **干系人分叉**：同一触点上不同角色出现相反反应。

**情绪标注规范**：用具体可观察行为描述，不用形容词。每个情绪点标注判据来源和原始材料位置。

## 4. 触点矩阵（阶段×触点×渠道×情绪×机会）

对每个阶段的触点展开一行，形成触点矩阵：

| 阶段 | 触点（MOT 打 ★） | 渠道/媒介 | 角色情绪 | 判据来源 | 机会 |
|---|---|---|---|---|---|
| [阶段 A] | [材料中的触点] | [渠道] | [可观察反应/UNKNOWN] | [证据位置] | [可衡量改进结果/UNKNOWN] |
| [阶段 B] | [材料中的触点] | [渠道] | [可观察反应/UNKNOWN] | [证据位置] | [可衡量改进结果/UNKNOWN] |

触点类型可以是人、系统、线下或文档；只记录原始材料明确的媒介，不为补齐类型而新增触点。

## 5. 痛点→机会转换规则（什么算真痛点）

### 5.1 真痛点四判定（缺一不算）

1. **有行为证据**：来源里有可观察的行为（尝试 3 次、打电话投诉、绕过系统走线下），不是"我觉得这个体验不好"。
2. **有停用/放弃威胁**：材料显示痛点可能导致角色退出或改变路径。
3. **有量化代价**：材料或 PM 提供了时间、金钱、人力或错误等代价；否则标 UNKNOWN。
4. **非个人偏好**：跨角色或跨来源重复出现（O 类意见至少 2 个独立来源印证），或直接导致决策翻转（MOT）。

### 5.2 机会量化（pmaster 机会评分 + 重要×满意矩阵）

```
机会评分 = 重要性 × (1 − 满意度)     # Dan Olsen 机会评分，归一化 0-1
高重要性 × 低满意度 = 优先补（最关键空白）
高重要性 × 高满意度 = 守成
低重要性 × 任意   = 暂缓
```

每个机会可追加 KANO 标签，但只能依据材料或 PM 判断。机会写成可衡量的改进结果，不写功能方案。

## 6. 结构化填充示意（无业务事实）

以下仅展示字段关系。将 `[角色]`、`[阶段]`、`[行为]`、`[证据]` 替换为当前原始材料中的内容；不要沿用示意中的阶段、渠道、数字或方案。

| 角色 \\ 阶段 | [阶段 A] | [阶段 B] |
|---|---|---|
| [角色 1] | 行为：[行为]；触点：[触点]；情绪：[UNKNOWN/证据] | 行为：[行为]；触点：[触点]；情绪：[UNKNOWN/证据] |
| [角色 2] | 未参与/未知（说明原因） | 行为：[行为]；触点：[触点]；情绪：[UNKNOWN/证据] |

关键时刻只在材料显示情绪转折、决策翻转或角色分叉时标记，并附 `[来源/位置]`。机会写成可观察的业务结果，未经材料或 PM 决策支持的内容保留为 `UNKNOWN`。

## 7. 工作流程

1. **枚举角色与阶段**：从已确认的上游产物和当前原始材料取角色与阶段；MECE 校验阶段互斥+穷举。
2. **建空矩阵**：角色×阶段网格先行，确认网格完整（无缺格、无重复）。
3. **逐格填充**：每格填 行为/触点/情绪，全部挂来源；空白格写原因（"未参与"或 → 进 Clarify）。
4. **标 MOT**：扫全矩阵，用情绪断崖/决策翻转/干系人分叉三判据标 ★。
5. **铺触点矩阵**：按阶段列触点、渠道、情绪、判据来源；补机会列。
6. **痛点→机会**：对每个 MOT 与低情绪点过"真痛点四判定"；合格者用机会评分+KANO 排序成机会清单。
7. **输出**：矩阵 + 情绪曲线图 + 触点矩阵 + 机会清单写入 user-journey.md 对应章节。

## 8. 核心硬规则

1. **先切矩阵再填充**：禁止直接列旅程清单；角色×阶段网格不完整不许填充（thinking-core §3 MECE）。
2. **每格有据**：矩阵每格行为/触点/情绪挂 SRC-*；AI 补全标 `AI_INFERENCE`，空格写原因不静默跳过。
3. **情绪必须有判据**：情绪点标注进化驱动力/JTBD 层/SDT 维来源；无来源的情绪 = 凭空发明，一票否决。
4. **MOT 三判据**：关键时刻必须命中 情绪断崖/决策翻转/干系人分叉 之一，否则不是 MOT。
5. **真痛点四判定**：无行为证据、无停用威胁、无量化解代价、个人偏好的，不算痛点，不进机会清单。
6. **机会可量化**：每个机会是"可衡量的改进结果"并挂 KANO 标签；写成功能方案（"加个按钮"）即不合格。

## 9. 边界（Do Not）

- 不写用户故事卡片或范围基线（→ user-stories）——矩阵停在"旅程客观映射"层。
- 不设计功能清单（→ feature-list）——机会写改进结果，不写功能。
- 不替角色决定"该怎么做"——只记录行为与情绪的客观事实。
- 不因某角色阶段"不重要"就省略网格——空格写原因或进 Clarify，不删行列。
- 不合并不同角色的旅程为一条"标准路径"——角色差异正是 to B 价值所在。
- 不为凑情绪点发明高/低谷——无判据的情绪一律不标。

## 10. 质量自检清单

- [ ] 角色×阶段矩阵已先建空网格再填充，网格无缺格无重复（MECE）
- [ ] 阶段轴来自原始材料，阶段边界有可观察进入/离开标志
- [ ] 每格行为/触点/情绪挂来源（SRC-* / AI_INFERENCE），无裸奔格
- [ ] 情绪曲线每个点标注判据（进化驱动力/JTBD/SDT）
- [ ] MOT 均命中三判据之一且标 ★
- [ ] 触点矩阵含人/系统/线下/文档类触点，无"只有线上触点"
- [ ] 每个痛点过"真痛点四判定"，不合格者已剔除
- [ ] 机会清单含机会评分或重要×满意定位 + KANO 标签，且为可量化改进结果
- [ ] 机会可回指到具体痛点与 MOT（有追溯链）
