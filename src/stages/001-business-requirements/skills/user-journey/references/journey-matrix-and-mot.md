# 旅程矩阵与关键时刻技法（Journey Matrix & Moments of Truth）

> 来源吸收：`producrequirementanalyzer`（product-requirements-analyzer）的进化驱动力/JTBD/SDT/重要-满意矩阵、`pmaster`（PM Master）的 AARRR 生命周期阶段与机会评分、`pmskills`（网龙产品设计方法论）的情景分析五要素，作为 user-journey 的可选落地能力。
> 定位：把"每角色一张旅程图"升级为"角色×阶段矩阵 + 情绪曲线 MOT + 触点矩阵"的结构化旅程技法——先切矩阵再填充，让旅程阶段、触点、情绪、机会都有据可依、无死角。
> 触发：旅程涉及多角色多阶段、需定位关键时刻（MOT）或把痛点转成可量化机会时加载；也适用于 to B 多干系人采购类旅程的阶段拆解。**按需加载，不设全局闸门**。

## 1. 输入映射（pm-scaffold 语境）

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| AARRR 生命周期阶段（获取/激活/留存/收入/推荐） | user-journey 的阶段定义参考 | to C 旅程阶段可映射；to B 用采购旅程阶段（认知→评估→试用→采购→实施→续费） |
| 进化驱动力（停用→不适信号） | user-journey 情绪曲线的低落点来源 | 判"用户在哪个阶段最想弃用" |
| JTBD 三层（功能/情感/社会） | 阶段的行为与情绪标注 | 每个阶段回答"用户雇佣产品完成什么工作、什么感受、希望别人怎么看" |
| SDT 三维（自主/胜任/关联） | MOT 的定位依据 | 关键时刻 = 自主/胜任/关联感被放大或受挫的触点 |
| 情景分析五要素（任务/时间/地点/起因/经过/条件/道具） | 阶段内容填充（行为与触点） | 每个阶段补"什么情景下发生" |
| 机会评分（重要性×满意度） | 痛点→机会的量化排序 | 机会不止"对应上"，还要按机会分排序 |

> **先切矩阵，再填充内容**（呼应 `src/framework/thinking-core.md` §3 MECE 穷举）：禁止直接列一张"用户旅程清单"；必须先按 角色 × 生命周期阶段 切出矩阵网格，再逐格填充，确保网格无空格、无重复。

## 2. 角色×生命周期阶段矩阵（MECE 切分）

### 2.1 阶段参考轴（pmaster AARRR → to B 采购旅程）

| 产品形态 | 阶段轴（MECE 穷举） | 说明 |
|---|---|---|
| to C | 获取 → 激活 → 留存 → 收入 → 推荐（AARRR） | 以"用户与产品的关系推进"切，互斥且可穷举 |
| to B 采购 | 认知 → 评估 → 试用 → 采购 → 实施 → 续费 | 以"采购决策链推进"切；to B 关键在评估与实施两段的多干系人差异 |

**阶段切分自检**：阶段之间互斥（一个时刻只属于一个阶段）、并集覆盖全程（无"漏掉的阶段"）、每阶段有可观察的进入/离开标志（如"提交采购单 = 从试用进入采购"）。切不出明确边界的阶段合并或丢弃，不保留模糊中间态。

### 2.2 矩阵模板

行 = 角色（来自已确认 `background-goal.md` 的角色枚举），列 = 阶段（MECE 穷举），格内填三件套：`行为 / 触点 / 情绪`。

| 角色 \ 阶段 | 认知 | 评估 | 试用 | 采购 | 实施 | 续费 |
|---|---|---|---|---|---|---|
| 业务负责人 | | | | | | |
| IT 决策人 | | | | | | |
| 采购经理 | | | | | | |
| 一线使用团队 | | | | | | |

- **先建空矩阵，确认角色×阶段网格完整，再填充**——网格数 = 角色数 × 阶段数，每一格都必须有内容（无内容 = 信息缺口 → 进 Clarify，不许空白跳过）。
- 每格行为/触点/情绪必须逐字来自来源（挂 SRC-*），AI 补全标 `AI_INFERENCE`。

## 3. 情绪曲线与关键时刻 MOT

### 3.1 情绪来源判据（producrequirementanalyzer 三框架）

情绪不是凭空写的"高兴/沮丧"，必须挂判据：

| 判据框架 | 问法 | 情绪落点 |
|---|---|---|
| 进化驱动力（停用→不适） | "如果停用，这个角色最强烈的'不适'是什么？" | 不适最强的阶段 = 情绪低谷候选 |
| JTBD 三层 | 功能工作（任务完成度）/ 情感工作（感受）/ 社会工作（别人怎么看） | 三层任一未满足 → 情绪低；超预期满足 → 情绪高 |
| SDT 三维 | 自主（有选择/控制感）、胜任（做得到）、关联（被看见/有联结） | 三维受挫触点 = MOT 负向候选 |

### 3.2 关键时刻（MOT）识别

MOT = **情绪剧烈波动或行为方向转折的触点**，满足以下任一即是：

1. **情绪断崖**：该触点前后情绪分差 ≥2 级（如 中→低），或出现可观察的放弃行为（"第 3 步找不到按钮，尝试 3 次后放弃"）。
2. **决策翻转**：该触点会改变角色对产品的整体判断（"试用期宕机一次 → 评估结论由通过变否决"）。
3. **干系人分叉**：该触点上不同角色出现相反情绪（业务负责人满意 vs 一线团队沮丧），预示实施阻力。

**情绪标注规范**：用**具体可观察行为**描述，不用形容词。❌"不满意"→ ✅"评估会议上直接否决，追问竞品比价"。每个情绪点标注判据来源（进化驱动力/JTBD 层/SDT 维 + SRC-*）。

## 4. 触点矩阵（阶段×触点×渠道×情绪×机会）

对每个阶段的触点展开一行，形成触点矩阵：

| 阶段 | 触点（MOT 打 ★） | 渠道/媒介 | 角色情绪 | 判据来源 | 机会 |
|---|---|---|---|---|---|
| 认知 | 行业峰会演讲 ★ | 线下/销售拜访 | 中↑（认可） | JTBD 社会层 | 提供白皮书降认知门槛 |
| 评估 | 售前 Demo 演示 ★ | 视频会议 | 低（卡在集成演示） | SDT 胜任 | 预制行业 Demo 包 |
| 试用 | 首次配置 | 系统 | 中↓（配置复杂） | SDT 自主 | 一键模板 + 引导 |
| 采购 | 合同审批 ★ | 内部流程 | 低（合规审查慢） | 进化驱动力（停用=合作泡汤） | 预出合规材料包 |
| 实施 | 数据迁移 | 系统/实施团队 | 低（历史数据丢失） | SDT 胜任 | 迁移前校验 + 回滚 |
| 续费 | 使用率报告 ★ | 邮件 | 中（只有销售来才想起） | JTBD 功能层 | 主动健康度月报 |

触点类型清单（填充用）：**人**（销售/客服/实施/对方内部人员）、**系统**（产品/邮件/官网）、**线下**（峰会/合同/审批单）、**文档**（白皮书/合同/使用手册）。每类触点在矩阵里都应有列或标注，避免只写"线上触点"。

## 5. 痛点→机会转换规则（什么算真痛点）

### 5.1 真痛点四判定（缺一不算）

1. **有行为证据**：来源里有可观察的行为（尝试 3 次、打电话投诉、绕过系统走线下），不是"我觉得这个体验不好"。
2. **有停用/放弃威胁**：痛点若不解，角色会转向竞品或中途退出（进化驱动力判据：停用后的"不适"真实存在）。
3. **有量化代价**：能用时间/金钱/人力/错误率量化（"每次审批 3 天""月度对账错 12 笔"）。
4. **非个人偏好**：跨角色或跨来源重复出现（O 类意见至少 2 个独立来源印证），或直接导致决策翻转（MOT）。

### 5.2 机会量化（pmaster 机会评分 + 重要×满意矩阵）

```
机会评分 = 重要性 × (1 − 满意度)     # Dan Olsen 机会评分，归一化 0-1
高重要性 × 低满意度 = 优先补（最关键空白）
高重要性 × 高满意度 = 守成
低重要性 × 任意   = 暂缓
```

每个机会追加 KANO 标签（producrequirementanalyzer）：基本型（缺了流失）/ 期望型（越完善越满意）/ 兴奋型（超预期惊喜）。机会落地形态是**可衡量的改进结果**（"减少 50% 表单填写时长"），不是功能方案（"加个导出按钮"）。

## 6. 完整示例：to B 采购旅程（认知→评估→试用→采购→实施→续费）

**场景**：某制造企业采购一套供应商管理 SaaS。角色：采购总监（业务负责人）、IT 架构师（技术决策）、采购专员（一线使用）、财务（付款干系人）。

**① 角色×阶段矩阵（MECE 网格）**：

| 角色 \ 阶段 | 认知 | 评估 | 试用 | 采购 | 实施 | 续费 |
|---|---|---|---|---|---|---|
| 采购总监 | 关注行业峰会，收集厂商线索 | 要求清单化对比 3 家 | 用真实品类试跑 2 周 | 拍板 + 定预算 | 关注上线进度 | 看年度降本报告 |
| IT 架构师 | —（不参与早期认知） | 评估系统集成与安全合规 | 验证 API 与数据迁移 | 出具技术准入意见 | 主导部署与集成 | 盯版本与运维 |
| 采购专员 | 收到销售白皮书 | 听 Demo，试用 UI | 每日录入，看效率 | 提采购申请走 OA 审批 | 数据迁移与日常操作 | 日活依赖，提改进需求 |
| 财务 | — | 参与报价谈判 | 试算 ROI | 合同与付款审批 | 验收付款 | 核对续费账单 |

> 注意 IT 架构师"认知"格：早期不参与 → 填"未参与"而非空白跳过；财务"认知"同样处理。空格要解释，不许无声留白。

**② 情绪曲线与 MOT**：

```
高 ▏
中 ▏   ★Demo演示         ★合同审批    ★上线首周
低 ▏  认知    评估      试用      采购      实施     续费
      ↗ 峰会认可  →↘ Demo卡集成 →↓ 配置复杂 →↘ 合规慢 →↑ 上线跑通 →↓ 只有销售提醒才想起续费
```

- MOT-1 评估·Demo：IT 架构师发现集成不支持既有 ERP → 情绪由中跌至低，评估结论从"通过"转"待定"（SDT 胜任受挫）。
- MOT-2 采购·合同审批：财务卡合规审查 12 天 → 采购总监情绪低（进化驱动力：停用=整单泡汤）。
- MOT-3 续费·健康报告缺失：使用率 90% 但无人告知价值 → 续费靠销售盯（JTBD 功能层未闭环）。

**③ 触点矩阵 + 痛点→机会**：

| 阶段 | 触点（MOT） | 渠道 | 情绪 | 机会（量化） |
|---|---|---|---|---|
| 认知 | 峰会演讲 | 线下 | 中↑ | 降认知门槛：发行业对标白皮书 |
| 评估 | Demo 演示 ★ | 视频会议 | 低 | 预制 ERP 集成 Demo 包 → 评估周期 6 周 → 3 周 |
| 试用 | 首次配置 ★ | 系统 | 低 | 行业模板一键导入 → 配置时长 -60% |
| 采购 | 合同审批 ★ | OA | 低 | 预出合规材料包 → 审批 12 天 → 5 天 |
| 实施 | 数据迁移 | 系统 | 低 | 迁移前校验+回滚 → 迁移失败回退率 -80% |
| 续费 | 使用率报告 ★ | 邮件 | 中 | 主动健康度月报 → 续费前主动触达率 100% |

每个机会挂 KANO：模板导入=期望型、合规材料包=基本型、健康度月报=兴奋型。

## 7. 工作流程

1. **枚举角色与阶段**：从 `background-goal.md` 取角色枚举；按产品形态选阶段轴（to C 用 AARRR / to B 用采购旅程），MECE 校验阶段互斥+穷举。
2. **建空矩阵**：角色×阶段网格先行，确认网格完整（无缺格、无重复）。
3. **逐格填充**：每格填 行为/触点/情绪，全部挂来源；空白格写原因（"未参与"或 → 进 Clarify）。
4. **标 MOT**：扫全矩阵，用情绪断崖/决策翻转/干系人分叉三判据标 ★。
5. **铺触点矩阵**：按阶段列触点、渠道、情绪、判据来源；补机会列。
6. **痛点→机会**：对每个 MOT 与低情绪点过"真痛点四判定"；合格者用机会评分+KANO 排序成机会清单。
7. **输出**：矩阵 + 情绪曲线图 + 触点矩阵 + 机会清单写入 user-journey.md 对应章节。

## 8. 核心硬规则

1. **先切矩阵再填充**：禁止直接列旅程清单；角色×阶段网格不完整不许填充（thinking-core §3 MECE）。
2. **每格有据**：矩阵每格行为/触点/情绪挂 SRC-*；AI 补全标 `AI_INFERENCE`，空格写原因不静默跳过。
3. **情绪必须有判据**：情绪点标注进化驱动力/JTBD 层/SDT 维来源；无来源的情绪 = 凭空发明，一票否决。
4. **MOT 三判据**：关键时刻必须命中 情绪断崖/决策翻转/干系人分叉 之一，否则不是 MOT。
5. **真痛点四判定**：无行为证据、无停用威胁、无量化解代价、个人偏好的，不算痛点，不进机会清单。
6. **机会可量化**：每个机会是"可衡量的改进结果"并挂 KANO 标签；写成功能方案（"加个按钮"）即不合格。

## 9. 边界（Do Not）

- 不写用户故事卡片或范围基线（→ user-stories）——矩阵停在"旅程客观映射"层。
- 不设计功能清单（→ feature-list）——机会写改进结果，不写功能。
- 不替角色决定"该怎么做"——只记录行为与情绪的客观事实。
- 不因某角色阶段"不重要"就省略网格——空格写原因或进 Clarify，不删行列。
- 不合并不同角色的旅程为一条"标准路径"——角色差异正是 to B 价值所在。
- 不为凑情绪点发明高/低谷——无判据的情绪一律不标。
