# 防冗杂约定（Anti-bloat Conventions）

> 产物结构 ≠ 业务深度。模板字段全填但内容是空骨架，比缺字段更糟糕——PM 拿到产物后会觉得「还不如直接看 PPT」。本目录收容防冗杂的硬规则与改进方向。

## 1. 空骨架红线（CRITICAL 防冗杂）

### 现状

校验器只检查「结构是否完整」——字段在不在、heading 列全不全。但「结构完整 + 内容是占位符」是当前最常见的失败模式：

```
## 目标与成功判断
待补充。

## 角色与干系人
待补充。
```

跑出来的产物形式合规，但 PM 看不到「为什么要做」「做成什么样」。

### 规则

**advisory 级红线**（不阻断，但 CI 红色显眼）：

- **占位符密度 > 30%**：产物正文中 `待确认 / 待补充 / UNKNOWN / TBD / TODO / [空]` 任一占位符数量 / 总有效行数 > 30% 时，发 `uj.bloat_warning` / `bg.bloat_warning` advisory
- **核心章节必须实写**：5 个核心章节（BG：项目背景 / 当前现状 / 核心问题与证据 / 目标与成功判断 / 角色与干系人；UJ：一句话旅程叙事 / 业务生命周期分解 / 角色旅程矩阵 / 路径与情绪 / 触点痛点与机会）中任一章节「占位符行数 / 该章节总行数 > 50%」时，发 `uj.section_hollow_<X>` / `bg.section_hollow_<X>` advisory
- **校验器在 advisory 报告里列出 Top-3 最空章节**：让 PM / AI 知道先补哪

### 不阻断的理由

阻断会逼 AI 写「待确认：客户希望改善预约体验」（实质空），反而破坏「材料不足时如实标 UNKNOWN」的纪律。advisory 只标记、不强迫——把判断权交给 PM。

## 2. 业务假设链（Generate 阶段必带）

### 现状

模板字段填写当前是「直接给结论」，没有暴露「结论怎么来的」：

```
## 核心问题与证据
当前预约流程长且转化率只有 47%（FACT）。
```

PM 看到的是结论，不知道 AI 是从材料直接读出的，还是综合多份材料推断的，还是根据行业经验外推的。

### 规则

Generate 阶段处理「事实 + 解读 + 风险」混合内容时，按下表标注：

| 内容类型 | 标注格式 | 示例 |
|---|---|---|
| 材料直接说出的事实 | `（FACT, 来源: <材料定位>）` | 转化率 47%（FACT, 来源: SRC-002 数据表） |
| AI 归纳的事实链 | `（AI_INFERENCE, 推断链: A→B→C, 风险: <如果 X 反例则结论失效>）` | 高峰时段取消率较高（AI_INFERENCE, 推断链: 高峰时段预约量大→客服响应慢→客户主动取消, 风险: 若实际是客服配置问题则结论失效） |
| 待 PM 决策的事项 | `（DECISION_TBD, 候选: A / B / C, 推荐: <理由>）` | 衡量窗口（DECISION_TBD, 候选: 7 天 / 30 天 / 季度, 推荐: 30 天便于跨周对比） |

### 落点

- BG 的「核心问题与证据 / 目标与成功判断 / 角色与干系人」
- UJ 的「业务生命周期分解 / 角色旅程矩阵 / 路径与情绪」
- 治理伴随文件的「主张来源与知识状态」表（已含六态标签，可直接复用 FACT/AI_INFERENCE 等列）

## 3. 产物分级（待 PM 评审飞书反馈后再落地）

### 现状

模板字段不分场景一律要求填，导致：
- 立项内部讨论：被 11 节结构拖慢，PM 觉得「还不如先开个会」
- 评审外部使用：被「待确认」淹没，反馈「还是 PPT 好懂」

### 拟落地

把产物分成两档，模板与校验器配套：

| 档位 | 用途 | 字段要求 | 校验器策略 |
|---|---|---|---|
| **骨架版（skeleton）** | 立项内部 / 团队对齐 | 主章节占位即可，详细字段「待补充」可接受 | 不阻断；提示「当前为骨架版」 |
| **完整版（ready_for_human_review）** | 评审外部 / 业务确认 | 主章节必须实写，占位符 < 10% | 占位符密度 > 10% 触发 advisory > 30% 阻断 |

frontmatter 加 `version_stage: skeleton | ready_for_human_review` 字段；模板保留两套说明。

### 状态

本约定仅做规划，落地需要：
1. PM 评审飞书反馈章节修订 5（P1-2）+ 盲区 3（lite 链路）后，统一决策
2. 然后改主模板 frontmatter + governance + 校验器

## 4. 与现有约定的关系

- 与 P0-3 lite 注释化互补：lite 模式解决「字段太多」，产物分级解决「同一字段在不同场景下填到什么程度」
- 与 P1-1 三层枚举协议互补：枚举协议给出「标准选项」，假设链给出「用了哪个选项 + 为什么 + 风险」
- 与 cross-cutting-conventions 中「失败回收」互补：失败回收是「跑完后的反馈」，本约定是「跑完前的纪律」

## 5. 维护

- 本目录是「原则集」，不在主模板硬塞——具体落地在 SKILL.md 引用本目录，避免污染产物正文
- 半年内若某条规则无争议，考虑下沉到校验器或主模板
- 反之保留在本目录，供后续讨论
