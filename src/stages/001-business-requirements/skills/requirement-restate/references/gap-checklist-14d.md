# 14 维度缺口扫描清单（Gap Checklist 14D）

> 来源吸收：`juloko` skill（research-to-prd）的 `references/gap-checklist.md`（14 维度遗漏检测清单库），作为 requirement-restate 的可选落地能力。
> 定位：在复述确认之外补一层"结构性遗漏扫描"，用 14 个维度逼出材料里根本没提的缺口，把"感觉写很全"的材料变成"可开工"的需求基线。
> 触发：Intake 后、RR 重述清单定稿前，对源材料逐维度扫描；也适用于多源材料新增时重扫。**按需加载，不设全局闸门**。

## 1. 输入映射（pm-scaffold 语境）

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| 原始素材（文档/听记/截图/聊天） | requirement-restate 的 Intake SRC-* 来源登记 | 扫描对象 |
| 缺口命中 | issue-record 的 Q-XXX（INF）/ ISS-XXX | 每条命中落一条问题或确认项 |
| 素材矛盾 | issue-record 的 CONFLICT（CLS 类别） | 术语/口径不一致路由冲突 |
| 定级 P0/P1/P2 | RR-NNN 的 confidence 与优先级 | 决定澄清顺序 |

> 每条缺口都必须挂 SRC-* 或标 `[推断]`，不得出现无来源的"顺手补一句"。

## 2. 14 维度扫描清单（搬入自 juloko gap-checklist）

每命中一个缺口 → 生成一条清单项（问题/待确认/冲突），并标注所属 PRD 模块。**禁止凭感觉抽查、禁止跳过任一维度。**

### 维度 1：角色与权限（模块 4 角色）
- [ ] 所有提到的角色是否都有明确职责定义？出现但没定义的角色 → Q
- [ ] 每个操作/数据的增删改查权限归属谁？谁不能看？→ Q（常漏"不能看"）
- [ ] 是否存在"代理/临时授权"（某人休假谁替）？→ 待确认
- [ ] 管理员/超级权限如何管控与审计？→ Q
- [ ] 角色是否会随组织调整变化？是否需要角色与人员解耦？→ 待确认

### 维度 2：业务流程完整性（模块 3 流程）
- [ ] **只有正向流程、没有逆向流程？**（撤回/驳回/取消/退款）→ P0，必问
- [ ] 异常/中断流程：审批拒绝后去哪？提交失败怎么处理？→ Q
- [ ] 流程是否有"草稿/暂存/挂起"等非终态？→ Q
- [ ] 跨部门/跨系统交接点是否清晰？谁触发谁？→ Q
- [ ] 流程是否会卡死（某角色不处理就永远挂着）？超时升级机制？→ P1

### 维度 3：业务规则与边界（模块 5 规则）
- [ ] 规则是否转成决策表并做完备性检查（条件组合未穷尽）？→ P0
- [ ] 阈值/边界值归属（≥ 还是 >）？→ 待确认
- [ ] 规则冲突时的优先级/消解顺序？→ P0 冲突
- [ ] 规则是否会变？变更由谁审批、是否需留痕？→ Q

### 维度 4：状态与生命周期（模块 5/状态机）
- [ ] 核心实体（工单/订单/单据）的全部状态是否列全？→ Q
- [ ] 状态×事件矩阵是否有空格（未定义流转）？→ P0
- [ ] 终态是否明确？能否"复活"（已关闭再打开）？→ Q
- [ ] 状态变更是否记录操作人与时间（审计）？→ Q

### 维度 5：数据实体与字段（模块 6 数据）
- [ ] 每个字段是否有口径定义（什么算一条、取值范围）？→ Q
- [ ] 字段数据来源系统？谁维护？→ Q（常漏"来源"）
- [ ] 唯一标识/主键是什么？重复数据如何判定？→ Q
- [ ] 敏感字段（身份证/金额/手机号）如何脱敏与权限控制？→ P1
- [ ] 老系统字段是否全要保留？还是只迁活跃字段？→ 待确认（现状≠需求）

### 维度 6：集成与接口（模块 8 集成）
- [ ] 上游谁产生数据、下游谁消费？接口方式（API/文件/库表）？→ P0
- [ ] 对方系统的负责人/接口文档在哪？→ Q
- [ ] 接口失败/超时/幂等如何处理？→ P1
- [ ] 是否需同步/异步？数据延迟容忍度？→ Q

### 维度 7：存量数据迁移（模块 8/上线）
- [ ] **历史数据迁不迁？迁多少（全量/近 N 年）？** → P0（最常被忘）
- [ ] 存量数据质量差（缺字段/格式乱）怎么清洗？→ Q
- [ ] 新旧编码映射（老 ID→新 ID）谁提供？→ Q
- [ ] 迁移窗口期（能否停机/错峰）？回滚方案？→ Q

### 维度 8：性能与量级（模块 9 非功能）
- [ ] 当前/预期数据量级（日增/峰值并发）？→ P0
- [ ] 响应时间要求（秒级/分钟级）？→ Q
- [ ] 是否有批量/导出场景压测？→ Q
- [ ] 增长预期（1 年/3 年翻几倍）？→ 待确认

### 维度 9：安全与合规（模块 9 非功能）
- [ ] 涉及哪些合规要求（等保/个保法/行业监管）？→ P0
- [ ] 操作是否需留痕/防篡改？→ Q
- [ ] 数据能否导出、导出是否审批？→ Q
- [ ] 越权访问如何防范与告警？→ Q

### 维度 10：异常与容错（模块 9 非功能）
- [ ] 网络/服务中断时用户能做什么？本地缓存？→ Q
- [ ] 输入非法/超长/特殊字符如何处理？→ Q
- [ ] 第三方依赖挂了如何降级？→ Q
- [ ] 错误提示是否给用户可行动指引（不是"系统错误"）？→ P2

### 维度 11：报表与统计（模块 7 报表）
- [ ] 业务方需要哪些看板/报表？给谁看？→ Q
- [ ] 统计口径/维度（按天/人/部门）？→ Q
- [ ] 实时还是 T+1？导出格式？→ 待确认
- [ ] 是否需要预警（指标异常自动提醒）？→ Q

### 维度 12：权限与审计（模块 4/9）
- [ ] 关键操作是否记录"谁+何时+改了什么"？→ Q
- [ ] 审计日志保留多久？谁能查？→ Q
- [ ] 是否需要操作复核/双人确认？→ 待确认

### 维度 13：术语与口径一致性（贯穿）
- [ ] 同一概念不同素材叫法是否统一（如"工单/任务/单子"）？→ 冲突/术语表
- [ ] 关键指标定义是否各方一致（"完成"指什么）？→ 冲突
- [ ] 时间口径（自然日/工作日/时区）是否统一？→ Q

### 维度 14：验收与上线标准（模块 10 验收）
- [ ] 怎么算"做完了"？UAT 由谁在哪验？→ P0
- [ ] 验收用例/场景谁提供？→ Q
- [ ] 上线节奏（灰度/全量）与回滚条件？→ Q
- [ ] 上线后谁来运营/客服/兜底？→ Q

## 3. 扫描后的定级（P0/P1/P2）

| 级别 | 判定标准 | 典型命中 |
|------|---------|---------|
| **P0** | 不答就没法开工 | 核心流程断裂、关键规则缺失/冲突、边界范围不清、存量数据无方案、合规要求未知、验收标准空白 |
| **P1** | 影响方案设计 | 异常分支、权限细则、集成方式、性能量级、安全控制 |
| **P2** | 影响体验细节 | 文案、排序、默认值、提示方式、导出格式 |

> 冲突项优先级恒为 P0。两份素材说法不一致而 PM 没发现，是需求返工头号原因。

## 4. 工作流程

1. **登记来源**：对每份素材登记 SRC-ID（遵循 source-handling 规范）。
2. **逐维扫描**：按 1-14 维度逐条过勾选清单；每命中一条生成一条清单项并标注所属模块。
3. **分类路由**：问题 → Q-XXX（INF）/ issue-record；待确认 → ⚠️ 进待确认清单；冲突 → CONFLICT（CLS）路由仲裁。
4. **定级排序**：按 P0/P1/P2 定级，P0 与冲突项排最前，进入 Clarify 批量提问（≤5 per session）。
5. **重扫收敛**：用户答案回填后重跑扫描——新答案往往会炸出新缺口（正常，非失败）。

## 5. 核心硬规则

1. **禁止凭感觉抽查**：14 维度全部扫过或显式跳过（跳过须说明理由）。
2. **每命中必落一条**：不留"大概没问题"的空泛结论；每条挂 SRC-* 或 `[推断]`。
3. **逆向流程是必查项**：只有正向流程、没有逆向流程（撤回/驳回/取消/退款）按 P0 必问。
4. **冲突恒为 P0**：术语/口径/规则矛盾全部挑出进冲突清单，不自行调和。
5. **现状≠需求**：老系统字段/现有做法只作 AS-IS 背景，是否保留由业务方裁决。
6. **扫出的缺口不在此解决**：只标记与路由，解决权在 stakeholder 与 issue-record。

## 6. 边界（Do Not）

- 不替业务方编造缺失字段、规则、指标或性能数值——命中处标 ❌ 进问题清单。
- 不把行业通用做法当本项目已确认事实写入（必须标 ⚠️ 待确认）。
- 不输出裸 `TBD`——必须编号（Q-XXX / ISS-XXX）并进清单。
- 不把业务方的方案设想直接抄成功能需求（见 fact-ledger 的 W 类处理）。
- 不用本清单替代 requirement-restate 的 verbatim 复述——扫描是补结构性缺口，复述是校准理解。

## 7. 质量自检清单

- [ ] 14 个维度全部扫过或显式跳过（跳过有理由）
- [ ] 每条缺口带 SRC-* 或 `[推断]` 标注，无无来源内容
- [ ] P0/P1/P2 定级完成，P0 与冲突项排最前
- [ ] 冲突项全部标记为 CONFLICT 并路由 issue-record（CLS）
- [ ] 逆向流程（撤回/驳回/取消/退款）已检查
- [ ] 存量迁移、合规要求、验收标准三类高频 P0 已覆盖
- [ ] 无裸 TBD、无编造字段/规则/数值
