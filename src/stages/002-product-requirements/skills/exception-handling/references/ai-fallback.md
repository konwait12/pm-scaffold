# AI 兜底策略技法参考（AI Fallback）

> 来源吸收：`prd-writer`（prd-writter__skillhub）步骤 3.4「异常兜底策略自动建议」（格式异常/低置信/幻觉/安全合规 4 类）+ 模板 ai-prd-template.md §9 兜底与风控，作为 exception-handling 的可选 to AI 落地能力。
> 定位：为 AI/模型类功能的输出失败定义兜底策略——当模型输出格式异常、置信度过低、疑似幻觉或触及安全合规时，系统如何拦截/降级/转人工，形成可验收的 EX-XXX。
> 触发：当异常处理涉及 AI 输出（LLM 返回、模型结果、智能处理）而非传统网络/业务异常时使用。**按需加载，不设全局闸门**。

## 1. 输入映射（pm-scaffold 语境）

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| AI 输出格式定义 | business-rules ai-task-types 输出定义 | 兜底判定的格式基准 |
| 兜底策略建议 | exception-handling 的 EX-XXX 行 | 兜底动作落点 |
| 置信阈值 | business-rules 的 BR-XXX | 低置信判定边界 |
| 人工复核流程 | exception-handling 恢复路径 | 人工 fallback 落点 |
| 用户提示文案 | interaction-rules 的 IX-XXX | 面向用户的兜底反馈 |

> **AI 能力未 confirmed，不写兜底**：以已定义的 AI 任务类型与输出格式为准；检测信号缺失标 `待确认`。

## 2. AI 兜底 4 类（吸收自 prd-writer 步骤 3.4）

每类给「检测信号 / 兜底动作示例 / EX 写法」。

### 2.1 格式异常

- **检测信号**：输出非合法 JSON；字段缺失/类型不符；输出为纯文本但要求结构化；长度越界。
- **兜底动作示例**（吸收自 ai-prd-template §9.1）：
  - `json_mode` 强制结构化输出
  - 正则兜底（提取可解析片段）
  - LLM 二次解析（用第二个调用修正格式）
  - 人工 fallback（解析失败转人工录入）
- **EX 写法**：`EX-0X: 当模型输出 JSON 解析失败（连续 2 次）时 → 展示"解析失败，请重试" → 重试 2 次后转人工处理`

### 2.2 低置信

- **检测信号**：输出置信度低于阈值（如 confidence < 0.9）；触发 `missing_info` 标记；关键字段推断不全。
- **兜底动作示例**（吸收自 ai-prd-template §9.2）：
  - 设定 confidence 阈值，低于即不采信
  - 输出带 `missing_info` 标记交人工补全
  - 默认值 + 明确提示"此字段为 AI 推断，请确认"
- **EX 写法**：`EX-0X: 当评分置信度 < 0.9 时 → 结果标注"低置信"并转人工复核 → 人工确认前不计入最终结果`

### 2.3 幻觉

- **检测信号**：输出包含无来源信息；引用原文与源文档不匹配；事实性内容与已知规则冲突。
- **兜底动作示例**（吸收自 ai-prd-template §9.3）：
  - Prompt 要求"引用原文/给出处"
  - 抽查机制（对关键事实人工抽检）
  - 关键场景限制输出（只允许引用知识库原文）
- **EX 写法**：`EX-0X: 当 AI 摘要引用的文档段落无法匹配时 → 标记该条目为"引用失效" → 抽检清单中移除并提示人工补充`

### 2.4 安全合规

- **检测信号**：输入/输出含敏感个人信息；触发脱敏规则；输出涉法务/合规红线内容。
- **兜底动作示例**（吸收自 ai-prd-template §9.4）：
  - 数据脱敏（手机号/身份证号打码）
  - 敏感信息过滤（输出前拦截）
  - 审计日志（AI 调用与输出留痕可追溯）
- **EX 写法**：`EX-0X: 当输出命中敏感信息规则时 → 自动脱敏后返回 → 并记录审计日志（谁在何时调用了什么）`

## 3. 工作流程

1. **定兜底面**：从 AI 任务类型的输出定义出发，确认四类兜底各覆盖哪些输出环节。
2. **写检测信号**：每个兜底 EX 写可判定触发条件（格式解析失败次数、置信阈值、引用匹配失败、敏感命中）。
3. **选兜底动作**：从兜底动作示例库选（拦截/降级/二次解析/转人工），含重试边界与人工 fallback 条件。
4. **配用户提示**：每个兜底配面向用户的中文提示（interaction-rules 文案规范），不暴露模型内部错误。
5. **定级输出**：按影响定级——涉及金钱/合规/数据落库的兜底为高优先，转人工不可跳过。
6. **挂验收**：每条兜底 EX 可被 acceptance-criteria 消费为失败用例（触发条件可复现）。

## 4. 核心硬规则

1. **四类兜底逐类过**：格式异常/低置信/幻觉/安全合规四类都过一遍，确认哪些真实可能发生，不遗漏安全合规。
2. **检测信号可判定**：置信阈值、失败次数、引用匹配等必须量化，写不出判据的兜底不成立。
3. **兜底动作带边界**：重试次数/间隔、转人工触发条件必须写明；"稍后重试"式无边界兜底不合格。
4. **低置信必须显式**：confidence 低于阈值的结果不得静默采信，必须标记/降级/转人工。
5. **安全合规必留痕**：涉及敏感数据的 AI 调用必须定义脱敏与审计日志，不定义即漏洞。
6. **不暴露模型内部**：用户提示不得出现解析失败/模型错误等技术细节，按 UI 文案规范改写。

## 5. 边界（Do Not）

- 不写实现细节（try-catch、异常类型、超时毫秒数、消息队列）——只定义产品级兜底行为。
- 不替代业务规则——置信阈值本身属 business-rules 判定，EX 引用而非重写。
- 不把通用网络/服务异常混入本技法——本技法只管 AI 输出侧失败。
- 不替技术选型决定 json_mode/正则方案——示例是提示，落地由工程实现。
- 不定义数据脱敏的技术算法——只定义"需要脱敏 + 触发规则 + 留痕要求"。

## 6. 质量自检清单

- [ ] 四类兜底（格式/低置信/幻觉/安全合规）逐类核对覆盖
- [ ] 每条兜底 EX 有可判定的检测信号（阈值/次数/匹配失败/敏感命中）
- [ ] 兜底动作含重试边界与人工 fallback 触发条件
- [ ] 低置信结果无静默采信路径
- [ ] 敏感数据兜底含脱敏 + 审计日志要求
- [ ] 用户提示无模型内部技术细节，符合 UI 文案规范
- [ ] 每条兜底 EX 可被 AC 消费为可复现的失败用例
- [ ] 高影响兜底（金钱/合规/数据落库）均转人工不可跳过
