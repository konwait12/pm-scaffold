# 异常状态与埋点技法参考（Exception and Tracking）

> 本文将相关实践转化为本项目的可选方法，不引入外部运行时依赖。
> 定位：exception-handling 产出的 EX-XXX 与 tracking-plan 产出的埋点文本是权威；本文档提供"异常二分类 + 埋点事件表 + 核心指标"的技法，增强异常覆盖与度量可见性。
> 触发：当异常处理需区分网络/业务异常，或需配套埋点度量时使用。**按需加载，不设全局闸门**。

## 1. 输入映射（pm-scaffold 语境）

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| 异常处理 | exception-handling 的 EX-XXX | 异常分类对象 |
| 状态机 | state-machine 的 STATE-XXX | 业务异常判定 |
| 交互规则 | interaction-rules 的 IX-XXX | 埋点触发动作 |
| 功能模块 | feature-list 的 FEA-XXX / functional-flow | P0 操作节点 |
| 业务规则 | business-rules 的 BR-XXX | 异常判定来源 |

## 2. 异常二分类（吸收自 prd-to-design-doc）

| 类别 | 含义 | 处理 | 追溯 |
|---|---|---|---|
| **网络异常** | 请求超时/断网/服务不可用 | 重试/降级/提示重连 | EX-XXX |
| **业务异常** | 权限不足/状态非法/数据冲突/配额超限/余额不足 | 按状态路由恢复 | EX-XXX, STATE-XXX, BR-XXX |

业务异常须枚举具体模式，不写"等异常"。

## 3. 数据埋点规划表（吸收自 product-design-0to1 Step 6.5）

为 PRD 中每个 P0 操作节点定义关键事件：

| 事件名 | 触发时机 | 关键属性 | 用途 |
|---|---|---|---|
| template_created | M1.1 模板新建成功 | 模板ID, 岗级, 薪酬项数 | 监控 HR 配置活跃度 |
| salary_calc_triggered | M2.1 系统触发计算 | 月份, 员工总数, 异常数 | 监控计算成功率 |
| salary_released | M3.1 HR 触发发放 | 月份, 员工总数, 实发总额 | 监控发放及时性 |
| payslip_viewed | M5.1 员工查看 | 员工ID, 月份 | 监控员工活跃度 |
| payslip_pdf_downloaded | M5.2 PDF 下载 | 员工ID, 月份 | 监控下载频次 |

埋点规则：
- 每个 P0 操作节点至少 1 个事件
- 关键属性必须可统计（避免高基数自由文本）
- "用途"必须明确，不能写"以备后用"

## 4. 核心指标（吸收自 product-design-0to1 Step 6.5）

| 指标类型 | 定义 | 示例 |
|---|---|---|
| 北极星指标 | 唯一核心指标 | 工资发放及时率 = 当月按时发放员工数 / 应发员工数 |
| 健康指标 | 过程监控指标 | 计算异常率、员工查看率、下载频次 |

北极星指标须与 project-background-goal 的 BG-XXX 目标对应，可量化。

## 5. 工作流程

1. **扫异常**：从 EX-XXX 提取，按 §2 网络异常/业务异常二分类，业务异常枚举具体模式。
2. **挂状态/规则**：业务异常追溯 STATE-XXX 与 BR-XXX。
3. **列埋点**：按 §3 为每个 P0 操作节点列埋点事件；每事件标触发时机+关键属性+用途。
4. **挂恢复**：每异常标恢复路径，追溯 EX-XXX，不写"开发处理"。
5. **定指标**：按 §4 定北极星+健康指标，追溯 BG-XXX。

## 6. 核心硬规则

1. **异常二分不混淆**：网络异常与业务异常分开处理；业务异常必须追溯 STATE-XXX/BR-XXX，不写笼统"异常"。
2. **埋点不空挂**：每事件追溯 IX-XXX/STATE-XXX/EX-XXX；关键属性可统计（非高基数自由文本）；"用途"明确，不写"以备后用"。
3. **to B 关键埋点**：审批/改派/资金/权限变更须埋点（合规与审计需要）。
4. **恢复路径显式**：每异常标恢复路径，不写"开发处理"。
5. **北极星唯一且可量化**：只定一个北极星，须有具体数值/公式，追溯 BG-XXX。

## 7. 边界（Do Not）

- 不设计埋点技术实现（SDK/上报协议/数据仓库，超出 PRD-only）。
- 不替代 EX-XXX / tracking-plan 文本——表是聚合视图，文本是权威。
- 不替业务方定埋点指标——交人工确认。
- 不写高基数自由文本属性（如完整评论内容）。

## 8. 质量自检清单

- [ ] 异常按网络/业务二分类，业务异常枚举具体模式追溯 STATE-XXX/BR-XXX
- [ ] 每个 P0 操作节点至少 1 个埋点事件
- [ ] 每事件关键属性可统计（非高基数自由文本），"用途"明确
- [ ] 审批/改派/资金/权限变更有埋点（to B）
- [ ] 每异常标恢复路径，无"开发处理"
- [ ] 北极星唯一且有具体数值/公式，追溯 BG-XXX
- [ ] 无埋点技术实现越界内容
