# 交叉引用一致性检查技法参考（Cross-Reference Check）

> 来源吸收：`product-spec-generator`（product-spec-generator__skillhub）references/prd-selfcheck-consistency.md 一致性自检：字段三元组来源检查 + 引用完整性 + 状态机三元一致性 + 严重级别 P0/P1/P2 与输出格式，作为 validation-rules 的可选落地能力。
> 定位：校验规则产出的 VL-XXX 与字段定义完成后，用"定义/使用/枚举三处对齐 + 交叉引用悬空检查 + 状态机三元一致性"三类检查扫描产物内部冲突，把 P0 阻断项挡在评审前。
> 触发：validation-rules 产物 Draft 完成后、Audit 前，或 PRD 整稿一致性自检时使用。**按需加载，不设全局闸门**。

## 1. 输入映射（pm-scaffold 语境）

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| 模块四关键字段表定义 | validation-rules 字段定义表 | 定义位置 |
| 模块五 FR 引用（筛选项/表格列/表单） | page-design 页面字段 + functional-flow | 使用位置 |
| 枚举取值定义/引用 | validation-rules 枚举值 + state-machine 状态枚举 | 枚举一致性 |
| BR-xx / AC-xx / E0X / FR-xx 引用 | business-rules BR / acceptance-criteria AC / exception-handling EX / feature-list FEA | 引用完整性 |
| 状态机 ↔ 异常 ↔ 规则 | state-machine STATE / exception-handling EX / business-rules BR | 状态机三元 |

> **产物未 Draft，不启动交叉检查**：检查对象是已生成的 VL 表与字段定义；无产物则 STOP，等待 Draft。

## 2. 三类一致性检查（吸收自 prd-selfcheck-consistency.md）

### A. 字段三元组来源检查

对每个关键字段（出现在 ≥2 个模块），核对三元一致：

- **定义位置**：在字段定义表中有定义（含类型/枚举）
- **使用位置**：在页面/表单/表格列中被引用
- **枚举一致性**：定义处枚举与引用处枚举取值完全相同
- 三元任一处缺失或枚举不一致 → 冲突

示例：`customerStatus` 在表单列与弹窗中被引用，但字段定义表未定义 → **P0 字段三元缺口**。

### B. 引用完整性（交叉引用悬空检查）

| 引用类型 | 悬空判定 |
|---|---|
| 每处 `BR-xx` 引用 | 该编号在 business-rules 中必须存在且已归类 |
| 每处 `AC-xx` / 验收引用 | acceptance-criteria 必须存在对应条目 |
| 每处 `EX-0X` 异常引用 | exception-handling 必须存在对应异常方案 |
| 每处 `FEA-xxx` 引用 | feature-list 必须存在该功能 |
| 每处 `VL-xx` 引用 | validation-rules 必须存在该校验 |

引用悬空（引用了不存在的编号）= **P0，必须修复后才能输出**。

### C. 状态机三元一致性

- **状态机**状态全集 ↔ **异常处理**覆盖（每个「卡住/失败」状态都有 EX 兜底）↔ **业务规则**触发条件
- 任一状态机状态在 exception-handling 无对应异常兜底 → **P0 冲突**
- 状态迁移触发条件与 business-rules 不一致 → P1 冲突

### D. 补充检查（吸收自 prd-selfcheck-consistency.md）

- **Mermaid ↔ 文字冲突**：流程图节点/状态与文字规则描述是否一致（状态名 = 状态枚举名）。
- **权限一致性**：权限规则表与操作列权限是否一致；角色定义与操作可见性是否一致。

## 3. 严重级别与处理（吸收自 prd-selfcheck-consistency.md）

| 级别 | 定义 | 处理 |
|------|------|------|
| P0 | 阻断性矛盾：字段无定义却被引用 / 状态机与异常缺口 / 引用悬空 | 必须修复后才能输出 |
| P1 | 明显不一致：枚举取值不符 / 角色与权限错位 | 必须修复，可批注后让用户确认 |
| P2 | 轻微不一致：命名口径差异 / 描述冗余 | 建议修复，不阻塞 |

## 4. 输出格式（吸收自 prd-selfcheck-consistency.md）

```markdown
### 一致性自检
- [x] 无前后矛盾（字段三元/引用完整性/状态机三元/权限均通过）
```

或（发现冲突时）：

```markdown
### 一致性自检
- [!][P0] 字段三元缺口：customerStatus 在页面列与表单中引用，但字段定义表未定义 → 补定义
- [!][P0] 引用悬空：页面 X 引用 BR-07，business-rules 无 BR-07 → 补 BR 或修正引用
- [!][P1] 状态机缺口：状态「已取消」在状态机存在，但 exception-handling 未覆盖其卡住场景 → 补 EX
- [!][P2] 命名口径：定义表称「客户状态」，页面称「客户进度」→ 统一为「客户状态」
```

## 5. 工作流程

1. **收对象**：收集 validation-rules 产物 + 上游引用点（页面字段引用、BR/AC/EX/FEA 编号）。
2. **过 A 字段三元**：对每个 ≥2 处出现的字段核对定义/使用/枚举。
3. **过 B 引用完整性**：扫描所有 `BR-xx`/`AC-xx`/`EX-0X`/`FEA-xxx`/`VL-xx` 引用，查悬空。
4. **过 C 状态机三元**：状态全集 ↔ 异常覆盖 ↔ 规则触发逐项比对。
5. **过 D 补充项**：Mermaid 与文字、权限规则与操作列。
6. **定级输出**：按 P0/P1/P2 定级并输出报告块；P0 必须修复（补定义/修正引用/补 EX），闭环前不进入 Human Gate。

## 6. 核心硬规则

1. **P0 必须修复后才输出**：字段三元缺口、引用悬空、状态机缺口三类 P0 冲突，闭环前不得交付。
2. **引用不悬空**：每一个 `BR-xx`/`AC-xx`/`EX-0X`/`FEA-xxx`/`VL-xx` 引用必须真实存在对应编号。
3. **枚举三处完全一致**：定义处与引用处枚举取值必须逐值相同，一值不符即冲突。
4. **状态机三元闭环**：状态 → 异常兜底 → 规则触发三者互相覆盖，任一状态缺 EX 即 P0。
5. **冲突不删内容**：发现冲突必须给出修复建议与严重级别，不能直接删内容规避。
6. **修复闭环后重验**：修复动作完成后重跑全部检查项，不以"修了这条"替代全量重扫。

## 7. 边界（Do Not）

- 不做内容质量评审（文案好坏、规则合理性）——本技法只查引用一致性与悬空。
- 不替上游补规则——发现引用悬空时标 `待确认` 问上游，不在 validation-rules 私造 BR/AC。
- 不检查测试用例/断言脚本（属 QA）。
- 不把命名口径差异当装饰性 P2 忽略——P1 口径冲突须修复或批注确认。
- 不检查字段类型技术细节（string/int）——只查定义/使用/枚举三处对齐。

## 8. 质量自检清单

- [ ] 每个 ≥2 处出现的字段通过定义/使用/枚举三元核对
- [ ] 所有 BR/AC/EX/FEA/VL 引用均有对应编号，无悬空
- [ ] 状态机状态全集 ↔ 异常覆盖 ↔ 规则触发三元闭环
- [ ] Mermaid 图与文字规则一致，无状态名冲突
- [ ] 权限规则表与操作列权限一致
- [ ] P0 冲突已全部修复，P1 已修复或批注待确认
- [ ] 修复后已重跑全量检查，输出一致性自检报告块
