# Audit Checklist · ux-flow

自查对象：父制品 `product-ux.md` 的 `## 3. UX 流程与交互规则` 章节（§3.1 主流程 + §3.2 分支与状态）。
自查时机：Generate 完成后、提交人工评审前。逐项勾选，存在未通过项需先修复或挂起并说明。

## 1. Structural Gate（结构门）

- [ ] 父制品中存在 `## 3. UX 流程与交互规则` 章节，标题带编号前缀（`## 3.`）被 `_norm` 归一化后仍可匹配。
- [ ] 章节中至少存在一个 `FEA-XXX` 标识符；每个 P0 功能均有对应的流程图。
- [ ] 每个流程图内嵌 `FEA-XXX` 与 `ST-XXX` 引用，能回溯到上游功能与故事。
- [ ] Mermaid 代码块语法正确（` ```mermaid `），渲染无报错。
- [ ] 流程图标题/编号与功能清单（§2.2）中的 `FEA-XXX` 一一对应，无孤儿 FEA、无重复编号。

## 2. Content Gate（内容门）

- [ ] 每个 P0 FEA 至少有 1 张 Mermaid 流程图，覆盖入口 → 步骤 → 决策 → 出口。
- [ ] 每个流程至少包含 1 个错误/空/加载状态分支（error / empty / loading）。
- [ ] 分支路径均标注条件（decision branch labels），避免无标签的裸箭头。
- [ ] 主流程、备选流程（alternate）、失败流程（failure）均已绘制，不遗漏。
- [ ] 存在多个入口的 FEA，已按入口分别绘制或明确合并说明。
- [ ] 跨系统/跨模块交接（handoff）在图中有节点或说明性标注。
- [ ] 超时、取消、恢复（timeout / cancellation / recovery）等关键状态已覆盖。
- [ ] 图内文字与功能清单、故事原文、页面名称一致，无自造术语。

## 3. Boundary Gate（边界门）

- [ ] 未泄漏 `IX-XXX` 交互规则细节（交互规则归 interaction-rules 子技能）。
- [ ] 未包含 `BR` / `VL` / `AC` 等业务规则、权限校验、验收标准（归 function-description）。
- [ ] 未包含页面布局、视觉样式、组件级设计（归 page-design）。
- [ ] 未包含模块边界划分、系统架构、API 或数据库设计决策。
- [ ] 未把下游功能/规则问题擅自定稿；涉及范围变更时仅标记为待确认。
- [ ] 图只是流程表达，不承担原型职责；如需可视化原型，明确标注为可选沟通辅助。

## 4. Semantic Gate（语义门）

- [ ] 流程中的关键事实、决定使用知识状态标签（`FACT` / `DECISION` / `AI_INFERENCE` / `UNKNOWN`）。
- [ ] 基于推断生成的步骤或分支（`AI_INFERENCE`）已单独标识，未与确认事实混淆。
- [ ] 每个流程可追溯到上游故事/旅程；不存在无法回溯的上游补充内容。
- [ ] 新出现的分支、状态、出口均能与上游确认范围或功能清单对应。
- [ ] 对下游的输入摘要（§10 下游输入摘要）与本图产出一致，无遗漏交接项。

## 5. Quality Lenses

- 第一性原理：删掉某个流程分支后，功能主路径是否仍成立？该分支是否只是"为了像完整"而加的？
- 系统思考：跨系统交接、角色交接、外部依赖是否被考虑？哪些已经有效、不能破坏？
- 对抗性审查：至少为每条关键分支构造一个反例（条件不满足时用户去哪），验证其互斥且可穷举。
- 逆向验证：从出口状态反推，前置步骤是否足够支撑该出口？
- 最小充分：图包含下游需要的步骤/分支/状态，且不包含布局、规则与实现细节。

## 6. Requirement Quality Gate（29148 特化）

每个分支条件、状态、出口按单条需求的九特征抽查：可验证（条件可写判据）、无歧义（两个读者理解一致）、单一（一个分支一条判定）、必要（删掉会丢功能路径）。分支条件不可验证（如"视情况而定"）为阻断项：要么量化，要么 `needs_user_input`。

## 7. Human Gate（人工门）

- [ ] 涉及范围、分支取舍、跨系统交接等影响决策的项已整理为待确认问题，未被 AI 擅自定稿。
- [ ] 存在多个可选分支/方案时，未自行代用户选择，已标出等待产品负责人确认。
- [ ] 已运行 `validate_artifact.py` 且输出 PASS（或已列出并说明未通过项）。
- [ ] 本人（AI 作者）可脱离上下文独立讲解每张图的主/备/错路径。
- [ ] 提交人工评审后，产品确认流程完整、分支真实；业务确认出口/交接符合目标。

## Audit Report Shape

```text
status_recommendation
passed_checks
failed_checks
repairs_applied
blocking_questions
nonblocking_unknowns
decisions_required
traceability_gaps        # 无 ST/FEA 追溯的步骤
downstream_risks         # 对 page-design / interaction-rules 的影响
```

若以上任一项未通过，先修复；无法自行决断的项进入 `## 8. 待确认问题`，标注阻断状态后交人工评审。
