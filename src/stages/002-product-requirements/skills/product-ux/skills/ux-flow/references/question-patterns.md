# Question Patterns · ux-flow

八种 Clarify 提问模板（一次一问的澄清循环）。每条给出：**何时用 / 问句骨架 / 三个示例 / 常见陷阱**。

---

## 1. 入口（Entry）

**何时用**：某 FEA 的入口不完整，或只写了站内单一入口，无法确认外部渠道。

**问句骨架**：
```
[为什么重要] 入口遗漏会让部分用户路径完全没有流程表达。
当前 §3.1 只画了 [已有入口]。请确认: 用户还能从 [外部链接 / 深链 / 推送 / 分享] 进入此功能吗?
```

**示例**：
- "预约入口只在首页吗？用户从分享链接点进来，应该走哪条路径？"
- "推送通知点开是直达填写页，还是先到列表页？请确认直达入口是否存在。"
- "这个功能在微信/小程序里是从公众号菜单进入吗？还是只有 App 内入口？"

**常见陷阱**：默认单一入口；把"理论上不存在"当"确认不存在"；入口列了却不说合并策略。

---

## 2. 步骤粒度（Step Granularity）

**何时用**：流程图把复合动作压成一步（如"填写并提交"），中间过程被隐藏。

**问句骨架**：
```
[为什么重要] 步骤被压缩后，下游无法据图实现。
当前把 [动作] 画成一步。请确认中间是否有 [确认 / 校验 / 二次提交] 环节?
```

**示例**：
- ""填写并提交"中间，是否需要先预览再确认？还是提交即完成？"
- "选完时段后是直接进入表单，还是先弹确认框再进？"
- "支付完成后是立即显示结果页，还是需要等异步回调？"

**常见陷阱**：把"用户以为的一步"当"系统实际的一步"；漏掉异步/等待步骤；把校验细节也画进图（应归 BR）。

---

## 3. 分支条件（Branch Condition）

**何时用**：分支无标签，或条件重叠、不穷举。

**问句骨架**：
```
[为什么重要] 分支条件不明确，图面"看起来全"实则不可执行。
当前分支 [分支位置]。请明确: 判定条件是什么？除了 [已有情况]，还有第三种可能吗?
```

**示例**：
- ""名额满"和"可预约"之外，是否还有"已截止""已取消"状态？它们走向哪里？"
- "登录判断放在哪个节点？未登录用户是回跳还是留在当前页？"
- "分支条件'剩余时段不足'的具体阈值是多少？不足一个还是不足全部？"

**常见陷阱**：裸箭头；两个条件可同时命中；漏掉第三种状态；用"视情况"代替具体条件。

---

## 4. 状态覆盖（State Coverage）

**何时用**：只有成功路径，error / empty / loading / timeout / cancel 状态缺失。

**问句骨架**：
```
[为什么重要] 状态缺失时，开发只能靠猜，测试无法写用例。
当前图只有 [成功路径]。请确认: 加载中 / 无数据 / 失败 / 超时 各显示什么、回退到哪?
```

**示例**：
- "列表页加载中显示什么？接口超时（如 5s）后用户看到什么？"
- "空态文案和引导是什么？比如'暂无可用场地'下面要不要放'查看其他日期'？"
- "用户中途取消或返回，数据保存吗？下次进入是恢复还是重填？"

**常见陷阱**：只画主路径；把状态说明当脚注；状态去向不明（回退目标悬空）。

---

## 5. 交接（Handoff）

**何时用**：流程跨越系统/模块边界，交接点、输出数据、失败回退不明确。

**问句骨架**：
```
[为什么重要] 交接点失败处理不明确，下游会误以为交接必成功。
当前节点 [节点] 跨越 [系统A]→[系统B]。请确认: 失败时回退到哪? 由哪个系统兜底?
```

**示例**：
- "下单走第三方支付，支付失败是回本页重试，还是跳收银台？谁负责记录失败？"
- "与库存系统交接时，扣减失败如何处理？用户看到的提示由谁定义？"
- "这个交接是同步还是异步？异步时用户等待页的状态是谁的职责？"

**常见陷阱**：把交接画成普通节点；不标失败回退；把系统职责边界擅自拍板。

---

## 6. 出口（Exit）

**何时用**：流程终点不明确，或多个出口没有说清用户去哪。

**问句骨架**：
```
[为什么重要] 出口悬空会导致"流程结束了但用户不知道下一步"。
当前流程结束于 [终点]。请确认: 完成后用户被带往 [回首页 / 看结果 / 去下一任务]?
```

**示例**：
- "预约成功后是停在成功页，还是 3 秒后自动跳回列表？"
- "流程完成后用户是否需要返回发起入口？（如从订单详情进来，结束后回订单详情）"
- "异常终止后是否保留部分输入？下次进入从哪继续？"

**常见陷阱**：只画终止节点不写去向；出口与入口路径不对称；忽略"保存草稿"继续场景。

---

## 7. 范围归属（FEA Membership）

**何时用**：某个流程不知道该归哪个 FEA，或疑似属于相邻功能的流程。

**问句骨架**：
```
[为什么重要] 流程归属不清会造成与相邻功能重复或遗漏。
当前流程 [流程] 疑似跨越 [FEA-A] 与 [FEA-B]。请确认: 主归属是哪个? 边界在哪?
```

**示例**：
- ""查看历史订单"该属于订单查询还是订单管理？两者是同一 FEA 吗？"
- "这个分支引出的页面是否属于另一个 P1 功能？本期要不要画全？"
- "与客服工单相关的流程是本期范围吗？还是属于另一条产品线？"

**常见陷阱**：把相邻功能的流程画进来（范围蔓延）；或该画的没画（遗漏）；边界由 AI 拍板而非确认。

---

## 8. 优先级（Priority）

**何时用**：流程涉及多个入口/分支，但哪个是 P0 主路径不明确。

**问句骨架**：
```
[为什么重要] P0 主路径决定 MVP 范围。
当前有 [入口A / 入口B]。请确认: MVP 必须打通的是哪条? 其余是 P1/P2 备选吗?
```

**示例**：
- "桌面端和移动端入口，MVP 是否只需打通移动端？"
- "第三方登录流程是 P0 吗？还是可以先只做手机号登录？"
- "异常重试路径是否影响验收？MVP 可接受的降级是什么？"

**常见陷阱**：把 P1 路径画成主路径；MVP 主路径含依赖未就绪的分支；优先级由 AI 猜。

---

## 通用建议

1. **一次只问一个**，按 Impact × Uncertainty 排序，先问阻断分支/入口的。
2. **不要问 AI 能查的事实**（平台规范、常见 UX 惯例）——自己查。
3. **每问必带 AI 初步判断**，让产品从选项里选而不是从零想。
4. **给 2-4 个互斥选项 +「其他」兜底**。
5. **回写位置必填**：每答一题必须能指向 §3.1 / §3.2 的具体图或节点。
