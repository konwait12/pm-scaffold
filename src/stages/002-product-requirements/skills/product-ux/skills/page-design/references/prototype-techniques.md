# 可点击原型技法参考（Prototype Techniques）

> 来源吸收：Trae `interactive-demo-factory` 与 `flow2demo` 两个 skill 的成熟技法，经适配后作为 page-design 的可选落地能力。
> 定位：page-design 产出页面骨架文本（§4 表格）是权威；本文档提供"把页面骨架转成可点击 HTML 原型"的技法，原型是 UX 的落地产物（UX 与原型一体），不是替代文本规则。
> 触发：当 P0 功能流程 ≥ 3 页、或涉及状态分支、或需要利益相关方评审视觉/交互时，生成可点击原型。

## 1. 输入与保真度

| 输入 | 必需 | 可接受格式 | 对产出的影响 |
|---|---|---|---|
| 页面清单 | ✅ | TXT / JSON / MD 列表 / Mermaid 节点 | 定义页面节点（page-design §4 表格可直接提供） |
| 流程描述 | ✅ | Mermaid / ASCII / 纯文本 / PDF / 图片 | 添加决策分支、状态机、跳转边 |
| UI 参考图 | ⭕ | PNG / JPG / Sketch / Figma 截图 | 升级为高保真布局 |
| 设计 token | ⭕ | CSS / JSON / Tailwind config | 覆盖默认品牌 |

保真度阶梯：仅页面清单 → 逻辑原型（低保真）；+流程 → 中保真（逻辑 100% 准确、占位 UI）；+UI 图 → 高保真。

## 2. 核心硬规则

1. **忠于输入，不发明状态**：分支目的地必须在页面清单中存在；若流程分支指向不存在的页面 → 停下来向人工报告，不静默补页面。
2. **多入口必须有演示入口页**：当存在多个起始页面（A/B/C/D）时，默认先做"演示入口"页，把各起始路径做成卡片，点击卡片进入对应起始页；不依赖侧边栏作为主路径。
3. **状态依赖目标页必须弹状态确认**：当点击结果取决于业务状态（已登录/未登录、已关注/未关注、已支付/未支付、权限角色、功能开关）时，用户点击真实入口后先弹"状态确认"弹窗，由演示者选择状态，再跳到对应目标页。弹窗选项用业务语言命名（如"已关注：基础页面 / 未关注：基础页面 + 关注模块"）。
4. **演示优先，不出现开发面板**：主 demo UI 中不出现右侧 AI 规则面板、调试面板、资源说明卡、路由表；AI 可读的规则、跳转矩阵、决策逻辑放在配套文档（如交互材料），不放进演示页。
5. **真实元素可点击**：页面内的真实元素（弹窗 CTA、账户行、通知卡）可点击驱动跳转，不只有侧边栏可点。

## 3. 交付物结构

```text
prototype/
├── index.html            # 可点击 demo（自包含单文件，含 CSS）
├── assets/               # 裁剪后的语义图片（复杂照片/品牌视觉用，普通 UI 用 HTML/CSS 重建）
├── demo-flow.md          # 交互材料：页面清单、入口跳转逻辑、页面跳转矩阵、状态判定
└── render-check.png      # 浏览器渲染验证截图（验证无空白页、文本不重叠、状态弹窗正常）
```

交互材料（demo-flow.md）建议结构：
- §1 页面与素材清单（与 page-design §4 表格一致，不发明页面）
- §2 总体入口跳转逻辑
- §3 核心页面状态判断（各状态 → 目标页）
- §4 分入口流程说明
- §5 页面跳转矩阵（从 → 到 → 触发动作 → 条件）
- §6 后续 HTML/原型建议

## 4. 生成与验证流程

1. **解析输入**：从 page-design §4 提取页面清单；从 ux-flow Mermaid 提取决策点（菱形）与分支；冲突（分支指向不存在页面）先报告。
2. **构建页面图**：`pages[]` 数组，每页含 id、name、category（entry/auth/detail/success/error）、所属 FEA。
3. **重建 HTML**：不要用整页截图当背景图；导航、文本、卡片、按钮、列表用 HTML/CSS 重建；复杂图片（照片/地图/插画/品牌视觉）才用裁剪图。
4. **连接点击**：真实元素可点击；状态依赖目标页先弹确认弹窗；多入口有演示入口页。
5. **验证迭代**：浏览器渲染检查——无空白页、资源加载、文本不重叠、长页面可见、状态路由先问状态、多起始路径可发现、无调试面板。
6. **回报假设**：报告任何未达目标的区域与假设，交人工确认。

## 5. 边界（Do Not）

- 不生成生产代码（无真实数据库/后端调用）。
- 不替代 page-design §4 文本规则——原型是沟通工具，文本规则是权威。
- 不替业务方选择默认状态——状态依赖必须弹窗询问或显式标注 `待确认`。
- 视觉细节（动效、配色微调）不是本步骤目标，除非人工明确要求高保真。

## 6. 质量自检清单

- [ ] 页面清单与 page-design §4 一一对应，无发明页面
- [ ] 每个分支目的地存在于页面清单
- [ ] 多入口项目有演示入口页
- [ ] 状态依赖目标页弹状态确认弹窗（业务语言命名）
- [ ] 主 demo 无调试/规则/路由面板
- [ ] 页面内真实元素可点击（不只侧边栏）
- [ ] 浏览器验证截图无空白页、无文本重叠
- [ ] 原型路径与 PRD 中引用的版本一致
