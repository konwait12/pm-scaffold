# AI 模型评估维度技法参考（AI Eval Dimensions）

> 来源吸收：`prd-writer`（prd-writter__skillhub）步骤 3.2「模型评估指标自动生成」（准确性/完整性/稳定性/幻觉率 4 维度）+ 模板 ai-prd-template.md §7 数据与评估体系（评测集 + 评估维度与验收标准表），作为 acceptance-criteria 的可选 to AI 落地能力。
> 定位：为 AI/模型类功能的验收标准提供 4 个评估维度、评测集设计与可测验收判据写法——让"模型表现达标"从感觉变为可复现的 AC-XXX。
> 触发：当验收标准涉及 AI 输出质量（准确率、抽取完整性、生成稳定性、幻觉率）而非传统功能验收时使用。**按需加载，不设全局闸门**。

## 2. AI 模型评估 4 维度（吸收自 prd-writer 步骤 3.2）

每个 AI 功能须在以下 4 维度中选取适用项定义评估方法与验收标准（模板吸收自 ai-prd-template §7.2）：

| 维度 | 评估方法 | 验收标准 |
|------|----------|----------|
| **准确性** | 评测集标注对比：模型输出 vs 人工标注结果 | 正确率 ≥ 阈值（如 ≥ 0.9）；分类 F1 ≥ 0.85 |
| **完整性** | 目标字段/要素覆盖度：应有输出 vs 实际输出 | 字段召回率 ≥ 阈值；关键字段 100% 覆盖 |
| **稳定性** | 同一输入多次调用输出一致性；不同时段波动 | 输出一致率 ≥ 阈值；低置信率 ≤ 阈值 |
| **幻觉率** | 无来源/引用失效信息占比；抽检确认 | 幻觉率 ≤ 阈值（如 ≤ 2%）；抽检通过率 ≥ 阈值 |

### 2.1 各任务类型评估侧重（对接 ai-task-types）

| 任务类型 | 侧重维度 |
|---|---|
| 分类 | 准确性（F1/准确率）、稳定性（同输入同类别） |
| 抽取 | 完整性（字段召回）、准确性（字段正确） |
| 生成 | 完整性（要素齐全）、幻觉率（无杜撰内容） |
| 推理 | 准确性（结论正确）、幻觉率（依据可追溯） |
| RAG | 幻觉率（引用忠实）、准确性（答案正确） |
| Agent | 稳定性（任务完成率）、完整性（步数覆盖） |

## 3. 评测集设计（吸收自 ai-prd-template §7.1）

```
- 样本规模：{最少样本数，如 ≥200 条覆盖全类别}
- 来源：{真实业务数据抽样 / 构造用例 / 历史沉淀}
- 标注要求：{人工标注口径，双人标注 + 仲裁}
- 分布要求：{正常/边界/异常/对抗用例占比}
```

### 3.1 评估用例设计（4 类）

| 用例类型 | 内容 | 用途 |
|---|---|---|
| 正常用例 | 覆盖主路径的典型输入 | 测准确性基线 |
| 边界用例 | 空值/极值/超长/特殊字符 | 测鲁棒性 |
| 异常用例 | 输入缺失、格式错误、上下文超限 | 测兜底触发 |
| 对抗用例 | 含误导/歧义/越权诱导 | 测幻觉与安全 |

每个用例记录：输入 → 期望输出 → 判定标准（通过/失败），作为 AC 的可复现样本。

## 4. 验收判据写法（对接 AC-XXX）

### 4.1 判据结构（Given/When/Then + 量化阈值）

```
AC-0X: 给定评测集 E-01（≥200 条含四类分布），当对 AI 分类功能运行全部用例时，
     则 分类准确率 ≥ 0.90，且幻觉率 ≤ 2%
```

### 4.2 可验证对比（吸收自 prd-writer 验收标准生成规则）

- ❌ 模糊：「AI 回答要准确」「抽取要完整」
- ✅ 可验证：「评测集上抽取字段召回率 ≥ 0.95」「分类准确率 ≥ 0.90，置信度 < 0.6 的样本须转人工」

### 4.3 示例：简历打分 AI（吸收自 prd-writer 示例 2）

- 准确性：`Given 评测集 200 份简历（含人工评分），when 运行打分，then 与人工评分一致率 ≥ 0.85`
- 完整性：`when 抽取"工作经历/技能/教育背景"三字段，then 字段覆盖率 = 100%`
- 稳定性：`Given 同一简历重复调用 5 次，then 输出分数波动 ≤ 5 分`
- 幻觉率：`Given 抽取结果抽检 50 条，then 无来源字段 ≤ 2 条（幻觉率 ≤ 4%）`

## 5. 工作流程

1. **定任务类型侧重**：从 ai-task-types 确定本 AI 功能评估侧重维度。
2. **设计评测集**：样本规模/来源/标注要求/分布，缺失标 `待确认`。
3. **设计 4 类用例**：正常/边界/异常/对抗各若干条，每条带期望输出。
4. **写评估表**：按 4 维度表填评估方法与验收标准，阈值量化。
5. **落 AC-XXX**：用 Given/When/Then 写验收判据，追溯评测集编号与 G-XXX。
6. **闭环核对**：每个维度阈值可测（构造输入可判定通过/失败），幻觉率必有抽检机制。

## 6. 核心硬规则

1. **阈值必量化**：准确率/召回率/幻觉率/一致率必须给数值（≥0.90、≤2%），"高/准/稳定"一律不合格。
2. **评测集必有**：每个 AI 验收 AC 必须挂评测集（样本规模/来源/分布），无样本的阈值不可复现。
3. **四维度按需选用但幻觉率必评估**：涉及生成/推理/RAG 的输出必须有幻觉率维度与抽检机制。
4. **用例四类齐全**：正常/边界/异常/对抗四类用例缺一不可——只测正常路径是评估最大漏洞。
5. **判据可判定**：每条 AC 用 Given/When/Then + 可量化结果，任何人可仅凭构造输入判定通过/失败。
6. **阈值可溯源**：阈值追溯到已确认 G-XXX / 业务目标；AI 推断的阈值标 `AI_INFERENCE` 交人工拍板。

## 7. 边界（Do Not）

- 不写可执行测试脚本/断言代码（属 QA）——只写可测的验收判据。
- 不指定模型/参数/评测工具（属工程方案）。
- 不替标注团队决定标注口径——标注规则缺失标 `待确认`。
- 不把四维度套成空表——不适用维度说明原因，不写 `待评估` 占位。
- 不在 AC 中复述模型内部行为（token/温度）——只评估可观察输出。
