# 交互流程五段式技法参考（Flow Five Stage）

> 来源吸收：Trae `prd-development` skill 阶段六「界面和交互说明」的页面结构 + 交互流程五段式模板，作为 interaction-rules 的可选落地能力。
> 定位：interaction-rules 产出的 IX-XXX 交互规则文本是权威；本文档提供"把每个操作的完整执行流程按五段式结构化"的技法，增强异常与边界覆盖度。
> 触发：当 IX-XXX 涉及状态依赖、异步处理、多方审批或需完整异常覆盖时使用。**按需加载，不设全局闸门**。

## 2. 页面结构（吸收自 prd-development 阶段六）

交互流程前先描述页面组成（视觉样式以 page-design 为准，此处只描述结构与布局）：

- **整体布局**：页面主要结构（顶部操作区+内容区、左侧导航+右侧内容、多 Tab 切换等）
- **区块划分**：页面拆分哪几个区块，每区块展示什么
- **区块关系**：哪些区块联动（如过滤区条件影响下方数据区）
- **默认状态**：首次加载时各区块初始展示状态

## 3. 交互流程五段式模板（吸收自 prd-development）

每个操作按以下结构描述：

```
操作名称
  触发：[用户做什么触发这个操作]
  执行中：[进行中的 UI 状态，如按钮 disabled、显示 loading]
  成功：[成功后的结果和页面变化]
  失败：[失败后的提示方式和可恢复操作]
  边界条件：[特殊输入或状态下的处理，如空值、超长、无权限]
```

| 段 | 内容 | 必填 |
|---|---|---|
| **触发** | 用户动作/系统事件触发交互的前置（点击/超时/状态变更/定时任务） | ✅ |
| **执行中** | 交互处理过程的中间态（loading/校验中/审批中/进度） | ✅ |
| **成功** | 交互成功后的结果与去向（跳转 PD-XXX / 状态转 STATE-XXX / 数据刷新） | ✅ |
| **失败** | 交互失败的模式与恢复路径（追溯 EX-XXX） | ✅ |
| **边界条件** | 权限/配额/并发/超时/空值/超长的特殊判定（追溯 BR-XXX） | ✅ |

## 4. 完整示例（提交评论操作）

```
提交评论
  触发：用户在评论输入框填写内容后点击"发布"按钮
  执行中：按钮置灰 disabled，显示"发布中..."loading，禁止重复点击
  成功：评论插入列表顶部，输入框清空，显示"评论发布成功"toast（2 秒消失）；
       评论状态转为"待审核"（追溯 STATE-XXX）
  失败：
    - 网络异常：显示"网络异常，请重试"，保留输入内容，按钮恢复可点
    - 内容为空：显示"评论内容不能为空"，按钮恢复
    - 图片超限：显示"图片不能超过 5MB"，保留已选图片
  边界条件：
    - 未登录：跳转登录页，登录后回跳并保留草稿
    - 内容被关闭评论：显示"该内容已关闭评论"（追溯 BR-XXX）
    - 频次限制：显示"评论过于频繁，请稍后再试"（追溯 BR-XXX）
```

## 5. 工作流程

1. **读交互规则**：从 IX-XXX 提取触发动作、处理逻辑、结果去向。
2. **描述页面结构**：整体布局+区块划分+区块关系+默认状态。
3. **拆五段**：按触发→执行中→成功→失败→边界条件填充；缺失段标 `待确认`。
4. **挂状态/异常**：成功段追溯 STATE-XXX；失败段每条模式追溯 EX-XXX；边界段追溯 BR-XXX。
5. **输出五段表**：在 IX-XXX 产物中以五段式结构呈现。

## 6. 核心硬规则

1. **五段缺一不可**：触发/执行中/成功/失败/边界条件必须齐全；失败段不得省略。
2. **失败段必须枚举模式**：每个操作至少列网络异常/权限不足/数据冲突/超时等失败模式及恢复路径，追溯 EX-XXX；无 EX-XXX 标 `待确认`，不写"开发处理"。
3. **成功段去向明确**：必须给出跳转 PD-XXX 或状态转 STATE-XXX 或数据刷新，无悬空去向。
4. **执行中段标注中间态**：长耗时/异步交互须标注中间态反馈（loading/进度/待审批），不阻塞无反馈。
5. **边界条件覆盖 to B 特有**：权限角色差异（RBAC）、多租户隔离、审批流并发、配额上限、空值/超长/超时必须显式列出，追溯 BR-XXX。

## 7. 边界（Do Not）

- 不设计动效/视觉细节（属 page-design 视觉层，样式以 page-design 为准）。
- 不替代 IX-XXX 文本规则——五段式是结构化增强，规则文本是权威。
- 不替业务方决定审批层级——以 BR-XXX 为准，存疑标 `待确认`。
- 不发明 EX-XXX 之外的异常——失败模式须追溯 exception-handling。
- 不写可执行的测试断言（超出 PRD-only）。

- [ ] 成功段去向为 PD-XXX / STATE-XXX / 数据刷新，无悬空
