# 架构图绘制技法参考（Architecture Diagram Craft）

> 来源吸收：`arch-diagram-pro`（arch-diagram-pro__skillhub）SKILL.md 的模块组成图/产品全景图分区结构、自适应布局引擎、8 项自校验、反模式与信息密度原则（吸收"产品范畴"部分，不吸收技术架构图与 HTML 模板），作为 page-design 的可选落地能力。
> 定位：page-design 需要向干系人表达产品模块组成、能力全景或功能分区时，用高信息密度的分区图结构组织内容——让"这个系统有哪些模块、各模块能力是什么、模块间如何流转"一眼可见。
> 触发：当页面/模块组成复杂（≥5 个模块）、需要利益相关方评审产品范畴或汇报产品全景时使用。**按需加载，不设全局闸门**。

## 1. 输入映射（pm-scaffold 语境）

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| 系统名称/主题 | feature-list 的 FEA-XXX 范围 | 图的主题 |
| 模块列表 | feature-list 功能清单/模块 | 模块卡片来源 |
| 模块能力描述 | page-design 页面内容区块 | 卡片列表项 |
| 流程走向 | functional-flow 主流程 | 流程带节点 |
| 指标/关键数值 | feature-list 优先级 / 里程碑 | 指标区数据 |

> **功能未 confirmed，不画全景**：模块与能力以已确认的 FEA-XXX 为准；推断模块标注 `AI_INFERENCE` 交人工核对。

## 2. 模块组成图分区结构（吸收自 arch-diagram-pro 布局结构）

```
[顶部标题带 - 深蓝背景，白色文字：系统名 + 副标题]
    ↓
[特征徽章横排：关键属性标签（如 "PC 管理后台" "多租户" "审批流"）]
    ↓
[模块卡片网格 - 2~4 列]
    ↓
[可选：流程带 - 深蓝背景，白色节点：核心流转方向]
    ↓
[可选：指标区 - 浅蓝背景，大数字标签小：关键数值]
```

### 2.1 模块卡片要素（吸收自模块卡片设计）

每个模块卡片必须包含：

- 左侧蓝色竖线 accent bar（宽 4px，强调色）
- 圆角卡片 + 编号徽章（深蓝圆底白色数字，01/02/03… 连续）
- 模块标题 + 能力列表（每条前置 `›` 符号，列 1~6 项关键能力）
- 每个卡片列表项须能回指 FEA-XXX / 页面区块

### 2.2 产品全景图布局思路（吸收自 arch-diagram-pro 产品全景图）

产品全景图 = 模块组成图的完整形态：标题带（产品名+定位副标题）→ 特征徽章（产品属性）→ 按业务域分组的模块卡片网格 → 核心流程带（用户/数据主路径）→ 指标区（北极星指标与关键量化值）。分组可按：用户端 / 管理端 / 平台能力 / 集成对接；每组一个分区标题（深蓝底色条带）。

### 2.3 自适应布局引擎（吸收自 arch-diagram-pro）

| 模块数 | 列数 | 布局说明 |
|--------|:---:|---------|
| 1-2 | 1 | 全宽展开，行内横向排列 |
| 3-4 | 2 | 双列平衡 |
| 5-8 | 3 | 三列紧凑 |
| 9-12 | 4 | 四列密集 |
| 13-16 | 4 + 缩小 | 压缩信息，精简列表项 |
| >16 | 强制分拆 | 分拆为多张图或筛选核心模块 |

> 模块超过 16 个时，**强制**分拆为多张图，不得强行塞入单张。

### 2.4 信息密度原则（吸收自 arch-diagram-pro）

- 卡片间距 ≤ 10px——信息密度高，无大面积空白。
- 每张卡片信息与其余卡片均衡（某模块描述过长则截断保留关键词，完整文本另附注释）。
- 标题层级清晰：大标题 → 分区标题 → 卡片标题 → 列表项，共 4 层。

## 3. 8 项自校验（吸收自 arch-diagram-pro，适配产品范畴）

图/结构完成后逐项核验，不通过则修正：

```
[ ] 1. 标题带完整 — 系统/产品名 + 副标题 + 特征徽章齐全
[ ] 2. 分区结构齐全 — 标题带 → 模块网格 → 流程带 → 指标区（按需），层级顺序正确
[ ] 3. 编号徽章连续 — 01, 02, 03... 无跳号或重复
[ ] 4. 每个模块卡片信息完整 — 标题 + ≥1 条能力 + 可回指 FEA-XXX
[ ] 5. 流程箭头连续 — 相邻节点间均有箭头连接，无断点
[ ] 6. 信息密度达标 — 卡片间距 ≤10px，无大面积空白
[ ] 7. 内容边界守住 — 只画产品/模块范畴，无技术实现细节
[ ] 8. 模块数 ≤16 — 超过已分拆或筛选
```

## 4. 工作流程

1. **定主题**：从已确认 FEA-XXX 提取产品/系统名与副标题。
2. **列模块**：按业务域分组枚举模块，标注每组模块数；>16 直接规划分拆。
3. **抽能力**：每个模块从 page-design 内容区块/FEA 提取关键能力（1~6 条），标注可回指编号。
4. **选布局**：按模块数选列数（自适应布局引擎）；特征徽章从维度匹配结果取。
5. **补流程带**：从 functional-flow 主流程提取核心流转节点，箭头连续。
6. **补指标区**：从 feature-list 优先级/目标 G-XXX 提取关键数值（按需）。
7. **过 8 项自校验**：逐项核验，不通过修正后重验。
8. **输出**：在 page-design 产物中以分区图结构呈现，或输出为沟通用图。

## 5. 核心硬规则

1. **分区顺序固定**：标题带 → 特征徽章 → 模块卡片网格 → 流程带 → 指标区，不可随意调序或省略必要分区。
2. **卡片信息必齐**：标题 + 编号徽章 + 能力列表是模块卡片底线；空卡片、无编号、无能力 = 不合格。
3. **编号连续无跳号**：01/02/03… 编号徽章必须连续，不跳号不重复——跳号即遗漏信号。
4. **模块数 >16 强制分拆**：宁可拆成多张图，不牺牲可读性硬塞。
5. **信息密度优先**：卡片间距 ≤10px，无大面积空白；长描述截断留关键词，完整内容另附。
6. **只画产品范畴**：模块/能力/流转全部可回指 FEA-XXX 与功能流程，不画技术实现细节。

## 6. 边界（Do Not）

- 不画技术架构图（微服务/数据层/中间件分层）——超出 PRD-only 产品范畴。
- 不写 HTML/CSS 模板代码——技法只定义内容结构与布局规则，产出形式不限。
- 不发明模块——模块以已确认 FEA-XXX 为准，推断模块标 `AI_INFERENCE`。
- 不塞实时动态/3D 可视化/手绘风格——图为静态产品表达。
- 不把图标/配色细节当硬性要求——视觉样式属视觉设计，非页面骨架契约。

## 7. 质量自检清单

- [ ] 标题带完整（系统名 + 副标题 + 特征徽章）
- [ ] 分区结构顺序正确，层级 4 层清晰
- [ ] 模块编号连续无跳号，数量 ≤16（或已分拆）
- [ ] 每个模块卡片含标题 + 能力列表，可回指 FEA-XXX
- [ ] 流程带节点箭头连续无断点
- [ ] 信息密度达标（卡片间距 ≤10px，无大空白）
- [ ] 指标区数值可溯源（G-XXX / 里程碑）
- [ ] 无技术实现细节，内容均在产品范畴
