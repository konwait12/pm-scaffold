# 页面状态与可用性收口扫查（Page State Scan）

> 来源吸收：work-buddy `ux-qa-gate` skill——状态与边界扫查（空/加载/错/成/部分/溢出/权限）+ Nielsen 可用性启发式 10 条 + 严重分级 🔴🟠🟡🔵。作为 page-design 的页面完备性收口技法。
> 定位：page-design 输出页面骨架（信息与导航契约）；本文档提供"每个数据驱动视图都要覆盖哪些状态 + 用 10 条启发式快速自评 + 按严重级定性遗留项"的收口清单，提醒页面表定稿前补状态。与 `high-freq-missing-10.md` 互补。
> 触发：Generate 页面表后、Audit 前；或 Audit 发现页面行缺少空/加载/错误/权限状态时。**按需加载，不设全局闸门**。

## 1. 页面状态扫查（每个数据驱动视图逐一打勾）

| 状态 | 页面骨架须体现 | 遗漏后果 |
|---|---|---|
| 空态 | 无数据时的引导，不是白屏 | 用户进死胡同 |
| 加载态 | 取数中的指示/骨架 | 误以为失败 |
| 错误态 | 明确错误提示 + 恢复路径 | 无法自救 |
| 成功态 | 操作后的确认/去向 | 反馈缺失 |
| 部分 | 部分数据缺失的优雅降级 | 整页崩溃 |
| 溢出 | 长文本/超多条目/大图被承接 | 布局错乱 |
| 权限 | 无权限时隐藏/禁用/引导 | 越权可见 |

## 2. Nielsen 10 条启发式（节选自评）

系统状态可见（Status）· 贴合现实（Match）· 用户掌控与自由（Control）· 一致与标准（Consistency）· 预防错误（Error Prevention）· 识别优于回忆（Recognition）· 灵活高效（Flexibility）· 极简与美学（Aesthetic）· 帮助识别与修复错误（Help with Errors）· 帮助文档（Help）。对 page-design 页面表逐页选适用条目自评，不适用项明确跳过。

## 3. 严重分级（遗留项定性）

| 级别 | 含义 | 处理 |
|---|---|---|
| 🔴 Blocker | 用户完全无法完成任务 | 交付前必修 |
| 🟠 Major | 明显受阻、可绕开但痛苦 | 交付前必修 |
| 🟡 Minor | 能感知但可绕开 | 记录、顺手则修 |
| 🔵 Enhancement | 打磨/可选项 | 记入 backlog |

任一 🔴/🟠 → 回到 Generate 补齐对应页面状态行再进 Human Gate；仅 🟡/🔵 → 记录遗留项。

> **边界**：page-design 只确认"这些状态是否存在、内容是什么"（信息与导航契约）；loading 动画、错误文案、反馈时机等写法属 `interaction-rules` 的 IX-XXX 与 UI 文案规范，不在此越界。
