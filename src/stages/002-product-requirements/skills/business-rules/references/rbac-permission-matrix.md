# RBAC 权限矩阵技法参考（RBAC Permission Matrix）

> 本文将相关实践转化为本项目的可选方法，不引入外部运行时依赖。
> 定位：business-rules 产出的 BR-XXX 业务规则文本是权威；本文档提供"把权限规则结构化为功能权限矩阵 + 数据权限规则两张表"的技法，增强权限差异可见性。
> 触发：当需求涉及多角色、权限差异、审批流或 to B 多租户场景时使用。**按需加载，不设全局闸门**。

## 1. 输入映射（pm-scaffold 语境）

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| 角色 | user-journey 的角色 / user-stories 的参与者 | 矩阵列头 |
| 资源/功能 | feature-list 的 FEA-XXX | 矩阵行 |
| 操作 | interaction-rules 的 IX-XXX 动作 | 单元格值 |
| 业务规则 | business-rules 的 BR-XXX | 权限判定来源 / 溯源 |
| 状态 | state-machine 的 STATE-XXX | 权限随状态变化 |
| 数据范围 | user-journey 的组织架构 | 数据权限规则依据 |

> **上游未 confirmed，不启动矩阵**：以 user-journey 角色 / FEA-XXX 为准；缺失标 `待确认`，不凭空发明。

## 2. 两张表结构（吸收自 product-design-0to1 Step 6.5）

RBAC 矩阵须输出**两张表**：功能权限矩阵（谁能做什么操作）+ 数据权限规则（谁能看到哪部分数据）。

### 2.1 功能权限矩阵（模块/操作 × 角色）

```
| 模块/操作 | HR | 管理者 | 员工 |
|---|---|---|---|
| M1 薪酬模板-新建 | ✅ | ❌ | ❌ |
| M1 薪酬模板-启用 | ✅ | ❌ | ❌ |
| M3 工资发放 | ✅ | ❌ | ❌ |
| M4 看板-查看 | ❌ | ✅ | ❌ |
| M5 我的工资条-查看 | ❌ | ❌ | ✅ |
```

单元格值约定：
- ✅ 允许 / ❌ 禁止 / 🔒 条件允许（须追溯 BR-XXX，标注条件）/ — 不适用

**精细化示例（吸收自 prd-development 评论功能权限控制表）**：当同一资源对不同角色有"部分允许"差异时，按操作粒度拆行：

```
| 操作 | 普通用户 | 管理员 |
|---|---|---|
| 删除评论 | 仅限自己的评论 | 任意评论 |
| 修改评论 | 仅限自己的评论 | 仅限自己的评论 |
```

### 2.2 数据权限规则（角色 × 可见数据范围 × 规则来源）

```
| 角色 | 可见数据范围 | 规则来源 |
|---|---|---|
| HR | 全公司所有员工工资单 | 决策清单 D-XXX |
| 管理者 | 仅本人所辖部门及下级部门员工 | 按部门隶属（D-XXX） |
| 员工 | 仅本人 | 用户ID = 登录ID |
```

每条规则必须能从 Step 5.5 字段决策清单或用户输入溯源，**不允许凭空发明**。

## 3. 工作流程

1. **列角色**：从 user-journey 提取角色，按 RBAC 层级排序（普通→主管→管理员→系统）。
2. **列资源/操作**：从 feature-list 的 FEA-XXX 提取模块与操作作为行。
3. **填功能矩阵**：每个单元格标注 ✅/❌/🔒/—；🔒 条件允许须追溯 BR-XXX 并写明条件。
4. **填数据权限**：为每个角色写可见数据范围 + 规则来源（追溯决策清单/用户输入）。
5. **挂状态**：权限随状态变化的（如"仅 PROCESSING 状态可审批"）标注 STATE-XXX。
6. **输出双表**：在 business-rules 产物附录呈现，权限差异显式可见。

## 4. 核心硬规则

1. **两张表缺一不可**：功能权限矩阵 + 数据权限规则必须同时输出；只画功能权限不画数据权限 = 权限不完整。
2. **权限差异显式化**：不同角色对同一资源的差异必须显式列出，不合并表述；"部分允许"按操作粒度拆行（如"仅限自己的评论"vs"任意评论"）。
3. **规则可溯源**：数据权限规则的"规则来源"必须追溯到决策清单 D-XXX 或用户输入；🔒 条件允许追溯 BR-XXX；无来源标 `待确认`，不凭空发明。
4. **状态相关权限标注**：权限随状态变化的必须挂 STATE-XXX；与 state-machine 不一致即 `CONFLICT`。
5. **to B 多租户**：跨租户权限须标注租户隔离边界；管理员权限须标注是否跨租户（"全公司"vs"跨租户"）。
6. **特殊系统泳道**：定时任务/外部集成/自动流转触发的操作，标注为"系统"角色并写明触发条件。

## 5. 边界（Do Not）

- 不设计权限技术实现（JWT / RBAC 中间件 / 权限框架，超出 PRD-only）。
- 不替代 BR-XXX 文本——双表是结构化视图，规则文本是权威。
- 不替业务方决定角色层级——以 user-journey 为准，AI 推断的角色层级须标 `AI_INFERENCE` 交人工拍板。
- 不把数据字段塞入矩阵（属 validation-rules）。

## 6. 质量自检清单

- [ ] 功能权限矩阵 + 数据权限规则双表齐全
- [ ] 角色按 RBAC 层级排序，覆盖 user-journey 全部角色（含特殊系统泳道）
- [ ] 资源/操作行覆盖相关 FEA-XXX
- [ ] 权限差异显式，"部分允许"按操作粒度拆行
- [ ] 🔒 条件允许追溯 BR-XXX 并写明条件
- [ ] 数据权限规则的"规则来源"追溯决策清单 / 用户输入，无凭空发明
- [ ] 状态相关权限挂 STATE-XXX，无 CONFLICT
- [ ] 多租户权限标注隔离边界（to B）
- [ ] 无权限技术实现越界内容
