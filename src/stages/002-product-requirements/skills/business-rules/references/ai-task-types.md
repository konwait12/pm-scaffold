# AI 任务类型技法参考（AI Task Types）

> 来源吸收：`prd-writer`（prd-writter__skillhub）步骤 3.1「AI 能力定义自动推导」（任务类型分类/抽取/生成/推理/RAG/Agent + 输入/输出定义）+ 模板 ai-prd-template.md §4 输入输出定义，作为 business-rules 的可选 to AI 落地能力。
> 定位：为 PRD 中的 AI/算法类功能（LLM、模型、推荐、智能处理）明确定义"任务类型"，从而推导出输入信号、输出形式与评估要点，避免把 AI 能力写成黑盒一句带过。
> 触发：当功能需求涉及 AI/模型/算法/智能处理，需要把"AI 要做什么"落成可验收定义时使用。**按需加载，不设全局闸门**。

## 1. 输入映射（pm-scaffold 语境）

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| AI 能力描述 | feature-list 的 FEA-XXX | 任务类型挂接对象 |
| 任务类型（6 分类） | business-rules 的 BR-XXX | AI 判定边界/触发条件 |
| 输入格式定义 | validation-rules 的 VL-XXX | 原始输入与 Prompt 输入校验 |
| 输出格式定义 | exception-handling 的 EX-XXX | 输出异常与兜底 |
| 评估维度/验收标准 | acceptance-criteria 的 AC-XXX | 模型行为可测性 |

> **AI 能力未确认，不定义任务类型**：以已确认的 FEA-XXX 为对象；输入/输出缺失标 `待确认`，不替技术选型。

## 2. AI 任务类型 6 分类（吸收自 prd-writer 步骤 3.1）

每个 AI 功能必须且仅归入一类主任务类型（可含一个辅助任务），每类定义：**输入信号 / 输出形式 / 评估要点**。

| 任务类型 | 输入信号 | 输出形式 | 评估要点 |
|---|---|---|---|
| **分类** Classification | 文本、工单、对象集合 + 预定义类别集 | 离散类别标签 + 置信度（如 `{label:"高危", confidence:0.92}`） | 准确率、各类别 F1、未命中时的拒识率 |
| **抽取** Extraction | 非结构化文本/文档/对话记录 | 结构化字段（JSON/表格）+ 每字段原文出处引用 | 字段级准确率/召回率、引用可追溯、缺失字段标记 |
| **生成** Generation | 业务参数、用户指令、模板约束 | 自然语言/文案/结构化内容（受格式约束） | 格式合规率、内容可接受度、人工抽检通过率 |
| **推理** Reasoning | 多条件事实 + 规则集 | 结论 + 推理依据链（结论、依据步骤） | 结论正确率、依据可追溯性、边界条件覆盖率 |
| **RAG** 检索增强 | 用户问题 + 知识库文档集 | 答案 + 引用来源（文档编号/段落位置） | 检索命中率、答案忠实度、引用准确率 |
| **Agent** 多步自主 | 目标任务 + 可用工具集 | 多步执行序列 + 最终结果（含每步状态） | 任务完成率、步数效率、工具调用准确率、中途失败恢复 |

### 2.1 输入定义模板（吸收自 ai-prd-template.md §4.2）

```
原始输入：{输入数据类型及来源}
Prompt 结构：
  - System Prompt：{角色定义、输出格式、禁止事项}
  - User Prompt：{包含的内容}
上下文长度预估：{单次调用总长度预估}
```

### 2.2 输出定义模板（吸收自 ai-prd-template.md §4.3）

**输出格式：** {JSON / 表格 / 自然语言}

```json
{
  "字段1": "说明",
  "字段2": "说明"
}
```

输出定义必须做到：字段逐一说明含义与取值，使下游 `validation-rules`（格式校验）与 `exception-handling`（解析失败兜底）可直接消费。

### 2.3 人机协作边界（HITL，吸收自 ai-prd-template.md §3.3）

| 环节 | 自动化策略 | 人工介入点 |
|------|------------|------------|
| {输入预处理} | {自动/半自动} | {何时人工介入} |
| {AI 处理} | {自动，低置信转人工} | {confidence < 阈值时} |
| {结果确认} | {人工确认后生效} | {影响金钱/合规的结果必人工} |

## 3. 工作流程

1. **识别 AI 触发**：从 FEA-XXX 中找出涉及 LLM/模型/算法/智能的关键词（智能筛选、推荐、AIGC、自动化）。
2. **定主任务类型**：从 6 分类中选定唯一主类，说明为何归入该类（不超过一句）；混合能力拆为主+辅助任务。
3. **定义输入**：原始输入、Prompt 结构、上下文长度预估；缺失标 `待确认`。
4. **定义输出**：格式（JSON/表格/自然语言）+ 字段说明，作为下游校验与兜底的契约。
5. **写 AI 相关 BR**：AI 判定的触发条件、边界（何时不做 AI）、低置信转人工阈值，用 EARS 句式入 BR-XXX。
6. **挂评估要点**：按任务类型对应评估要点列出可测项，与 acceptance-criteria 的 AC-XXX 对齐。

## 4. 核心硬规则

1. **任务类型必归唯一主类**：分类/抽取/生成/推理/RAG/Agent 六选一；混排须拆解，不写"智能化处理"这类黑盒描述。
2. **输入输出必定义**：每类任务必须有输入信号 + 输出格式 + 字段说明，缺失标 `待确认`，禁止留空进评审。
3. **输出可被校验消费**：输出格式须让 VL-XXX 能写格式校验、EX-XXX 能写解析失败兜底；JSON 字段说明到含义与取值。
4. **人机边界显式**：HITL 表中每个环节标注自动化策略与人工介入点；影响金钱/合规的结果必须人工。
5. **评估要点匹配任务类型**：准确率/忠实度/完成率等按任务类型选，不套通用模板；阈值量化（≥0.9 而非"高"）。
6. **不越界到技术选型**：不指定模型名/参数/工程链路（超出 PRD-only），只定义任务行为与验收口径。

## 5. 边界（Do Not）

- 不指定具体模型、参数、API 或技术实现链路（属工程方案，超出 PRD-only）。
- 不写 Prompt 全文——只定义 Prompt 结构（角色/任务/输出/约束四要素）与约束要求。
- 不把 AI 能力写成"智能优化""自动生成"一句带过——必须落到 6 分类之一并定义输入输出。
- 不替业务方决定置信阈值——低置信转人工的阈值标 `待确认` 或 `AI_INFERENCE` 交人工拍板。
- 不在 business-rules 中重复验收标准——评估要点挂 AC-XXX，AI 判定边界/触发才是 BR。

## 6. 质量自检清单

- [ ] 每个 AI 功能归类到 6 分类之一，且主类唯一
- [ ] 输入信号（原始输入/Prompt 结构/上下文长度）已定义或标 `待确认`
- [ ] 输出格式（JSON/表格/自然语言）+ 字段说明齐全，可被 VL/EX 消费
- [ ] HITL 人机协作边界表完成，金钱/合规结果有人工介入点
- [ ] 评估要点按任务类型选择且阈值量化
- [ ] AI 判定边界已入 BR-XXX（何时触发/何时不做/低置信转人工）
- [ ] 无模型选型/参数/API 越界内容
