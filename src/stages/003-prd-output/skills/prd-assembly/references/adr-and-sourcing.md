# 决策记录与来源标注（ADR & Sourcing）

> 来源吸收：`pm888__skillhub` 的 ADR 内联格式（§6.2）、Sourcing Rules（§2.1）、Handoff Context（§4/§13.4）、决策预注册四象限（§9）与坏消息公式（§10.3），作为 prd-assembly 决策记录与 Human Gate 沟通的可选落地能力。
> 定位：给「决策从哪来、依据是什么、错了怎么纠」提供一套诚实机制——ADR 内联记录难逆转决策，Sourcing 6 级标注管住脑补，决策预注册让复盘可证伪，坏消息公式让 gate 沟通不报喜不报忧。
> 触发：Intake 发现决策（DEC-XXX）/ 假设（ASSUMPTION）需要登记来源时；Human Gate 前整理决策清单与风险沟通材料时。**按需加载，不设全局闸门。**

## 1. 输入映射

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| 难逆转决策（改范围/改口径/改状态机） | DEC-XXX（决策记录） | ADR 内联格式登记决策/替代方案/理由/后果/信心度/证伪器 |
| 每一条信息的来源类型 | SRC-XXX（来源登记，见 source-handling.md） | Sourcing 6 级标注，杜绝脑补 |
| 阶段间交接信息 | 各 work item 产物之间的交接上下文 | Handoff Context 机器可读契约，避免重问已答 |
| 关键决策的复盘 | Human Gate / 99-review 决策复盘 | 决策预注册四象限（技能/方差/运气/学费） |
| 滑期/风险/阻塞沟通 | Human Gate 呈现材料 | 坏消息公式（事实→影响→在做→诉求） |

## 2. ADR 内联模板（每个难逆转决策立即写）

```markdown
### ADR-001：[决策标题]
- **决策**：[最终选择]
- **替代方案**：[方案 B / 方案 C / 维持现状]
- **理由**：[为什么选这个，含 Trade-off 依据]
- **后果**：[预期正面 / 已知负面 / 回滚成本]
- **信心度**：[高/中/低] — [原因]
- **证伪器**：如果 [可观察现象] 在 [日期] 前发生，此决策需重评
```

写稿质量规则（与决策相关的部分）：

1. 未确认信息标 TBD，不自行填充。
2. 每个功能点有明确的输入/处理/输出。
3. 字段规则表完整（类型/必填/默认值/校验/长度/唯一性）。
4. 权限矩阵明确（谁能看/谁能操作/谁能配置）。
5. 边界情况覆盖（空值/超长/并发/极端值）。
6. ADR 记录所有难逆转决策。
7. 信心度贯穿所有关键判断。

## 3. Sourcing Rules：6 级来源标注

每一条信息必须标注其来源类型，**绝不允许脑补**：

| # | 信息类型 | 标注方式 | 处理规则 |
|---|---|---|---|
| 1 | 已确认事实 | `[来源, 日期]` | 可直接使用 |
| 2 | 用户/研究输入 | `[用户陈述, 日期]` | 可使用，需在 PRD 引用 |
| 3 | 模型知识（无 web 验证） | `Unverified — model knowledge` | 必须标注，关键项需人工复核 |
| 4 | 推断（基于事实的逻辑推导） | `推断 — 依据 X` | 需列出推导链 |
| 5 | 假设（未经验证的猜测） | `假设` | 必须列入 Open Questions / ASSUMPTION |
| 6 | 编造的 URL/数字/统计 | —— | **绝对禁止** |

**底线**：不知道就说不知道。无 web 访问时不准编造 URL、日期、市场容量、竞品数据。未知就标 TBD 并进入待确认清单（Open Questions / issue-record）。

对应到 prd-assembly 的产物：脚手架已有 `ASSUMPTION`（假设）与 `UNK-XXX`（未知）登记机制，本技法的 6 级标注直接映射到 SRC-XXX 来源类型字段。

## 4. Handoff Context：阶段间机器可读契约

每个阶段产出必须以 Handoff Context 块结尾，下一阶段读取该块预填答案、不重问已答问题。

```markdown
## Handoff Context
- Stage: research | prd | review | decision | update
- 产品名: [name]
- 用户层级: [A 普通用户 / B 专业用户 / C 之间]
- 目标平台: [web / mobile / desktop]
- 预算: [budget]
- 时间: [timeline]
- 关键决策: [ADR-001, ADR-002 ...]
- Source files: [上一阶段文件 → 本阶段文件]
```

映射到脚手架：对应各 work item 之间的产物交接（背景 → 旅程 → 故事 → 功能…），Intake 阶段先读上游 Handoff Context 信息，避免重复澄清已确认问题。

## 5. 决策预注册（Pre-Registration）与四象限复盘

### 5.1 关键决策必须在产出前写下选项、概率、可证伪标记

1. **公平地写基线与替代方案**：每个真实选项都按其最强论点陈述；「维持现状」必须列为选项。
2. **概率用数字**：「我觉得能成」→「70% 在 [日期] 前达到 [可观察结果]」。
3. **预注册证伪器**：「如果 [可观察现象] 在 [日期] 前发生，我就错了」——现在写，未来才能不靠自尊心地纠偏。
4. **过程与结果分离复盘**（四象限）：

| 象限 | 含义 | 该做什么 |
|---|---|---|
| 好过程 / 好结果 | 技能（skill） | 提炼可复制方法论 |
| 好过程 / 坏结果 | 方差（variance） | 什么都不改 |
| 坏过程 / 好结果 | 运气（lucky）——最危险 | 它在教坏习惯，别学 |
| 坏过程 / 坏结果 | 学费（tuition） | 提炼教训 |

5. **模式胜过单条**：每 ~10 次复盘跨条读，识别个人系统性偏差。

### 5.2 决策条目模板（事前预注册）

```markdown
# Decision Entry: [标题] — [日期]

**Deciding:** [实际选择 + 截止日期] · **State:** [已知 / 猜测 / 情绪标记]

## Options（每个按其最强论点陈述）
1. [选项 A — 最强论点]
2. [选项 B — 最强论点]
3. 维持现状：[最强论点]

## The Call
**Choice:** [选项] · **Because:** [2-3 个承重理由]
**Expectations:** [X% 在 (日期) 前达到 (可观察结果)；...]
**I'm wrong if:** [可观察现象 + 日期]
**Review on:** [复盘日期]
```

### 5.3 决策质量规则

- 每个选项包括「维持现状」都按其最强论点陈述。
- 至少一个 expectation 含数字 + 日期。
- 证伪器是可观察的，不是感受。
- 复盘对照书面条目，绝不靠记忆。
- 象限在画教训之前命名。

## 6. 坏消息公式（Human Gate 风险沟通）

**事实 → 影响 → 我们在做 → 明确诉求**。无软化前言，无归咎，无「不幸地是」。

| ❌ 不要 | ✅ 要 |
|---|---|
| 「由于不可预见的情况，可能会有一些延迟。」 | 「支付 API 弃用让我们损失 2 周。上线从 2/5 推到 2/19，除非砍掉发票范围——周五前需决策。」 |
| 「我们对容量有点担心。」 | 「我们唯一的 iOS 工程师 3/1 离职。2/10 前无补人决策，移动里程碑滑一个 sprint。」 |

**软化规则**：
- 删除事实周围的 hedge（「somewhat」「may potentially」「it seems」）。不确定性只在真实且量化时保留（「60/40 我们能赶上日期」）。
- 不预归咎（「如前所述…」读作自保；重要就平实重述风险）。
- 每个问题配它给读者制造的**决策**。无诉求的坏消息是 venting，有诉求的才是管理。

对应 prd-assembly：Human Gate 呈现未决风险（UNK-XXX）与不一致报告时，用本公式组织——事实（什么变了）→ 影响（对确认/上线意味着什么）→ 在做（已采取的动作）→ 诉求（需要批准人做什么决定）。

## 7. 工作流程

1. Intake 阶段：对上游每个 DEC-XXX / ASSUMPTION / UNK-XXX 应用 Sourcing 6 级标注，登记到 SRC-XXX。
2. Generate 阶段：每遇到难逆转决策（范围/口径/状态机变更），立即写 ADR 内联块。
3. 阶段交接：每个产物以 Handoff Context 块收尾，供下游 Intake 预填。
4. 关键决策点：写决策条目（选项 + 概率 + 证伪器 + 复盘日期）。
5. Human Gate：用坏消息公式组织风险与不一致沟通材料（事实→影响→在做→诉求）。
6. 复盘节点：按四象限对照书面条目复盘，命名象限后再提炼教训。

## 8. 核心硬规则

1. 每一条信息必须带来源标注，绝不允许脑补；编造的 URL/数字/统计绝对禁止。
2. 难逆转决策立即写 ADR（决策/替代方案/理由/后果/信心度/证伪器）。
3. 替代方案必须包含「维持现状」并按最强论点陈述。
4. 概率用数字 + 日期表达，证伪器必须可观察。
5. 复盘对照书面条目，象限在画教训之前命名。
6. 坏消息用「事实→影响→在做→诉求」公式，无诉求的坏消息不出口。

## 9. 边界（Do Not）

1. 不替人类做最终取舍——决策权归人工，AI 只整理与辅助。
2. 不在无来源时编造市场容量、用户数、竞品声明。
3. 不把「事后补写」当决策记录——价值在事前真开放时写下。
4. 不按结果给决策打分——lucky 象限会强化坏习惯。
5. 不用 ADR 替代脚手架既有的 DEC-XXX 登记与 issue-record 机制，两者互补。
6. 不在 Human Gate 沟通中用 hedge 软化真实风险。
