# PRD 评分卡参考（PRD Scoring Rubric）

> 来源吸收：Trae `prd-reviewer` skill 的「10 分制 7 模块评分体系 + 17 项快速检查清单 + 三大禁忌」，经 to B 适配（剔除 tapd 地址/设计师等待定工具字段，改为"产物路径+评审人"；保留背景四要素/量化目标/灰度/报表/风险合规完整扣分规则）后作为 prd-assembly Human Gate 的参考工具。
> 定位：prd-assembly 产出的 prd.md 与 review-taxonomy 裁决是权威；本文档是**advisory 级参考工具，不写入产物状态机、不影响 gate 阻断行为**。
> 触发：PRD 汇总 Human Gate 前，评审人可选用于量化自检。**按需加载，不设全局闸门，advisory 级**。

## 0. 级别声明（必读）

本评分卡是**参考工具**：评分结果不改变 prd.md 的产物状态（draft/ready_for_human_review/confirmed），不接入 validate_artifact.py，不产生 blocking 闸门。仅辅助评审人结构化自检。最终阻断仍以 review-taxonomy 的 REVISION 裁决与 authorized-reviewers 的人工批准为准。

## 0.1 蒸馏说明

蒸馏自 workbuddy `prd-reviewer` skill（10 分 7 模块 + 3 红线 + 17 检查）+ `incremental-prd-collaboration` 高频遗漏清单 + `incre-prd-checklist.md`。本文档是**advisory 级**，prd-assembly validate_artifact.py 是**结构级**——两者互补不互替代。

## 1. 三大禁忌（评分红线，吸收自 prd-reviewer）

1. **禁止模糊评分**：扣分须引用 prd.md 原文位置（§章节/FEA-XXX/BR-XXX），不允许"大致符合""基本达标"等模糊表述。
2. **不跨模块抵扣**：某模块得 0 分不影响其他模块得分，模块间独立评分。
3. **未按 prd.md 模板填写**：对应模块计 0 分，整体不超过 6 分。

## 2. 七模块评分（10 分制，含扣分规则，to B 适配）

### 模块 1：基础信息完整性（1.0 分）
扣分规则：每缺失 1 项扣 0.2 分；填写不规范每项扣 0.1 分；扣完 1 分止。

| # | 检查项 | 扣分 |
|---|---|---|
| 1 | 产物路径+评审人（替代 tapd 地址/设计稿地址） | -0.2 |
| 2 | 项目级别（S/A/B 级三选一） | -0.2 |
| 3 | PM 负责人 | -0.2 |
| 4 | 技术负责人 | -0.2 |
| 5 | 测试主 R | -0.2 |
| 6 | 需求提出人 | -0.2 |
| 7 | 改动涉及范围（端/系统/页面/模块） | -0.2 |
| 8 | 期望联调时间 | -0.2 |
| 9 | 期望上线时间 | -0.2 |
| 10 | PRD 修订记录（版本+时间+修订内容+变更方+关注人） | -0.2 |

### 模块 2：项目/需求背景（1.5 分）
格式标准：用户 + 场景 + 问题 + 量化数据四要素（to B 须含角色与组织场景）。

| 检查项 | 要求 | 扣分 |
|---|---|---|
| 格式规范 | 含"用户+场景+问题+量化数据"四要素 | -0.5 |
| 量化数据 | 有具体数值（用户量级/问题发生率/影响范围） | -0.5 |
| 描述清晰 | 核心问题明确，无模糊表述 | -0.3~0.5 |
| 是否填写 | 此项为空得 0 分 | →0 分 |

### 模块 3：目标和收益（2.0 分）

| 子项 | 要求 | 扣分 |
|---|---|---|
| 量化目标 ROI | 有具体数值（如转化率提升 5%/月活新增 20 万/借款规模增加 5000 万）；无具体数值 | -0.6 |
| 达成路径 | 工时>5pd 必填；路径合理拆解对应量化目标；应填未填 | -0.6 |
| 评估方式 | 明确评估方法和评估时间；不明确 | -0.4 |
| 是否填写 | 此项为空得 0 分 | →0 分 |

### 模块 4：需求详述（3.0 分）
评分原则：数据埋点非必填项，根据需求类型酌情评分。

| 子项 | 要求 | 扣分 |
|---|---|---|
| 需求列表 | 序号+需求点简述+优先级(P0/P1/P2)+备注；缺失 1 项关键信息 | -0.2/项 |
| 交互逻辑 | 有交互稿贴出；场景完整；逻辑无遗漏；缺失 | -0.3 |
| 产品逻辑 | 图文/表格描述；金字塔原理+MECE；不清晰/不符合 MECE | -0.3~0.5 |
| 数据埋点 | 非必填，按需求类型酌情：①纯服务端需求（无用户侧交互）可不填不扣分；②App/H5 端需求应有埋点，缺失关键埋点扣 0.3~0.5；③标注"无需埋点"不扣分 | -0.3~0.5 |

### 模块 5：灰度方案（0.5 分）

| 情况 | 要求 | 扣分 |
|---|---|---|
| 需灰度/ABtest | 明确灰度范围+比例+时间+监控指标（to B 多租户灰度）；未填写→0.5，不具体→0.2~0.3 | -0.5 |
| 无需灰度 | 标注"无需灰度"或"无需 ABtest"；未标注 | -0.2 |

### 模块 6：数据报表需求（0.5 分）

| 情况 | 要求 | 扣分 |
|---|---|---|
| 需新增/修改报表 | 报表字段+统计口径+展示形式具体需求；未填写→0.5，不具体→0.2~0.3 | -0.5 |
| 无需新增/修改报表 | 标注"无需新增/修改数据报表"；未标注 | -0.2 |

### 模块 7：风险/合规披露（1.5 分）

| 检查项 | 要求 | 扣分 |
|---|---|---|
| 资金风险判断 | 明确是否"跟钱相关"+风险等级（高/中/低）；未判断→0.5，等级未填/填错→0.3 | -0.5 |
| 数据泄露风险 | 有→详细描述+法务/财务/风控沟通结论；无→标注"无数据泄露风险"；未标注/描述不完整 | -0.4 |
| 其他合规风险 | 有→详细披露+标注沟通结论；to B 须含权限/审计/数据出境；未披露 | -0.3 |
| 是否填写 | 此项为空得 0 分 | →0 分 |

## 3. 评级标准

| 评级 | 分值 | 含义 |
|---|---|---|
| 合格 | ≥7.0 | 可推进人工批准 |
| 待改进 | 6.0-6.9 | 标记 CONDITIONS，附改进清单 |
| 不合格 | <6.0 | 路由 REVISION，返工 |

## 4.1 研发评审版 PRD 硬标准（蒸馏 B1 + G3 pm-master）

PRD 送研发评审前，**必须**包含以下硬性章节；任一缺失即使评分 ≥7 也应打回返工：

- [ ] 组件级需求（页面/接口/数据模型分层清晰）
- [ ] 状态机（涉及状态变更的字段须文档化）
- [ ] 埋点方案（事件名 + 触发时机 + 上报参数 + 分析维度）
- [ ] 接口契约（调用方 / 返回结构 / 错误码）
- [ ] 验收标准（Given/When/Then + 量化阈值）
- [ ] 异常降级（至少 1 条失败路径 + 兜底）
- [ ] 灰度与回滚（适用范围 + 比例 + 监控 + 回滚触发条件）
