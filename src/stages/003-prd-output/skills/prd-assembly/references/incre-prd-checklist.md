# PRD 增量协作高频遗漏检查清单

> 本清单沉淀为独立、可验证的增量评审原则；不依赖任何本地索引或特定工具。
> 用途：prd-assembly §Red-Review 阶段对 PRD 做"高频遗漏"压力测试，确保产物满足 L0-L2 共性质量要求。
> 适用阶段：prd-assembly `Audit`（评审评审）之前。

## 1. 产品边界（防"PRD 滑向 API"）

PRD 描述的是**业务意图/规则/状态/文案/验收**，**不默认滑向**：

- [ ] 字段类型（数据库 schema / DDL）
- [ ] API 端点（路由、参数序列化）
- [ ] 后端实现细节（中间件、队列、缓存策略）
- [ ] 客户端 SDK / 调用约定

若产品确实需要技术方案，单独走 `prd-to-ddd-design` work item，不在 PRD 内自包含。

## 2. 高频遗漏清单（13 类）

逐项对照 PRD 各章节；任一未覆盖且**适用**于本期需求，必须在 `issue-record.md` 登记 ISS-NNN 并标注 owner。

### 2.1 按钮 / 触发元素文案

- [ ] 主操作按钮文案明确（避免"确定"这类语义模糊）
- [ ] 次操作按钮文案与主操作可区分（取消 / 跳过 / 暂存）
- [ ] 危险操作按钮需要二次确认文案

### 2.2 异常 / 边界状态

- [ ] 网络异常（断网、超时、弱网）
- [ ] 空数据（首次使用 / 清空后）
- [ ] 无权限（未登录 / 角色不足）
- [ ] 并发冲突（重复提交 / 资源锁定）
- [ ] 数据过期（缓存失效 / 跨时区）

### 2.3 阻断 / 降级文案

- [ ] 服务降级提示（部分功能不可用时怎么告知）
- [ ] 阻断态操作路径（被拒绝时下一步是什么）

### 2.4 时间 / 时区

- [ ] 跨时区展示口径
- [ ] 时间窗（活动开始前 X 小时的 X 取值依据）
- [ ] 倒计时刷新策略

### 2.5 数字 / 货币 / 阈值

- [ ] 数字口径（百分比 vs 绝对值）
- [ ] 货币与币种
- [ ] 临界值（0、1、最大值）
- [ ] 四舍五入规则

### 2.6 权限 / 隐私

- [ ] 角色矩阵（运营 / 客人 / FA / CCE 等）
- [ ] PII 字段（手机号 / 邮箱 / 身份证）的展示与导出规则
- [ ] 授权范围（单业务线 vs 跨业务线）
- [ ] 数据保留期限与合规（GDPR / 个保法）

### 2.7 状态机完整性

- [ ] 每个有状态实体都有完整状态枚举
- [ ] 状态转移条件明确（事件 + 守卫）
- [ ] 终态与回退路径
- [ ] 异常状态如何回到正常态

### 2.8 通知 / 触达

- [ ] 触发时机（实时 / 定时 / 事件驱动）
- [ ] 推送渠道（站内 / 微信 / 邮件）
- [ ] 频次控制（防骚扰）
- [ ] 取消 / 退订路径

### 2.9 文案一致性

- [ ] 同一对象在不同章节使用同一术语
- [ ] 缩写首次出现展开
- [ ] 状态描述统一（"已支付" vs "支付成功"）

### 2.10 验收标准可测

- [ ] 每条 AC 给定可观察结果（截图 / 数值 / Boolean）
- [ ] Given/When/Then 原子化（无"并且"）
- [ ] 量化阈值可核验（不能是"流畅 / 友好"）

### 2.11 数据 / 持久化

- [ ] 写操作是否需要确认（防误触）
- [ ] 数据一致性（写后立即读是否一致）
- [ ] 缓存策略与过期

### 2.12 跨端 / / 跨角色一致性

- [ ] 多端展示一致性（小程序 / H5 / 后台）
- [ ] 跨角色视角（运营看的 vs 客人看的）
- [ ] 跨业务线影响（FSN/WFJ/CORP 等）

### 2.13 灰度 / 回滚

- [ ] 灰度范围 / 比例 / 时间
- [ ] 监控指标
- [ ] 回滚触发条件
- [ ] 回滚操作路径（前端开关 / 配置中心 / 后端开关）

## 3. 评审使用方式

```
PRD 完成后 → §Red-Review 阶段：
1. 按 §2 逐项勾选 → 标记适用项与不适用项
2. 不适用项须在适用性块中写明具体事实依据、来源、判断人和时间；禁止只写“本期不适用”或泛化 N/A
3. 适用项未覆盖的 → 在 issue-record.md 登记 ISS-NNN（带 owner 与关闭条件）
4. 全部勾完 + ISS 登记完 → 进入 §Human Gate
```

## 4. 与现有契约的兼容性

- 不替代 prd-assembly 的 `validate_artifact.py`：本清单是**advisory 工具**，不是阻断闸门
- 不替代 review-taxonomy 机器扫描：本清单是**作者自查**，扫描仍是机器事
- 与 `references/audit-checklist.md` 互补：audit-checklist 是结构层（本清单是内容层）
