# 竞品矩阵三态（Competitor Three-State Matrix）

> 来源吸收：`pm888__skillhub` 的「行选择就是分析本身（Row Selection is the Analysis，§2.6）」与反模式清单中相关条目（#15/#16/#17），作为 prd-assembly 处理竞品/功能对比信息时的可选落地能力。
> 定位：当上游背景/范围决策需要竞品依据（功能对齐、差异化定位、MVP 范围取舍）时，产出一张「有红格、有出处、有权重、有结论」的竞品矩阵——而不是挑赢的行、填满绿格的镜子。
> 触发：Intake/Clarify 阶段出现竞品对比信息、范围取舍依赖「对手做了什么」时；或 Human Gate 前需要向评审人说明功能取舍依据时。**按需加载，不设全局闸门。**

## 1. 输入映射

| 外部 skill 输入 | pm-scaffold 对应产物 | 说明 |
|---|---|---|
| win/loss notes、销售异议、功能对比信息 | 上游背景事实（SRC-XXX 登记） | 行来源必须是决定交易的因素，不是自己赢的功能清单 |
| 竞品界面/文档观察 | SRC-XXX 来源登记（trial / docs 等出处） | 每个非显而易见单元格必须带出处 |
| 功能取舍决策（做/不做/部分做） | DEC-XXX（决策记录）或范围基线 in/out | 权重列标 deal-breaker 的行决定取舍优先级 |
| 评审沟通材料 | Human Gate 呈现材料 | 内部诚实版与对外 battlecard 是两份不同产物 |

## 2. 核心原则：行选择就是分析本身

做竞品/功能对比时，**行的选择比单元格的填充更重要**：

1. 行必须来自**决定交易的因素**（win/loss notes、销售异议），不是来自你赢的功能清单。
2. 必须包含你**输的行**。没有红格的矩阵 = 镜子不是地图。
3. 单元格至少三态：✅ 有 / 🟡 部分或方案受限 / ❌ 缺。🟡 是真相所在处。
4. 每个非显而易见的单元格必须带出处：`[docs, 日期]` / `[trial, 日期]` / `[报告来源]`。
5. 加权重列：`deal-breaker / evaluated / checkbox`。deal-breaker 上的 🟡 = 你的 roadmap 在说话。
6. 内部诚实版（带红格 + 出处）与销售 battlecard 是**两份不同产物**，不能互相替代。

## 3. 三态定义（✅ / 🟡 / ❌）

| 状态 | 含义 | 示例 |
|---|---|---|
| ✅ 有 | 该行能力已完整具备，方案无受限 | 支持多租户隔离（[docs, 2026-05]） |
| 🟡 部分或方案受限 | 有但受限：仅特定版本、需要变通、体验打折 | 权限支持但仅 RBAC 单层，无数据级权限（[trial, 2026-06]） |
| ❌ 缺 | 不具备该能力 | 无审计日志（[docs, 2026-05]） |

> 🟡 是真相所在处：只填 ✅/❌ 两态会把「部分支持」的妥协空间抹平，评审人看到的矩阵就会失真。

## 4. 矩阵模板（含权重列、出处列、结论列）

| 行（决定交易的因素） | 权重 | 竞品 A | 竞品 B | 我方 | 出处 | 结论 |
|---|---|---|---|---|---|---|
| [因素名，来自 win/loss] | deal-breaker | ✅ | 🟡 | ❌ | [来源, 日期] | 我方差距 → roadmap 动作 |
| [因素名] | evaluated | 🟡 | ✅ | ✅ | [来源, 日期] | 追平即可 |
| [因素名] | checkbox | ❌ | ❌ | 🟡 | [来源, 日期] | 低优先 |

### 列说明

| 列 | 作用 | 规则 |
|---|---|---|
| 行 | 决定交易的因素 | 来自 win/loss notes、销售异议，必须含「你输的行」 |
| 权重 | deal-breaker / evaluated / checkbox | deal-breaker 上的 🟡/❌ = roadmap 必须回应 |
| 单元格 | ✅/🟡/❌ 三态 | 禁止只用两态；🟡 需在结论列说明受限细节 |
| 出处 | `[docs, 日期]` / `[trial, 日期]` / `[报告来源]` | 每个非显而易见的单元格必须带 |
| 结论 | 对取舍的含义 | 明确写出：追平 / 差异化 / 接受差距 / 触发决策 |

## 5. 行选择清单（决定行来源的问题）

- 客户在交易中真正比较的是什么？（来自 win/loss notes，不是产品手册）
- 我们输掉的单子，输在哪些因素上？
- 销售在异议处理中被问得最多的功能是什么？
- 哪些因素在 RFI/RFP 中是必答题？
- 哪些因素在演示/POC 中被反复验证？

> 如果行只来自「我们自豪的功能」，这份矩阵是镜子不是地图。

## 6. 权重列判定规则

| 权重 | 含义 | 单元格为 🟡/❌ 时的动作 |
|---|---|---|
| deal-breaker | 缺它就会丢单/决策反转 | 必须写进 roadmap 或范围取舍理由；标注影响哪个 FEA/决策 |
| evaluated | 客户会评估但不单点否决 | 追平或差异化说明即可 |
| checkbox | 有更好但非决定性 | 低优先，允许接受差距 |

deal-breaker 上的 🟡 = 你的 roadmap 在说话：不能只记录「竞品支持」，必须回应「我们何时/是否支持」。

## 7. 内外两版分离（诚实版 ≠ 销售版）

| 版本 | 用途 | 特征 |
|---|---|---|
| 内部诚实版 | 范围取舍 / 决策 / roadmap | 带红格、带出处、带差距结论 |
| 对外 battlecard | 销售/竞标沟通 | 只讲优势与应对话术 |

**不得互相替代**：内部矩阵直接发销售 = 失去谈判筹码；用 battlecard 做内部决策 = 决策失真。prd-assembly 场景中产出的竞品矩阵默认是内部诚实版，用于支撑范围决策。

## 8. 工作流程

1. 明确对比目的：范围取舍 / 差异化定位 / MVP 决策，决定行来源口径。
2. 收集决定交易的因素（win/loss notes、销售异议、RFI/RFP 必答题），列出候选行。
3. **强制加入你输的行**——没有红格的矩阵不成立。
4. 逐行填充三态单元格，每个非显而易见的单元格附出处。
5. 标权重列：deal-breaker / evaluated / checkbox。
6. 填结论列：每个差距给出含义（追平/差异化/接受/触发决策）。
7. 将矩阵作为范围决策依据（映射到 DEC-XXX / 范围 in/out），随 Human Gate 呈现。
8. 检查是否落入「只挑赢的行 / 只填两态 / 无出处 / 无权重 / 无结论」反模式，如有则重写。

## 9. 核心硬规则

1. 行必须来自决定交易的因素，不是自己赢的功能清单。
2. 必须包含你输的行（至少一行 ❌ 或 🟡），没有红格的矩阵 = 镜子不是地图。
3. 单元格至少三态（✅/🟡/❌），🟡 是真相所在处。
4. 每个非显而易见的单元格必须带出处。
5. 必须有权重列，deal-breaker 上的 🟡/❌ 必须触发 roadmap/范围回应。
6. 内部诚实版与对外 battlecard 分开，互不替代。

## 10. 边界（Do Not）

1. 不把矩阵填成全部 ✅ 的镜子——必须暴露差距。
2. 不用两态（✅/❌）抹平「部分支持」的妥协空间。
3. 不编造竞品能力——无出处的单元格标 TBD 或留空，不进结论。
4. 不用竞品矩阵直接定范围——矩阵支撑决策，取舍仍由人工拍板。
5. 不把内部诚实版当作对外沟通材料，反之亦然。
6. 不把竞品对比当作新增需求的入口——发现差距先路由回原 work item 或登记 issue-record。

- [ ] 矩阵至少包含一行「我方劣势」的红格
- [ ] 每个单元格为三态之一，🟡 已在结论列说明受限细节
- [ ] 每个非显而易见的单元格带出处（[docs/trial/报告, 日期]）
- [ ] 权重列存在，deal-breaker 行上的 🟡/❌ 已触发范围/roadmap 回应
- [ ] 每行有结论（追平/差异化/接受差距/触发决策）
- [ ] 内部诚实版与对外 battlecard 未混用
- [ ] 矩阵已映射到 DEC-XXX / 范围 in/out，随 Human Gate 呈现
