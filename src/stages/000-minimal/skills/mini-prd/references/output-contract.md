# 输出契约 · mini-prd（L0 轻量档）

## 状态机（Status Machine）
与所有 Skill 相同的 6 种状态：draft → needs_user_input → conditional_review → ready_for_human_review → confirmed → superseded。

## 产物章节（Artifact Sections）

正文 6 节（干系人/研发/测试阅读）：

| 节 | 标题 | 内容要求 |
|---|---|---|
| §1 | 改什么 | 改动点精确定位（文件/页面/字段/文案）+ 一句话目标 + 来源 |
| §2 | 为什么 | 触发来源 + 一句话证据（现状问题/不做的代价） |
| §3 | 影响范围 | 影响模块/入口/角色 + 回滚方式 + 边界说明 |
| §4 | 行为需求与验收 | 可观察结果 + Given/When/Then 精简验收（可判定通过/失败） |
| §5 | 适用边界与回退依据 | 说明实际新增的失败边界与回退；若不改变既有失败语义，说明无需新增回退的事实依据 |
| §6 | 依赖与开口问题 | 外部依赖 + 未决项 ≤3，每项有 owner 与影响 |

## 升档触发线（升档 = 返回 intake-routing 重选档位）

| # | 触发 | 升档 |
|---|---|---|
| 1 | 影响多个模块，或跨端/多服务 | L1 |
| 2 | 涉及多个角色或外部角色 | L1 |
| 3 | 需要状态机、生命周期、状态副作用或恢复策略 | L2 |
| 4 | 多个独立恢复路径、不可逆操作，或无法证明简单回退 | L2 |
| 5 | 含合规 / 资金 / PII / 跨境 | L2 |
| 6 | 改动体量 ≥1 个完整模块 | L1 |

命中任一 → 不生成 mini-prd，回 intake-routing 依据资格矩阵与硬升级条件重选档位；评分若用于沟通，只能作辅助说明，不能覆盖硬条件。

## 聚合规则（Aggregation Rules）
- **不写指针**：§4 必须内嵌规则内容，禁止「详见 XX-XXX」指针。
- **不新增需求**：改动点外的诉求路由回 intake-routing 立项。
- **验收可测**：每条验收必须可观察或可量化，并说明验证方法与判定方式；不得为满足格式伪造数字阈值。
- **占位唯一**：`待确认` 是唯一占位符；正文各节在送审前必须真实填满。

## 轻量治理（vs 完整治理）
- **保留**：单签 ReviewRecord + hash 锚（宪法底线：谁批的/何时批的/批的什么版本）。
- **裁掉**：preflight 充分度判定、七透镜 think、review-taxonomy 机器扫描、B3 收口表、issue-record 独立库、traceability_check、prd-assembly 聚合、audit chain 全链。
- 裁的是**工序**，不是**证据链**。
