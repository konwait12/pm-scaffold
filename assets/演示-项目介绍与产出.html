把一个业务需求，按固定环节问清楚、逐条确认，产出一本完整、可追溯、工程可直接开工的需求说明书。 下面以活动红点提醒这个真实需求为例，看它怎么走完，产出什么。

说明书第 08 章 · 业务规则（节选 6/15 条） 来源：REQ-001 PRD §08
编号 规则描述（条件 + 行为） 所属功能 来源
BR-001 当活动开始时间距当前时间恰为 24 小时，且活动未取消/未改期，且该活动"DAY-1 提醒"开关开启时，系统为每位已预约用户创建一条未读红点记录（粒度：用户×活动×场景）；任一前置不满足则不触发。 FEA-001 ST-001 / FF-001 §2.1 / B-01
BR-005 当同一活动已存在 ≥1 个未读红点场景时，系统将新触发的场景合并入既有红点，不新增红点数量、不展示数量；当该活动尚无未读红点时，新建单一红点。 FEA-005 ST-004 / Q-004 / B-02
BR-006 当用户对某活动任一有效详情（活动详情/行程单详情/TKU Page）完成有效查看时，系统将该用户×该活动的全部场景红点一次性清除；已读写入失败则本次不清除、下次进入重试。 FEA-005 ST-004 / Q-004 / EX-02
BR-007 当用户进入活动详情/行程单详情/TKU Page 任一有效入口时，系统判定为有效查看：进入即算、不计浏览时长、不因快速退出撤销。 FEA-006 ST-002 / Q-005 / CLS-FF-001
BR-011 当用户未登录时，系统在三入口均不显示红点、不攒积、登录后不补显示；未登录的红点状态请求返回空集合。 FEA-008 ST-010 / Q-003 / B-09
BR-014 当活动取消/改期时，系统即时清除该活动全部相关红点、不残留误导客人；清除失败则重试。 FEA-010 ST-008 / Q-008 / EX-05
说明书第 12 章 · 验收标准（节选 4/20 条） 来源：REQ-001 PRD §12
编号 验收口径（Given / When / Then） 量化阈值 优先级
AC-001 Given 已预约该活动且已登录的用户，活动未取消，DAY-1 开关开启，距活动开始恰为 24 小时；When DAY-1 触发事件到达；Then 状态源为该用户×该活动创建 1 条未读红点记录 创建 1 条 P0
AC-002 Given 距活动开始恰为 24 小时，事件推送接口不可用；When DAY-1 触发事件到达；Then 状态源不生成红点，三入口不报错（降级） 新增 0 条 / 报错 0 P0
AC-003 Given 距活动开始超 24 小时或活动已开始/已结束；When DAY-1 触发事件到达；Then 状态源不创建任何红点记录 新增 0 条 P0
AC-006 Given 同一活动已有 1 条未读红点；When 新场景触发；Then 红点总数仍为 1，不累加（聚合） 总数 = 1 P0
三结果的密度与准确性
不仅要有内容，还得每一句都站得住。这是这套机制和"一页纸需求"最大的区别。

内容密度

无空占位
每个章节都有实质内容，不写"待补充"凑数
逐条编号
规则、验收、异常全部带 ID（BR-001、AC-001）可逐条引用
量化阈值
验收写"创建 1 条""新增 0 条"，不写"体验要好"
边界明确
恰为 24h 触发、超 24h 不触发，不写"提前一点"

内容准确性

每条标来源
BR-001 来自 ST-001 / FF-001 §2.1 / B-01，事后查得到
事实与决策区分
FCT 是事实、DEC 是决策，不混为一谈
AI 推断显式标
AI 推断的内容标 AI_INFERENCE，不假装是业务确认
不编造
信息不足处显式标"待确认"，不写一个编出来的数字
常见的需求传递
  • 口头说一句"加个红点提醒"
  • 规则"详见附件 / 看群里截图"
  • 验收写"体验顺畅"
  • 改版后旧文档失效，没人知道对错
  • 工程按自己理解做，做错返工

四需求多大，流程多细
不搞一刀切。小改不空跑，大工程不漏项。
快速通道

小改 · 4 环节

改文案、调配置、修小问题。登记 → 判断 → 起草 → 确认，当天定。

例子：活动提醒文字调整
标准通道

新功能 · 7 环节

新增一个完整功能。覆盖背景、故事、清单、流程、规则、验收。

例子：活动取消后自动提醒客人
完整通道

大工程 · 13 环节

跨模块、多角色、涉数据合规。全链路逐步确认，不漏项。

例子：全平台红点提醒体系
五不变的几条原则
流程会变、工具会变，这几条不会变。

机器不拍板

系统只负责梳理、提问、整理。所有确认由业务负责人完成，决定权始终在人。

每步有人确认

每个环节结束都要业务负责人点头，确认了才进下一步，不让问题悄悄传到后面。

产出自包含

说明书不写"详见别处"。该知道的全在文档里，换人接手也能看明白。

每句话可追溯

每条规则、每个决策都标来源与时间。事后追问查得到，不会变成"谁说的不知道"。
