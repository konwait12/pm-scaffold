## 8. 幂等性保证

异常重试必须保证幂等：
- **EX-001 搜索重试**：幂等，多次搜索不改变数据
- **EX-002 上传重试**：断点续传，不重复创建记录
- **EX-003 投递重试**：先查是否已存在，存在则返回成功不重复创建
- **EX-005 解析重试**：覆盖原有结构化数据，版本保留
- **EX-018 邮件重试**：只标记"待重发"不重复发送，避免 spam

**为什么幂等重要？**
网络抖动是常态，前端重试很常见。不保证幂等会产生重复数据（如重复投递、重复邮件），造成用户困惑和数据污染。

## 9. 用户体验原则

异常处理 UX 黄金法则：
1. **说清楚**：告诉用户发生了什么 → "网络不稳定"不是"错误 500"
2. **给出路**：告诉用户能做什么 → "点击重试"、"换文件"、"联系谁"
3. **不吓人**：用平实语言，不出现 stack trace、"崩溃"、"致命错误"
4. **留后路**：尽量保存用户已输入内容，不丢工作

### 反模式
- "系统异常，请联系管理员" → 用户不知道联系谁
- "错误码: 500" → 用户看不懂技术错误码
- 清空表单 → 用户白填，非常糟糕
- 弹多个错误框 → 骚扰用户

## 10. 监控与 SLO

- **错误率告警阈值**：任一 FUN 错误率 > 5% → 触发告警
- **P95 延迟告警**：API P95 > 3s → 触发告警
- **SLO 目标**：异常恢复成功率 ≥ 99% → 即用户重试后能成功的比例
- **日志保留**：所有异常必须记录，保留 90 天 → 便于排查
